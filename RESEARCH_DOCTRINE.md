# Enterprise Math Research Doctrine

[Chinese version](RESEARCH_DOCTRINE.zh-CN.md)

> **Question the problem itself first. Let philosophy guide mathematics; but philosophy must cash out in countermodels, equivalence relations, and verifiable gates.**

This is a public research principle of Enterprise Math.

It means:

1. **Problem before proof.** Before attacking a theorem, state the object, allowed equivalence, observable, claimed invariant, and quantifier level. A hard proof problem may actually be a badly posed question.
2. **Philosophy creates questions, not exemptions from evidence.** A philosophical idea becomes mathematical only when it produces an exact definition, a countermodel, an invariance/equivalence statement, a finite certificate, a proof obligation, or another falsifiable gate.
3. **Use the lowest sufficient abstraction.** Do not upgrade from sets to groupoids, descent, stacks, or higher structures because the language is fashionable. Upgrade only after exhibiting a concrete lower-language failure and a higher-language repair that preserves the distinctions the problem declares observable.
4. **Negative results are first-class results.** Killing a false identification, separating presentation from native structure, proving nonrepresentability, or constructing an indistinguishability family is progress when it removes a wrong question.

Operationally, the preferred order is:

```text
QUESTION-LANGUAGE AUDIT
    -> DECLARE OBJECT + EQUIVALENCE + OBSERVABLE + QUANTIFIERS
    -> FIND COUNTERMODEL / INVARIANT / OBSTRUCTION
    -> INSTALL A VERIFIABLE GATE
    -> PROVE ONLY THE REPAIRED QUESTION
```

A philosophical claim that cannot yet be converted into a falsifiable mathematical obligation remains a research intuition, not a theorem and not native ontology.
