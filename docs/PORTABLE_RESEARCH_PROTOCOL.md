# 可由任意对话接续的研究

生效：2026-09-23。来源：用户明确要求修复自动研究、移除使对话无法研究的环境绑定，并由本机先取得研究增量后发布可在 ChatGPT 网页或客户端完成的任务。机器入口为 `control_plane/research_delivery_policy.json`，由当前控制权威路由引用。

研究产出是证明、反例、精确计算证据、实验结果或有来源的文献结论。注册、状态检查、恢复定时开关和任务清单只服务于这些产出。

## 按数学产出决定所需工作

日常推导以问题、前提、论证和实际证据为中心。完整书面证明可以按其数学内容复核，Lean 用于确实需要的形式化工作；一个例子、失败尝试或中间引理无需先配套代码、测试套件、JSON 表单、PR 或独立证书。计算材料保留影响结论的输入、算法、范围和精度；选用的方法确实依靠证书时再保存该证书。

普通笔记可以单语，用自然语言说明已证、猜想、条件结论和实验观察，在使用处给出可定位的引用。明确的前提或状态可覆盖一段论证。规范来源登记、双语配对、正式 Result 与独立 Review 在对应的规范整合或共享操作时办理。

在连贯研究中积累笔记，在有意义且需要保全的结果、交接或中断边界成批保存；不为每次变形、试值、换路或聊天回复分别制造 checkpoint。一个已保存的科学文件可由 Activity、接续包和账户日志引用，完整内容不必逐处复制。实际尚无下一动作时如实留空，不为填表制造新任务。

## 旧任务接续与成果保全

接续旧任务书时，以当前明确协议执行。旧文档中的工程流程、整套规则版本指纹、重新 PASS 和行政自报字段不构成研究或保存材料的前提；当前汇报必须按 `final_response_identity_policy.json` 显示真实身份及读写状态角标；不批量重写旧任务书、Result、Review 或事件。任务书不必使用固定五段英文标题；正文须有实际内容且不能保留未填写占位符，科学问题、假设、输入、来源和所需证据仍按实际规则保留。Git commit 与文件路径用于定位来源，不证明数学结论，也不要求旧材料匹配当前 HEAD。

不改变共享任务状态的自由推导（包括 FREE Phase A）可以直接推进并及时保存。独立 activity 登记、工具覆盖查询、七态复用决议及 harvest 分类可并行或在成果后处理，不阻断探索或保全；正式提出方法新颖性、接纳共享工具时仍应查重并如实说明复用与能力边界。既有来源隔离不因查重而提前开放。

向用户汇报实际成果、欠项与下一动作不需要正式任务完成权。`pre-final` 默认仅返回这一沟通结论，且 `authorized=false`；需要检查正式任务完成权时使用 `--formal-task-completion`。报告、保存草稿或强制的真实读写状态／身份尾标都不授予 CLAIM、Result/Review 写入或父目标完成权。正式共享操作继续核验真实身份、publication、owner/lease、CAS、幂等、明确暂停和科学依赖。

2026-11-01 用户明确恢复强制角标：实质回复显示 `EM-Source-Status`，研究角色同时显示真实身份，维护模式不虚构研究 ID。按 2026-11-02 用户要求，角标标签、状态和简短警示原因使用英文，正文不必翻译；精确路径、ID 与回执引用保留原值。读取显示 `Read=Verified / Verified snapshot reused / ⚠ Read failed / ⚠ Unconfirmed`；写入显示 `Write=Written and verified / Not required / ⚠ Not written / ⚠ Write failed / ⚠ Unconfirmed`（待处理或未知）。所需成果只有实际发布并取得对应远端读回或权威完成回执后才能标成功；未成功须显著标示 ⚠、受影响目标与简短原因，未知操作先核查不能盲重试。多目标逐项说明，读取成功不代表写入成功。不需要保存的回合明确 `Write=Not required`，不得为角标制造写入，也不得把被拒或尚未尝试的必需保存称为无需写入。复用有效证据，不增加逐步哈希或自证手续；角标不绕过拒绝／暂停或授予任务权限，也不证明所有客户端已实际执行。

优先保留证明、反例、推导与计算材料，并及时提取可复用工具和定理。假设、定义、精确输入、代码/参数、实验范围、真实来源及未验证部分仍须如实保留；取消行政手续不等于忽略数学前提、伪造实验或宣称未经独立审核的成果已被接纳。

科学文件的保存以精确 commit、路径及足够范围的远端回读或权威完成回执核实，复用已核验版本；只有内容或写入结果不确定时才补读受影响部分。Activity 关联、账户日志镜像、正式 Result 和独立 Review 各按自己的记录报告。后续补记直接引用同一份科学证据；只补实际欠项。

在取舍研究对象、压缩表示或判断精确命题时，若结论依赖残差，按[残差研究约束](RESIDUAL_FIRST_RESEARCH_CONSTRAINT.md)处理证据和适用范围。

## 按需使用原生速记本

这里的速记本指 Nollm 原生结构提炼：Host 根据实际读过的证据形成判断、选择一个物理入口，Core 沿原生场展开邻域，Access 返回表达和固定来源。普通笔记、目录盘点和字面检索分别按其实际作用使用。核对前提后直接引用同范围的已有证明；条件、观测范围或结论改变时，针对新范围所需的论证继续研究，并标明实际新增部分。 判断是否重复时，核对研究对象、前提、量词、参数或观测范围及结论。命题相同而证明方法不同，按同一结果的证明变体保留其来源；有独立核验、简化依赖等实际价值时继续，不重新计作一个新定理。扩大成立范围、减弱假设或改正旧结论时，链接旧结果并写明差异即可，无需逐引理另填登记表。

在 TASK 或其他已获准知情研究中，接续旧问题、应用既有结论、怀疑重复推导，或发现来源与成立条件变化时，可按需要使用现有记忆接口。已知表达 ID 时直接用 `em_memory_show` 和 `em_memory_source`；需要了解相关结构时从 `em_memory_walk` 返回的 Surface 逐步选择一个物理入口，再核对邻域中的条件和固定来源。当前 `em_memory_walk` 在 `has_more=true` 时，沿累计 `choices` 追加 `next` 继续分页；小场可直接观察 `order=0` 的 Surface，再由 Host 选择显示的物理候选。字面查询只作辅助。FREE A 和任务的来源隔离继续适用，全成果场不代替阶段适用的基础或获准的精确读取。

在有意义的成果批次保存、交接或中断边界，若本批结论值得后续复用，Host 可结合已观察的相关邻域和真实来源判断：已有理解仍适用则保留；原命题或条件改变则原位修订；不同命题或新的联系则形成独立表达，并由 Host 选择原生位置。现有 `em_memory_save` 使用新的表达 ID、实际读过的固定 `COMMIT:PATH#Lfirst-Llast` 来源，以及 `at=[q,r]` 或 `revise=<current note ID>`；按实际可用接口保存并读回。不要为每次变形、试值、每条回复或单纯 HEAD 变化另记一条，也不以记忆维护阻断科学文件保全。

`current=true` 只表示该表达是场中的当前绑定，不表示已经对最新 Source 复核。读取新原文、Source bundle 刷新和 GitHub 新提交都不会自动修订理解；Host 根据实际差异决定是否更新，并保留历史表达及其固定来源。一次未召回不能证明旧结果不存在；预算不足或没有合适理解时继续读取问题所需的源码与论文。记忆保存不代替原始证明、Activity、正式 Result 或独立 Review，也不授予定理接纳或任务完成权。

## 心跳／BRC–Shor 的运算约束

任务属于心跳世界、BRC–Shor 或原生残差归因时，在生成科学输入、运算、重验和新增参考计算前，必读 [BRC 唯一运算路径](HEARTBEAT_BRC_ONLY_ARITHMETIC.md) 与 [机器约束](../research_constraints/heartbeat_brc_only.json)。此范围执行 `ACTUAL_TYPED_BRC_ONLY`；下文“可接续”“替代实现”“环境故障不阻断研究”均不授权退回非 BRC 科学运算。

接口不足时继续保存原生输入、支路、符号／相位、观察和未决点，定位或建立有对应证明的 BRC 扩展；不得用 π、经典三角函数、普通矩阵指数或 Taylor／Padé／Cayley 绕行，不得靠提高精度、只用分数或改名补证。普通对话可继续证明 BRC 恒等式、设计载体和证书，但不能把未执行操作记成已执行。

接续时复用已验证的精确前沿。一次同刻闭环复验不自动覆盖物理时间轨迹或其它输入；关系深度、递归折扣和求解迭代不等于心跳间隔。历史结果保留原始证据，未完成原生对应的项继续标记 `NATIVE_ATTRIBUTION_PENDING_BRC_REVALIDATION`。本节只连接已有用户方法约束，不改变任务、审查、P000 或其它研究范围。

## 任务书描述研究问题

任务书说明母问题、符号定义、精确输入、已验证事实、所需证据、完成标准和实际未决问题，研究方法与推导顺序由研究者选择。自然语言和通常数学记号足以表达的内容无需另转机器表单；需要跨工具交换大整数或有理数时，才采用不会丢失精度的字符串或分子／分母表示。有限计算用于证明时说明覆盖与推理依据，所用方法依靠证书时说明检查关系。任务不得以“必须在本机”“必须有 Python/CLI/完整 checkout/特定 MCP/指定 SDK”等环境条件作为对话开始或推进研究的准入条件。

科学对象确实包括某个原生实现、版本或实验协议时，保留它作为待验证对象。把所需执行拆成支持工作，给出输入、命令或算法语义、预期输出格式和可核验凭据。网页对话可先推进其理论分析、误差界、证书设计、反例或下一项可推理问题。替代实现的结果只能以实际范围报告；没有运行的原生实验仍标为待执行。

旧任务书及已有 Result/Review 保持原字节和来源。发布清晰继承关系的子任务或显式 supersedes 的新一代任务书，说明新增信息缺口和保留的数学标准；不能通过改名把未验证实验变成已完成。

## 每次定时研究的闭环

1. 已有明确研究问题和有效前沿时直接接续；需要领取新的共享任务时再走当前规范派发。读必要输入并复用已验证成果。同一对话复用仍有效的自身会话；新对话沿现行 Activity 协议保持真实贡献与来源历史。
2. 尽快进入科学工作，按问题需要持续推理、构造或计算。本轮尚未得到新结论时保留实际进展和具体未决点，不以固定运行次数要求产出新定理，也不用状态消息替代工作。
3. 将实际证据、验证方式、未验证项和不可重做项持久化到 Source。有具体后续工作时记录问题或动作；当前单元已完成或尚不确定后继时，可将后继留空，如实记录单元状态。正式执行沿现有 CLAIM、publication、Result 和独立审查路径；未能写回的内容准确标为草稿，不能伪报发布成功。
4. 按原定时任务频率继续。只在用户停止要求、实际平台终止或该次执行的合法结束边界温柔收尾，保存可续接前沿。父研究目标不因一个控制子流程完成而自动完成。

## 环境或控制故障的处理

先做一次有界诊断，区分工具调用失败、控制记录错误、输入缺失和真正数学困难。可恢复的 MCP、SDK、计算环境或回执错误不能解释为“没有研究任务”，也不能触发研究定时任务自我停用。修复具体原因，同时推进已授权范围内不依赖该故障的研究。若只能完成推理草稿，明示尚未写回/尚未执行的部分，并保留精确支持请求。

当前任务若只剩特定原生实验，控制端应执行支持单元，并通过规范发布提供可在对话中继续的数学问题。先对齐最高有效前沿；不重复已完成的理论结果来掩饰实验欠项，不抢占他人的活跃 CLAIM，不把任意可见任务当作已获派发。

驾驶员应消费实际研究返回并作独立判断。有具体、有信息增益的后续问题时再发布，已完成的当前范围可如实收束。巡检应修复实因并核验至少一条实际研究路径；反复“恢复开关—遇同错误—停用”不是完成标准。保持原频率和通知意图，状态无变化时避免重复无价值报告。

## 接续包

接续包必须让下一对话从持久化材料理解：当前问题；精确输入；已完成且不重做的单元；实际尚未完成的问题和已知下一动作（如有）；适用的证明/计算关系；实际验证和欠项；证据位置；任务与贡献来源。控制 Source 的当前读回不是历史接受证明。已通过独立审核的任务直接消费其结果，不能为恢复会话重做。

普通对话的 GitHub 控制操作见 [操作协议](CHATGPT_ORDINARY_CONTROL.zh-CN.md)。任务发布继续使用现有不可变 V2 记录，P000、来源隔离、作者历史、独立审核和数学强度保持不变。
