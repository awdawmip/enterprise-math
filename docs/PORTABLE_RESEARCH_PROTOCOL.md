# 可由任意对话接续的研究

生效：2026-09-23。来源：用户明确要求修复自动研究、移除使对话无法研究的环境绑定，并由本机先取得研究增量后发布可在 ChatGPT 网页或客户端完成的任务。机器入口为 `control_plane/research_delivery_policy.json`，由当前控制权威路由引用。

研究产出是证明、反例、精确计算证据、实验结果或有来源的文献结论。注册、状态检查、恢复定时开关和任务清单只服务于这些产出。

## 任务书描述研究问题

任务书固定母问题、符号定义、精确输入、已验证事实、未解决问题、所需证据和完成标准。将第一步写为一个具体可回答的问题，提供足够的小型输入与来源。大整数用十进制字符串，有理数用明确的分子/分母，有限计算说明完备性条件和证书检查关系。任务不得以“必须在本机”“必须有 Python/CLI/完整 checkout/特定 MCP/指定 SDK”等环境条件作为对话开始或推进研究的准入条件。

科学对象确实包括某个原生实现、版本或实验协议时，保留它作为待验证对象。把所需执行拆成支持工作，给出输入、命令或算法语义、预期输出格式和可核验凭据。网页对话可先推进其理论分析、误差界、证书设计、反例或下一项可推理问题。替代实现的结果只能以实际范围报告；没有运行的原生实验仍标为待执行。

旧任务书及已有 Result/Review 保持原字节和来源。发布清晰继承关系的子任务或显式 supersedes 的新一代任务书，说明新增信息缺口和保留的数学标准；不能通过改名把未验证实验变成已完成。

## 每次定时研究的闭环

1. 从当前规范派发和有效前沿取一个明确研究单元，读必要输入并复用已验证成果。同一对话复用仍有效的自身会话；新对话登记真实身份，保持贡献与来源历史。
2. 尽快进入科学工作。每次至少争取一个可核验的新结论，或将一个确切未决点缩小为更强的子命题/反例边界。需要较长推理时允许持续研究，不用状态消息替代工作。
3. 将实际证据、验证方式、未验证项、不可重做项和下一问题持久化到 Source。正式执行沿现有 CLAIM、publication、Result 和独立审查路径；未能写回的内容准确标为草稿，不能伪报发布成功。
4. 按原定时任务频率继续。只在用户停止要求、实际平台终止或该次执行的合法结束边界温柔收尾，保存可续接前沿。父研究目标不因一个控制子流程完成而自动完成。

## 环境或控制故障的处理

先做一次有界诊断，区分工具调用失败、控制记录错误、输入缺失和真正数学困难。可恢复的 MCP、SDK、计算环境或回执错误不能解释为“没有研究任务”，也不能触发研究定时任务自我停用。修复具体原因，同时推进已授权范围内不依赖该故障的研究。若只能完成推理草稿，明示尚未写回/尚未执行的部分，并保留精确支持请求。

当前任务若只剩特定原生实验，控制端应执行支持单元，并通过规范发布提供可在对话中继续的数学问题。先对齐最高有效前沿；不重复已完成的理论结果来掩饰实验欠项，不抢占他人的活跃 CLAIM，不把任意可见任务当作已获派发。

驾驶员应消费实际研究返回、作独立判断并发布有信息增益的下一问题。巡检应修复实因并核验至少一条实际研究路径；反复“恢复开关—遇同错误—停用”不是完成标准。保持原频率和通知意图，状态无变化时避免重复无价值报告。

## 接续包

接续包必须让下一对话从持久化材料理解：当前问题；精确输入；已完成且不重做的单元；一个尚未完成的具体问题；可执行的证明/计算关系；实际验证和欠项；证据位置；任务与贡献来源。控制 Source 的当前读回不是历史接受证明。已通过独立审核的任务直接消费其结果，不能为恢复会话重做。

普通对话的 GitHub 控制操作见 [操作协议](CHATGPT_ORDINARY_CONTROL.zh-CN.md)。任务发布继续使用现有不可变 V2 记录，P000、来源隔离、作者历史、独立审核和数学强度保持不变。
