# Enterprise Math Logic Blacklist

Status: `ACTIVE / PROJECT-LEVEL RESEARCH LOGIC`

Date: `2026-09-09`

This file records research patterns that are not merely weak heuristics but are logically inadmissible for a stated target unless the target is explicitly retyped.

The blacklist does not prohibit a mathematical construction in every context. A construction may be valid for one theorem and blacklisted for a stronger theorem with different quantifiers. The purpose is to prevent target leakage, premise smuggling, and semantic substitution.

## LB-01 — Target-imprinted residual completion

### Pattern

A target requires an exact global identity, for example

\[
E(u)=0
\quad\text{or}\quad
f\equiv0.
\]

The route then:

1. prescribes or constructs a candidate already carrying the desired endpoint behavior;
2. defines a residual, correction, forcing, or defect by
   \[
   r:=E(u)
   \quad\text{or}\quad
   f:=E(u);
   \]
3. proves that this residual is small, decaying, flat at one point, zero to high order, or negligible after a selected limiting/rescaling procedure;
4. treats that weaker residual property as if the original exact identity had been derived.

### Verdict

`BLACKLISTED_FOR_ZERO_RESIDUAL_TARGETS`.

### Logical defects

- `TARGET_LEAKAGE`: the desired output has already influenced the candidate before the target equation is solved;
- `QUANTIFIER_MISMATCH`: “there exists an admissible residual/force” is substituted for “the residual/force is identically zero”;
- `LOCAL_TO_GLOBAL_SUBSTITUTION`: pointwise, jet-level, asymptotic, or rescaled vanishing is substituted for a global identity;
- `WITNESS_CONTAMINATION`: the repair term is defined from the desired witness and then used as evidence that the witness arose without that repair;
- `SEMANTIC_TARGET_SUBSTITUTION`: a formally proved weaker/different theorem is presented as evidence for a stronger target.

### Formal freeze

\[
\bigl[D^\alpha r(x_*)=0\ \forall\alpha\bigr]
\not\Rightarrow
\bigl[r\equiv0\bigr].
\]

Likewise,

`RESCALED_RESIDUAL -> 0`

never implies

`ORIGINAL_RESIDUAL ≡ 0`

without an independent global theorem.

### Allowed boundary

If the theorem itself explicitly existentially quantifies the residual/forcing/correction and permits it to be chosen, residual completion is **not automatically invalid for that theorem**.

However:

`VALID_FOR_EXISTENTIAL_FORCED_THEOREM != EVIDENCE_FOR_ZERO_FORCE_THEOREM`.

A result may cross from the former lane to the latter only through a separate proof establishing the exact zero-residual identity.

## Navier–Stokes specialization

For the Enterprise Math unforced Navier–Stokes lane:

`FORCING_IDENTICALLY_ZERO_FROM_PREMISE_TO_CONCLUSION`.

The following route is therefore blacklisted:

`DESIRED_SINGULAR_PROFILE -> DEFINE_NS_RESIDUAL_AS_FORCE -> PROVE_FORCE_FLAT/SMALL -> CLAIM_ENDOGENOUS_BLOWUP`.

Mandatory distinctions:

- `FLAT_AT_SINGULAR_POINT != ZERO_FORCE`;
- `ZOOM_LIMIT_UNFORCED != ORIGINAL_TRAJECTORY_UNFORCED`;
- `FORMAL_VERIFICATION != SEMANTIC_TARGET_EQUIVALENCE`;
- `FORCED_BREAKDOWN_WITNESS != UNFORCED_SELF_INSTABILITY`.

The current research direction is

`AUTONOMOUS_SELF_STATE_INSTABILITY`:

fix \(f\equiv0\) first, allow only the autonomous Navier–Stokes dynamics, and determine whether instability is generated by the state itself. This label is a research direction, not a theorem status.

## Proof-assistant rule

Formal verification certifies the encoded theorem. It does not certify that the encoded theorem is semantically equivalent to a different research target.

Before importing a formal result into a stronger claim, audit:

1. exact quantifier order;
2. whether residual/forcing/correction is fixed, zero, or existentially chosen;
3. whether a local limit is being substituted for a global identity;
4. whether the desired output influenced witness construction;
5. whether the conclusion is being promoted across semantic lanes without a bridge theorem.

A failure at any of these gates blocks promotion of the result to the stronger target.
