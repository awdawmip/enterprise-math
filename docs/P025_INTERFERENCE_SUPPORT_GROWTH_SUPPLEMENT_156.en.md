# P025 Supplement 156 — Dependency closure is the fixed point of an expanding operation envelope

## 1. From static prerequisite state to executable interference

Stage 155 showed that if only actions in `Q` may fire, the exact static helper-state support

\[
R_Q=Q\cup\operatorname{Pred}(Q)
\]

is sufficient for every Q-only word.

Now change the future operation envelope: promote the newly exposed predecessor helpers themselves to executable actions. Their own hidden predecessors may then affect legality, so the previous static state support may no longer be self-contained.

## 2. Iterated support growth

Define

\[
Q^{(0)}=Q
\]

and recursively

\[
\boxed{
Q^{(t+1)}
=
Q^{(t)}\cup\operatorname{Pred}(Q^{(t)}).
}
\]

Interpretation:

- if exactly the actions in `Q^(t)` are executable and all other helper statuses are frozen, then Stage155 says state support `Q^(t+1)` is sufficient;
- if those newly exposed state coordinates are then promoted to executable actions, the next layer `Q^(t+2)` becomes relevant.

Because the helper DAG is finite, this sequence stabilizes.

## 3. Fixed point equals dependency closure

At the fixed point `Q^*`, every helper predecessor of every member is already inside the set. Hence `Q^*` is predecessor-closed and contains the original `Q`.

Conversely every predecessor-closed set containing `Q` must contain every layer of the recursion. Therefore

\[
\boxed{
Q^*
=
\downarrow Q.
}
\]

Thus Stage153/154's autonomous action support is exactly the fixed point of repeated Stage155 state-support promotion.

## 4. Promotion can expose a new legality collision

Suppose `Q^(1)` is used only as state support for `Q^(0)` actions. It is sufficient.

If the new helpers in `Q^(1)\Q^(0)` become executable, their enabledness may depend on predecessors in `Q^(2)\Q^(1)`. Then two global ideals can agree on all of `Q^(1)` but disagree on legality of a newly promoted action.

This occurs already for the highest pre-output helper in the perfect 16-way compiler.  The first repair has three helper coordinates, but promoting its two child helpers to actions exposes four hidden first-layer predecessors and forces the seven-helper next layer.

## 5. Exact perfect-family growth

For one highest pre-output helper of the perfect balanced compiler:

\[
\boxed{
\begin{array}{c|c}
k & |Q^{(t)}|\text{ until fixed point}\\
\hline
8 & 1,3\\
16 & 1,3,7\\
32 & 1,3,7,15
\end{array}}
\]

The fixed point size is

\[
\boxed{\frac{k}{2}-1,}
\]

matching Stage154's full dependency support.

## 6. Precision interpretation

Dependency support should not automatically be charged as initial state precision. It is generated by what the future is allowed to manipulate.

A natural staged interpretation is

\[
\boxed{
\text{declared actions}
\to
\text{static prerequisite state}
\to
\text{promoted actions}
\to
\text{new hidden prerequisite state}
\to\cdots
\to
\downarrow Q.
}
\]

The same dependency graph therefore supports different precision costs under different future operation envelopes.

## 7. Prior-art boundary

Dependency closure and fixed-point iteration on DAG supports are classical. No generic novelty claim is made. P025 contributes the exact future-operation interpretation and the scalable support-growth witnesses.
