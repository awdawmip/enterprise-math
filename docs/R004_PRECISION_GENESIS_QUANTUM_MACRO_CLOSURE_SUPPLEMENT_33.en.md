# R004 precision genesis — Supplement 33: primitive counter ISA gap

Status: `PROVED_WIP + EXECUTABLE_REFERENCE + ISA-RESOURCE SPECIALIZATION`
Parent: `R004_PRECISION_GENESIS_QUANTUM_MACRO_CLOSURE_SUPPLEMENT_32.en.md`

Let `M` be the p-adic residual query module on d coupling-cell coordinates.

## 1. Two primitive instruction surfaces

**Cell-counter ISA.** A primitive may store only one coupling-cell coordinate. Coordinate j must retain depth

`e_j^cell = log_p |pi_j(M)|`.

Total state mass is `mu_cell=sum_j e_j^cell`.

**Aggregate-counter ISA.** A primitive may directly accumulate an arbitrary integer linear combination of witness cells. Then the minimal structural state is the module M itself and `mu_agg=log_p |M|`.

## 2. Exact ISA gap module

The coordinate-projection map embeds M into the product of its coordinate images:

`M -> product_j pi_j(M)`.

Define `G_ISA=(product_j pi_j(M))/M`. Then

`mu_cell-mu_agg = log_p |G_ISA| >= 0`.

Thus the storage benefit of aggregate counters is an exact finite p-group quotient, not an empirical benchmark.

For the diagonal residual line generated by `(1,...,1)` at cap K, cell ISA stores d full-depth counters, aggregate ISA stores one, and the exact saving is `(d-1)K`.

## 3. Boundary

The aggregate ISA is legal only when the primitive execution environment can accumulate the declared integer linear combinations directly. If only individual witness cells can be addressed, the cell ISA is the correct capability model. The ISA is therefore part of the typed future language, not an implementation afterthought.

## 4. Validation

3,200 random residual modules over p=2,3, caps K=1,2 and dimensions 1..4 were checked exactly. Every case satisfied `mu_agg<=mu_cell`; 2,215 cases were strict.
