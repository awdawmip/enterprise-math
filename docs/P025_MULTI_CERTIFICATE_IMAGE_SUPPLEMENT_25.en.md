# P025 Supplement 25 — Rank-Two Ceiling for Arbitrarily Many Block-Linear Certificates

## 1. Enriching the future language with many certificates

Supplement 20 proves that the current additive witness language descends exactly to the compressed block-value lattice

\[
\Lambda_{abc}\subseteq\mathbb Z^2.
\]

Now let the future language contain any finite family of integer-linear certificate observables

\[
\boxed{
\ell_j(u,v)=r_j u+s_j v,
\qquad j=1,\ldots,q.
}
\]

Collect them into

\[
\boxed{
H:\Lambda_{abc}\to\mathbb Z^q.
}
\]

The number `q` of reported certificate coordinates can be arbitrarily large. The underlying relation-state rank cannot.

## 2. P025-T73 — certificate image rank is at most two

Let `g_1,g_2` be any basis of the rank-two non-unit compressed lattice; in the unit boundary there is only one basis vector.

The labelled certificate image is generated by

\[
\boxed{
H(g_1),\ H(g_2)\in\mathbb Z^q.
}
\]

Therefore

\[
\boxed{
\operatorname{rank}_{\mathbb Q}H(\Lambda_{abc})
\le
\operatorname{rank}_{\mathbb Z}\Lambda_{abc}
\le2.
}
\]

So adding more block-linear certificates does not create additional independent relation-state directions. It may add more labelled outputs, but all of them live on a rank-at-most-two integer image.

## 3. P025-T74 — full certificate rank is block-value complete

Assume all three blocks are non-unit, so `Lambda_abc` has rank two. If the joint certificate map has rational rank two, then its linear extension

\[
H:\mathbb Q^2\to\mathbb Q^q
\]

is injective. Hence its restriction to `Lambda_abc` is injective.

Therefore

\[
\boxed{
\operatorname{rank}_{\mathbb Q}H=2
\Longrightarrow
\text{the full labelled certificate vector uniquely determines }(u,v).
}
\]

In the rank-one unit boundary, any nonzero certificate image already has the same property on the one-dimensional lattice.

Thus once two rationally independent block-linear certificate directions are present, retaining additional linear certificate coordinates cannot distinguish any further block-value states. They can still be operationally convenient or carry different task thresholds, but not increase the underlying exact state partition.

## 4. Two independent certificate rows give explicit recovery

For two rows

\[
(r_1,s_1),
\qquad
(r_2,s_2)
\]

with determinant

\[
\Delta=r_1s_2-r_2s_1\ne0,
\]

and observed values `y_1,y_2`, Cramer's rule gives

\[
\boxed{
 u=\frac{y_1s_2-y_2s_1}{\Delta},
\qquad
 v=\frac{r_1y_2-r_2y_1}{\Delta}.
}
\]

For a vector known to lie in the actual certificate image, these rational expressions recover the original integer block-value state exactly.

Example for `2+3=5`: take the Wronskian row `(-3,2)` together with `(1,1)`. Their determinant is `-5`, so the pair `(W,u+v)` is already a complete coordinate system on the block-value state.

## 5. P025-D15 — Smith/determinantal image invariants

Let the basis-image matrix have columns

\[
y_1=H(g_1),
\qquad
y_2=H(g_2)
\]

in `Z^q`.

The standard determinantal divisors give its abstract Smith invariant factors.

Let

\[
\delta_1=\gcd\{\text{all entries of }y_1,y_2\}.
\]

If all `2x2` minors vanish, the image has rank one and its nonzero Smith factor is `delta_1`.

Otherwise let

\[
\delta_2
=
\gcd\{\text{all }2\times2\text{ minors}\}.
\]

Then the rank-two invariant factors are

\[
\boxed{
(d_1,d_2)
=
\left(\delta_1,\frac{\delta_2}{\delta_1}\right).
}
\]

These are standard Smith-normal-form facts and are not P025 novelty.

## 6. P025-N09 — Smith factors do not determine the labelled certificate image

Abstract invariant factors are too coarse when the future language gives fixed meanings to certificate coordinates.

Use the prime triple

\[
2+3=5,
\]

for which

\[
\Lambda_{235}=\mathbb Z^2.
\]

Consider two two-certificate maps:

\[
H_1(u,v)=(u,2v),
\]

and

\[
H_2(u,v)=(u,u+2v).
\]

Both have Smith invariant factors

\[
\boxed{(1,2).}
\]

But their labelled images differ:

\[
H_1(\mathbb Z^2)
=
\{(x,y):y\equiv0\pmod2\},
\]

while

\[
H_2(\mathbb Z^2)
=
\{(x,y):y\equiv x\pmod2\}.
\]

The labelled target

\[
\boxed{(1,0)}
\]

lies in the first image but not the second.

Therefore

\[
\boxed{
\text{same Smith invariants}
\not\Rightarrow
\text{same labelled certificate language}.
}
\]

If future queries care about particular certificate coordinates, one must retain a labelled image generator/HNF-style state, not only abstract invariant factors.

## 7. Relation to Wronskian-only precision

A single Wronskian observable has rank one on a rank-two block-value lattice. It deliberately forgets one rational direction. That forgotten direction is exactly why one Wronskian value does not reconstruct the whole additive state and why Stage 22 has an affine floor line.

Adding one independent block-linear observable raises joint rank to two and collapses each certificate fiber to a single block-value point.

Thus the transition

\[
\boxed{
\text{one certificate direction}
\to
\text{two independent directions}
}
\]

is qualitatively different from merely adding a third, fourth, or hundredth dependent observable.

## 8. Architectural consequence

For block-linear certificate languages, there is a hard representational ceiling:

\[
\boxed{
\text{number of certificate outputs}
\not=\text{independent precision dimension},
\qquad
\text{independent dimension}\le2.
}
\]

This is a direct consequence of the relation-state quotient, not an arbitrary dimensionality reduction.

The relevant state hierarchy is:

\[
\boxed{
\Lambda_{abc}
\xrightarrow{H}
\text{labelled rank-}\le2\text{ certificate image}
\to
\text{task-specific threshold/decision quotient}.
}
\]

The last step still belongs to P023: if only threshold predicates of the certificate vector matter, the full labelled image may itself be over-refined.

## 9. Prior-art boundary

Smith normal form, determinantal divisors, Cramer's rule, ranks of integer linear maps, and injectivity of full-column-rank maps are standard mathematics.

P025 does not claim them. The project-side result under test is their exact placement after the arithmetic block-value quotient, giving a reusable ceiling on the independent state dimension of any future language built only from block-linear certificate forms.

Historical novelty of this packaged interface remains `NOVELTY_UNVERIFIED`.
