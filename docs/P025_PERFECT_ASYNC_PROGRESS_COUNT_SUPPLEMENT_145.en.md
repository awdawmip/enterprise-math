# P025 Supplement 145 — Exact asynchronous progress counts for perfect binary compilers

## 1. Perfect binary family

Let

\[
k=2^d,
\qquad d\ge2,
\]

and use the perfect balanced binary conjunction compiler from Stage 137. Before the output root `z` fires, the helper dependency poset consists of two disjoint perfect binary gate subtrees of height `d-1`.

Stage 144 identifies asynchronous helper-progress states exactly with the order ideals of this poset.

## 2. Ideal-count recurrence for one gate subtree

Let `F_h` be the number of ideals of the internal-gate poset of a perfect binary subtree of height `h`, including that subtree's root gate.

For `h=1`, the subtree contains one gate, so

\[
\boxed{F_1=2.}
\]

For `h>=2`, split ideals according to whether the subtree root is present.

### Root absent

The left and right child gate subtrees are independent, so there are

\[
F_{h-1}^2
\]

choices.

### Root present

An ideal containing the root must contain every gate ancestor below it, hence the whole subtree. There is exactly one such ideal.

Therefore

\[
\boxed{
F_h=F_{h-1}^2+1.
}
\]

The first values are

\[
2,\ 5,\ 26,\ 677,\ldots
\]

## 3. Full pre-output asynchronous state count

For the full `k=2^d` compiler, remove output root `z`. The remaining helper poset is the disjoint union of two height-`d-1` gate subtrees, so

\[
\boxed{
N_{async}(2^d)=F_{d-1}^2.
}
\]

Exact values include

\[
\boxed{
N_{async}(4)=4,
\quad
N_{async}(8)=25,
\quad
N_{async}(16)=676,
\quad
N_{async}(32)=458329.
}
\]

## 4. Width and synchronous comparison

The widest antichain is the first helper-gate layer, containing one gate per raw pair. Hence

\[
\boxed{
\operatorname{width}(P_{gate})=\frac{k}{2}.
}
\]

By contrast, deterministic synchronous pre-output execution has exactly one helper state per parallel level, including the empty initial helper set:

\[
\boxed{
N_{sync}(2^d)=d=\log_2 k.
}
\]

Thus the exact comparison is

\[
\boxed{
\log_2 k
\quad\text{versus}\quad
F_{\log_2 k-1}^2
}
\]

for synchronous path states versus asynchronous ideal states.

## 5. Architectural consequence

The enormous state-count gap is generated by scheduler freedom alone. The raw input, compiler DAG, helper count, rule set and saturated endpoint are fixed.

Therefore a runtime implementation cannot infer its required state precision from circuit size/depth alone; it must include the concurrency/scheduling language.

The same compiler can be low-state under a deterministic schedule and high-state under a permissive asynchronous schedule.

## 6. Prior-art boundary

Counting ideals of rooted trees and asynchronous configurations is classical enumerative order/concurrency theory. No generic novelty claim is made. P025 contributes the exact perfect-compiler specialization and its precision interpretation.
