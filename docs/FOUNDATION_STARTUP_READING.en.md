## Sources and meaning

`tools/build_em_foundation_startup.py` produces two offline, deterministic
reading projections from the same reviewed field mapping:

| Profile | Output | Consumers |
|---|---|---|
| `ordinary_research` | `definitions/EM_FOUNDATION_STARTUP.json` | TASK, Driver, Steward, frozen FREE B |
| `free_phase_a` | `definitions/EM_FREE_A_FOUNDATION_STARTUP.json` | FREE A |

The explicit mandatory relation contains P000, Heartbeat World, residual
fidelity, joint-relation preservation and global Weighted-BRC typing. Ordinary
links are not mandatory edges. Final Cell addressing and further exact
spatial/time/tool details retain their actual conditional triggers.

The packages are not new source authority. Each `normative_payload` group names
its source `path`; its `values` map uses exact JSON pointers to copied whole
values. Conditions, exceptions and nested fields remain present. Source
metadata and actual Git blob IDs identify the inputs; no build timestamp or
moving HEAD enters the output. The global repository's P000 V4 projection has a
different canonical source and is not a substitute for this Source relation.

Read current behavioral/control rules separately from the scientific inputs.
Preserve an existing task's/discovery candidate's frozen scientific pins. A
later control update cannot silently replace them.

## Build and check

Run from a checkout containing the actual five required sources:

```sh
python3 tools/build_em_foundation_startup.py --write
python3 tools/build_em_foundation_startup.py --check
python3 -m unittest discover -s tests -p test_em_foundation_startup.py
```

`--write` parses, resolves mandatory edges and classifies all inputs before
writing either generated file. A missing/invalid source, changed schema or
unclassified field prevents publication of a newly claimed complete package
and preserves the old outputs. Existing canonical sources and independent
work remain available. `--check` reports missing/mismatched outputs without
modifying them. `--report PATH` optionally writes the complete maintenance
coverage map; it cannot accompany a role read.

Exit codes are `0` for success, `1` for a generated-file mismatch, and `2` for a
source/input/output error or an unavailable read. Tests and build reports are
maintenance evidence, not new researcher registration or startup gates.

## Role-appropriate read and fallback

```sh
python3 tools/build_em_foundation_startup.py --read ordinary_research
python3 tools/build_em_foundation_startup.py --read free_phase_a
```

The local reader checks the actual scientific inputs, reuses a matching
generated package, or reconstructs the classified role-appropriate values in
memory when only the cache is absent/stale. `--scientific-inputs PATH` accepts
an optional JSON map of exact source paths to required Git blob IDs; a mismatch
does not rebase the pins. Local validation can be reused until the inputs or
receiving context actually change; no remote verification ceremony is added.

When classified inputs cannot be obtained, FREE A receives a short unavailable
result without a mixed-source dump, omitted-field catalog or build-report
details. Use a matching valid Phase-A package or an existing exact permitted
source read, and preserve actual exposure. Other independent work continues.
Ordinary roles may use exact canonical sources at their required versions.

For connector-only readers, the two output files are separate complete
artifacts. Fetch the profile for the actual role at its required scientific
version; do not fetch a mixed ordinary package and then ask the model to ignore
parts already received. Read the current FREE role, anti-anchoring and primitive
substrate separately. Those entry texts route B-specific inventories to the
Phase-B reference rather than listing them inside Phase A.

## Question-first precise lookup

An independent question that actually contains the relevant typed structure
may use precise definitions, applicable conditions and needed tool material
before the candidate is frozen. Whole catalogs, result comparison and dedup
remain Phase B. Record the question/source relationship in existing notes.

The local reader accepts one exact request:

```sh
python3 tools/build_em_foundation_startup.py --lookup /path/to/request.json
```

```json
{
  "question_formed": true,
  "structure_relevant": true,
  "path": "definitions/ENTERPRISE_BRC_WEIGHTED_LOG_FOUNDATION_20260902.md",
  "selector": "2. Positive weighted branch carrier"
}
```

This is a maintenance example for an already formed finite positive-weight
branch question, not a suggested Phase-A question. No candidate-freeze field
is required. The booleans express the caller's actual problem/relevance
judgment; the reader does not independently certify origin, clean context,
mathematical truth or novelty.

The first adapter supports exact definition sections and the positive-branch
tool symbols `CWMState`, `cwm_from_positive_weights` and
`is_positive_path_realizable` in `src/enterprise_math/brc_weighted.py`. A tool
selection includes its same-module static source dependencies, without the
whole module or unrelated tool inventory. An optional `source_blob` pins this
selected source. These selectors are maintenance documentation; they are not
preloaded as a topic menu in the Phase-A package.

Unformed or unrelated input returns `NOT_TRIGGERED`. An unsupported selector
does not authorize a whole-file fallback: use the existing stage-appropriate
exact reader or extend this small adapter for a concrete need. The supported
adapter is not an exhaustive list of permitted research topics or tools.

## Coverage and actual measurements

The full field classification stays in the maintainer report. FREE A receives
the current mandatory values, minimal source identity and generic conditional
lookup instruction. Current required premises may themselves mention prior
terms/results; they are preserved, and the package does not certify a clean
context or erase prior exposure.

Static package size measures the named file bytes only. It does not measure
tool wrappers, host injection, cached reuse, the complete role/control chain,
first substantive work latency or an end-to-end context ceiling. Preserve
actual raw samples and compare only matching task/science/role/cold-or-warm
conditions; otherwise report measured absolute values and missing evidence.
