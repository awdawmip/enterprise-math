# Driver review and optional follow-up

Status: current research policy, 2026-11-13. This policy changes workflow, not mathematical conclusions.

Saving results, continuing the actual scientific frontier and selecting future directions do not require a six-gate matrix, a follow-up packet or a fixed number/order of reviews. Missing review is NOT_REVIEWED; unresolved multiple reviews remain unresolved evidence. Neither state stops mathematics or silently grants acceptance.

## Actual review evidence

One immutable review retains its author, scope, disposition and evidence. Multiple reviews are all retained; latest timestamp never wins by itself. If a single operational judgment is needed, an authorized Driver may explicitly synthesize the exact current set with a real rationale. Reference passes are optional and may occur in any order/number. A synthesis without them records NOT_PERFORMED. Original records and findings stay immutable.

`tools/research_result_records.py review` accepts an optional `--followup-spec`; omission saves the actual review without manufacturing another Task or checklist. `review_reference`, `review_synthesize`, and `followup_materialize` retain current own Driver/DA and contribution checks. See the existing [operation fields](DRIVER_FLOW_OPERATIONS.md) only when using those operations.

## Optional planning

`gate_decisions` may be omitted or contain only relevant annotations. Omitted names are NOT_REVIEWED. A REQUIRED annotation is advice, not a command to create a matching Task. An asserted SATISFIED annotation still needs real evidence; the service never invents it. `task_role` is descriptive planning metadata, not an execution-role grant.

Lean/formalization is deferred and is not a default progress or ordinary acceptance prerequisite. When validation is needed, use the proposition’s reproducible human proof or recalculation. Existing active owners and explicit work are preserved; default new-unit selection defers only tasks explicitly tagged LEAN_FORMALIZATION.

## Formal state and existing work

A pending review or absent/invalid follow-up packet does not block subsequent research. Canonical dispatch preserves a later actual live owner and the recorded scientific frontier. A rejected unreviewed DONE is not formal closure, but it is not a permanent research blockade. Actual hard resource/scientific blocks, owner CAS, session/role authenticity and immutable publication boundaries still apply.

Formal Task/parent closure must state its actual scope and meet its own existing evidence contract; acceptance of a bounded negative result does not prove the mother objective. In particular, an old report lacking a typed completion assessment is not retroactively rewritten. Its existing accepted disposition remains usable; optional planning metadata is not mistaken for another mathematical review. Preserve successor publications such as H0O and their owners.

`EXISTING_PUBLISHED_TASK_BOUND` links the exact existing Driver-published Task named by one accepted immutable review; it does not retype lineage, republish a Task or create a CLAIM. `EXISTING_CONTROL_ASSET_BOUND` retains its exact-set integration binding meaning. An explicit `supersedes_followup_packet_id` correction preserves old RR/DR/DFU bytes and one source-preserving, hash-pinned chain; old invalid packets are not silently declared valid.

## Work acquisition and resource waits

The existing claim tool returns an already-open run when the caller also has its existing execution:prepare grant. It reuses the actual winning authorization. Legacy claim/open receipts remain usable and old open stays idempotent. Resume can renew only the current still-live own canonical claim through a uniquely journaled HEARTBEAT, subject to execution:claim; a local checkpoint timestamp does not renew ownership or take another owner’s claim.

Definite transient read-only resource waits resume the original request and cursor with persisted 5–300s backoff. Fixed capacity requirements are reported honestly. Cancellation wins its race and is never revived. Refusals are not replayed. Unknown writes reconcile only the original request; no replacement identity, request or automatic mutation is used.

Implementation and deployed version must be reported separately. This change does not launch research, infer a CLAIM from registration, accept mathematics, change scheduling or expand credentials.
