## Research-mode precedence

Current canonical source `research_architecture.json` controls research-context visibility.

- `FREE_AXIOM_DISCOVERY` uses the primitive discovery substrate before candidate freeze;

This tool surface does not choose the research question.

## Explicit TASK_RESEARCH hot start

Before substantive work, normally use only:

1. `AGENTS.md` — compact role/safety/liveness router;
2. **the exact task entry** — supplied taskbook, exact theorem/spec/code object, or exact current router when foundation selection itself is the task;
3. **the first exact dependency actually needed to begin**.

Then work.

Do **not** make Common Surface an automatic second read. It is a triggered ownership/theorem/tool/conflict lookup surface, not a default context dump.

## FREE_AXIOM_DISCOVERY hot start

FREE does not use the TASK packet.

Phase A begins from:

1. FREE role/anti-anchoring contract when exact role mechanics are needed;
2. `definitions/00_FREE_AXIOM_DISCOVERY_SUBSTRATE.md`;
3. only exact primitive definitions that substrate router actually requires.

Do not preload the general current-result router, current research/coordination context, or a suggested question/discovery-lens menu before candidate freeze.

Use generic exclusion categories rather than enumerating salient current results merely to forbid them.

After candidate freeze, the general current-result router and prior/current project context may be opened for Phase-B falsification, de-duplication, prior-art and integration audit.

## Tests / Lean / computation

Use relevant diagnostics only when actual repeated formal/test/tool work begins. Do not poll CI.

Computation/formal tools are evidence/mechanics surfaces. Their existence/ease is not a reason to select an ontology or FREE research question.

## Runtime tools

Inspect the actually available runtime tool surface before promising an operation. Connected GitHub may be used for canonical reads and authorized writes. Other tools are used only when available and appropriate.

## Read stability

Within one execution phase, reuse immutable content already fetched at a known SHA/ref. Re-reading unchanged routers/PR metadata merely for reassurance is a performance defect.

Refresh only when freshness/concurrency can materially change the result or immediately before a concurrency-sensitive write.
