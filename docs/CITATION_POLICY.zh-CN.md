# 引用与思想谱系规则

## 1. 适用范围

本规则适用于进取数论引用的外部数学、计算、物理、历史与哲学来源。

目标不只是生成参考文献表，而是让每一个借用的定义、结构类比、竞争解释和创新边界都可以追溯。

## 2. 规范来源编号

任何在规范项目文字中被实质使用的外部来源，都必须在 `sources.json` 中拥有一个稳定的 `SRC-*` 记录。

规范文字使用以下格式引用：

`[SRC-EXAMPLE-ID]`

来源记录至少必须包含：

- 稳定编号；
- 标题；
- 作者或负责机构；
- 年份；
- 来源类型；
- 原始链接或 DOI；
- 关系角色；
- 进取数论具体使用了什么；
- 明确说明**哪些内容不能声称是我们的发明**；
- 核验日期。

## 3. 来源优先级

技术和历史主张按以下顺序优先选择来源：

1. 原始研究论文或首次正式出版物；
2. 官方标准或官方项目/数学库文档；
3. 作者维护的预印本或机构档案；
4. 原文无法获得时使用权威学术综述；
5. 二手摘要只用于导航，不作为关键归因依据。

如果后续综述能够解释一个领域怎样发展，可以在原始来源之外补充引用综述。

## 4. 关系标签

任何实质影响项目结构的来源，都应在 `lineage.json` 中分类。

核心允许关系为：

- `ADOPT`；
- `EXTEND`；
- `REINTERPRET`；
- `COMBINE`；
- `CONTRAST`；
- `INSPIRE`。

同一个来源对于不同项目构件可以具有不同关系。

## 5. 主张与来源对应纪律

引用必须真正支持它所附着的句子或命题。

不能仅仅因为一篇论文“主题相近”就引用它。

不能把结构邻居论文当成进取数论物理解释成立的证据。

当前人和进取数论使用相同公式但语义不同，必须同时说明形式一致点和语义差异。

## 6. 创新表述

历史创新本身也是一个独立主张，需要独立证据。

在专门的优先性审查完成之前，整体框架保持 `NOVELTY_UNVERIFIED`。

安全表述：

- “我们定义”；
- “我们提出”；
- “我们组合”；
- “我们重新解释”；
- “我们研究”；
- “在当前记录的检索范围内尚未发现等价整体组合”。

以下表述需要专门优先性审查：

- “首次”；
- “前所未有”；
- “此前从未提出”；
- “原创发明”；
- “不存在前人工作”。

发现新的前人工作属于成功研究贡献，不是对项目的威胁。

## 7. 新来源更新流程

任何新引用只要进入规范工作，就必须：

1. 核验原始来源；
2. 在 `sources.json` 中创建或复用一个 `SRC-*` 记录；
3. 在 `lineage.json` 中把来源连接到相关项目构件；
4. 选择正确关系标签；
5. 如果来源改变思想谱系或创新边界，同步更新 `docs/PRIOR_ART_AND_NOVELTY.en.md` 及其中文版；
6. 更新任何实际依赖它的定理、规范、参考文献或物理对照文档；
7. 除非旧记录本身事实错误，否则不删除旧来源；
8. 运行引用完整性与双语检查。

如果一个来源只是修正拼写或提供无实质影响的背景例子，可以不改变创新图，但只要进入规范引用，仍需建立来源记录。

## 8. 项目内部贡献来源

外部文献和项目内部原创贡献分开追踪。

如果某个定义、定理、反例、证明思路、实现或术语修订源自 GitHub Issue、Discussion、commit 或 Pull Request，应在可行时在相关规范文档中保留项目来源。

不能用外部引用把贡献者来源覆盖掉。

## 9. 修正与争议

如果发现误读来源：

- 同时修正中英文版本；
- 更新 `sources.json` 或 `lineage.json`；
- 保留 Git 历史；
- 明确缩小或撤回受影响的创新主张。

如果两个来源冲突，应记录冲突，而不是静默选择更有利于进取数论的那一个。

## 10. 自动检查

`tools/check_references.py` 用于验证机器可读的来源谱系和稳定来源编号。

以下情况必须让 CI 失败：

- 来源编号重复；
- 必填来源元数据缺失；
- 谱系关系指向不存在的来源；
- 规范 `[SRC-*]` 引用指向不存在的来源；
- 项目构件使用未知创新状态；
- 来源登记表中的来源没有出现在主要前人工作图中。

自动化无法判断一次引用在思想上是否诚实。审阅者仍必须检查引用来源是否真的支持所声明的关系。
