## Executive verdict

Primary return:

`POST_ERROR_INHERITANCE_POSITIVE / MUSE_EFFECT_TASK_DEPENDENT / NO_STARTUP_PRESELECTION / NOT_CANONICAL`

The strongest stable result is **not** “Muse makes researchers correct.” It is narrower:

1. a failed/narrowed/prior-art-absorbed route can be compiled into a typed lesson whose reusable unit is the **failure structure plus survivor structure**, not a blacklist label;
2. `SHOULDER_SEARCH` can be restricted mechanically to the structure of a failure that has already occurred;
3. historical shoulders then reduce repeated conceptual reconstruction without forbidding re-entry under changed carrier, horizon, semantics, assumptions or target;
4. a pull-only Muse can increase branch, representation and question diversity, but the gain depends on exploration budget/task structure and genuinely includes unproductive serendipitous branches;
5. therefore R032 does **not** promote the full PASS token `EXPLORATION_MUSE_POSITIVE`. The stable core is post-error inheritance; Muse remains a phase-relative, task-dependent research affordance.

No canonical theorem/common surface is modified.

## 1. Temporal order: researcher exploration before meta-tool exposure

R032 freezes the following chronology.

`TASK CONTRACT + ACCEPTED FACTS + STATUS + PROVENANCE + EXCLUSIONS`

→ `FREE RESEARCH / TOOLS_DORMANT`

→ researcher develops hypotheses/representations and may be wrong

→ either:

- researcher explicitly emits `STUCK / NEED_NEW_IDEAS / SEARCH_TOOL_LIBRARY / explicit analogy or different-direction request`, in which case Muse may be pulled; or
- researcher accepts a route as killed, narrowed, prior-art absorbed or abandoned, in which case Lesson Compiler becomes legal.

Only after the second path has produced an actual `failure_structure` may automatic `SHOULDER_SEARCH` run.

Forbidden startup chronology:

`TASKBOOK -> semantic signature -> historical gold -> selected correct tool -> research`.

Forbidden correction chronology:

`new claim -> automatic challenger -> historical warning -> forced convergence`.

The implementation makes these timing rules executable: Muse rejects unrequested activation; Lesson Compiler rejects pre-failure calls; Shoulder Search rejects extra query fields such as taskbook/gold.

## 3. Exploration Muse: retrieval policy and diversity evidence

`research_muse_registry.json` freezes `TOOLS_DORMANT` as the THEORY_EXPLOSION default and four Muse shelves:

- **Tool Shelf** — typed R029 tools used as question generators, not startup directives;
- **Analogy Shelf** — cross-domain analogies with the hard marker `ANALOGY_IS_GENERATOR_NOT_EVIDENCE`;
- **Mutation Shelf** — carrier/observable/horizon/direction/assumption/semantics/scale/coordinate mutations;
- **Strange Tool** — deliberately low-similarity possibilities for serendipity.

The retrieval objective is `EXPLORATION_BRANCH_DIVERSITY_NOT_CORRECTNESS_RANKING`. Semantic proximity may contribute to a shelf, but semantic-nearest-only retrieval is forbidden as the sole strategy.

Registry-geometry stress test used five query families and 32 seeds/query. The original full runner produced mean unique tool layers `3.0` for the semantic-nearest control versus `3.2` for Muse; Muse was worse on none of the five queries, while strange-tool draws exposed roughly four to five domains/query. This is only evidence that the retrieval mechanism diversifies its own output, **not** evidence of human scientific productivity.

A crucial negative control was retained: the Muse pool contains deliberately unproductive branches (`dimension_numerology`, `decimal_pattern_hunt`, `single_entropy_proxy`, `metaphor_only`). A Muse that can only emit routes designed to become useful would trivially prove itself by construction.

## 4. Post-Error Lesson Compiler

The lesson schema requires:

`lesson_id, source_route, failure_class, researcher_accepted_failure, original_question, original_claim_or_model, what_failed, minimal_witness_or_failure_evidence, what_survived, unexpected_structure_revealed, new_distinctions, new_objects_or_coordinates, new_tool_candidate, new_negative_boundary, new_questions_generated, analogous_prior_failures, how_prior_failures_helped, what_should_NOT_be_inferred, novelty_status, confidence_evidence_grade, failure_structure`.

Two fields are non-negotiably nonempty:

- `what_survived`;
- `new_questions_generated`.

This prevents a postmortem from degenerating into an error ledger.

Five historical lessons were compiled for R020/R022/R025/R027/R028. The compiler also accepts `UNPRODUCTIVE_ROUTE` if it still has a bounded survivor such as “this coordinate does not discriminate this declared fixture” and a new question such as “is the route bad, or is the observable under-instrumented?” Thus “no theorem survived” does not automatically mean “zero research value.”

Hard anti-fence rule:

> A lesson may say “under conditions H, route C failed by witness W and left survivor S.” It may not compile this into “do not research C.”

## 5. SHOULDER_SEARCH

Allowed query fields are exactly:

- `failure_class`;
- `minimal_witness`;
- `broken_implication`;
- `surviving_invariant`;
- `newly_exposed_object`.

The original taskbook, semantic signature and historical gold are rejected as query inputs. This is the central timing firewall: the direction of historical retrieval is generated by the researcher’s own experienced failure.

Four structural fixtures recover the intended first shoulder in the original full run:

- hidden middle-join/composition failure → R020;
- scaling/covariance failure exposing phase → R025;
- order-dependent scalar credit failure → R028;
- useful generic mechanism absorbed by prior art → R022.

Each result returns prior failure, survivor, possible transfer, non-transfer warnings and historical generated questions. It does not return a prohibition.

## 6. Four-policy open-ended synthetic backtest

Worlds:

`COMPOSITION_WORLD`, `SCALE_PHASE_WORLD`, `CREDIT_WORLD`, `OPEN_MULTI_THEORY_WORLD`.

Each world admits multiple valuable representations/objects; no single gold theorem is declared. Full local run: 3 budgets (`14,18,22`) × 64 seeds × 4 worlds × 4 modes = `3072` runs.

| metric (mean) | FREE_ONLY | STARTUP_PRESELECT | CLAIM_ADVERSARY | MUSE_PLUS_ERROR_INHERITANCE |
|---|---:|---:|---:|---:|
| hypothesis count | 4.000 | 2.000 | 3.000 | 6.000 |
| representation diversity | 4.000 | 2.000 | 3.000 | 6.000 |
| non-registry concept yield | 1.750 | 0.500 | 0.250 | 2.794 |
| productive failure ratio | 1.000 | 0.000 | 0.000 | 0.833 |
| lesson yield / failed route | 0.000 | 0.000 | 0.000 | 1.000 |
| new question yield | 2.250 | 0.250 | 0.500 | 4.671 |
| effort to first valid object | 4.043 | 3.000 | 3.637 | 4.043 |
| premature abandonment | 0.000 | 0.000 | 0.333 | 0.000 |
| repeated conceptual cost | 2.000 | 0.000 | 1.000 | 1.162 |
| inherited conceptual cost saved | 0.000 | 0.000 | 0.000 | 2.236 |
| muse-induced branch diversity | 0.000 | 0.000 | 0.000 | 1.835 |
| valid object yield | 3.000 | 2.000 | 2.000 | 3.480 |

The most informative comparison is not “who converges fastest.” `STARTUP_PRESELECT` converges fastest in this historical-preference control while producing substantially fewer representations/questions/non-registry concepts. `CLAIM_ADVERSARY` suppresses visible wrong routes, but in doing so produces premature abandonment and prevents the failure structure from being experienced. `MUSE_PLUS_ERROR_INHERITANCE` does **not** improve time-to-first-valid over FREE_ONLY, but it raises branch/representation/question diversity and reduces repeated conceptual reconstruction after analogous failures.

Muse also lowers the productive-failure ratio from `1.0` to about `0.833` because some strange branches are genuinely unproductive. This is a desired adversarial result: Muse is not free value. At budget 14, many added branches do not cash out into more valid objects; at 18 and 22, more worlds convert those branches into additional objects/concepts. Hence the NARROW verdict: Muse benefit is budget/task dependent.

## 7. Productive Failure Metric: scalar killed, vector/Pareto survives

A productive-failure route is represented by coordinates such as:

`(new valid distinctions, counterexamples, tool candidates, new questions, reusable negative boundaries, unsupported overclaims)`.

Several plausible scalar weightings were attacked. Tool/question-heavy weights can favor R022 while boundary/distinction-heavy weights favor R028. The same five historical profiles therefore do not admit a weight-free canonical ranking.

Surviving rule:

1. preserve the vector profile;
2. compute a Pareto frontier;
3. scalarize only after an explicit objective/weight convention is declared.

This mirrors the R028 lesson: a useful scalar summary is not the same as an intrinsic scalar ontology.

## 8. Convergence-oriented assumptions killed or narrowed

1. `fewer wrong hypotheses -> better research` — killed as a universal objective; fewer unsupported overclaims remains useful later.
2. `faster convergence -> better research` — killed; convergence remains one secondary coordinate.
3. `historical error warning should always surface before retry` — killed; post-error shoulder retrieval survives.
4. `most semantically similar tool is best inspiration` — killed; relevance is one signal, diversity/serendipity remain separate objectives.
5. `post-error lesson should prescribe the next direction` — killed; it exposes survivors/transfers/questions plus non-transfer warnings.
6. `failed route has zero value if no theorem survived` — killed; bounded negatives/instrumentation questions may survive.
7. `one scalar ranks all productive failures` — killed; vector/Pareto survives.
8. `same meta-tool policy is optimal in all phases` — killed; phase-relative policy survives.
9. `repeating a historically failed idea is necessarily wasted` — killed; changed semantics/carrier/horizon/assumptions may invalidate the old boundary.
10. `tool retrieval should optimize correctness rather than idea diversity` — killed for THEORY_EXPLOSION; correctness/evidence gates strengthen later.

## 9. Phase comparison

### THEORY_EXPLOSION

Default: `TOOLS_DORMANT`. Muse is pull-only. Automatic claim adversary is off. Errors receive high tolerance. Post-error extraction is strong. Local proof/evidence checks still apply whenever a theorem/evidence claim is actually made, but diagnostics are not injected merely to steer the search.

### THEORY_CONSOLIDATION

Targeted theorem/composition/negative-boundary diagnostics may activate because the objective has changed from generating theory to comparing and stabilizing reusable structure. Muse remains pull-based. Lessons/shoulders continue to preserve failure inheritance.

### CANONICALIZATION

Strong proof checking, evidence grading, root coverage, prior-art/status correctness and promotion gates are appropriate. Muse is optional/nonblocking. At this phase a policy optimized for free branching would be misaligned with the acceptance objective.

Thus meta-tool intensity is phase-relative rather than universal.

## 10. Prior-art rooting and Enterprise Math residue

R032 does not claim to invent exploratory search, divergent creativity, case-based reasoning, failure-driven learning, explanation-based learning, CEGAR, design rationale, negative-results publication, serendipity-aware recommendation, novelty search, quality-diversity or falsification/error philosophy.

The project-specific residue is narrower:

`future-relative exact mathematics + typed post-error lessons + pull-based inspiration + failure-structure-only shoulder retrieval + explicit anti-fence semantics`.

Important distinctions from nearby prior art:

- unlike ordinary case retrieval, Shoulder Search forbids original task/taskbook/gold inputs and activates only after an actual failure structure exists;
- unlike CEGAR, the system is not required to use counterexamples to converge toward one target abstraction; counterexamples may instead generate new objects/questions;
- unlike accuracy-optimized recommendation, Muse explicitly admits far-neighbor/strange items and measures branching diversity separately from correctness;
- unlike a failure-memory blacklist, lessons preserve conditional scope and explicitly record what must **not** be inferred.

Prior-art absorption is itself treated as productive failure: it can kill a novelty claim while preserving a project-specific interface or question generator.
