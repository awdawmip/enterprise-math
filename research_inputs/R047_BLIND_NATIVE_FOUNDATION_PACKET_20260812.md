# R047 Blind Native Foundation Packet

Status: `FROZEN INPUT / CALIBRATION TARGET WITHHELD / NOT THEOREM EVIDENCE`

Purpose: provide the same minimal native-side starting language to blind Foundation arms before any engineering calibration target is opened.

## 1. Foundational rule

Use the active project rule:

`Definition is not inherited. Success is evidence. Explain the success from a smaller native logic.`

During this Foundation phase, however, the engineering-success target itself is sealed. Do not infer or reconstruct it from project history.

## 2. Declared bare relational starting substrate

The starting language may use only the following as given native-side material unless a candidate explicitly derives more:

- a carrier of cells / finite states;
- declared local contact or incidence relations between cells;
- occupancy / membership of a finite current state when a candidate uses occupied clusters;
- equality and ordinary finitary logical formation;
- exact finite/integer bookkeeping attached to explicitly declared finite relations.

No center, distance, equidistance, radius, circle, sphere, angle, radian, Euclidean embedding geometry, continuum point set, smoothness, area/volume measure, Fourier normalization, Gaussian normalization, PDE, or classical pi is part of this starting substrate.

## 3. Available construction language, not pre-granted ontology

A candidate may construct and type, when justified from the declared substrate:

- local relation patterns and finite-alphabet labels;
- finite counts / histograms / quotients as readouts;
- collapse / quotient / support / residual state;
- deterministic forward rewrite or addition rules;
- branching and recoalescence semantics;
- finite-memory carriers and recursively updateable state;
- explicit scale / precision states and refinement maps;
- integer or finite algebraic state extensions.

Every such construction must state whether it is N0-definable, an N1 operational choice, or an N2 readout. None becomes native merely because it is useful.

A calibration target has already been frozen by the Driver before this packet was issued. Foundation arms are not given its content.

If target-specific information is incidentally visible through unavoidable surrounding context, record `CONTEXT_CONTAMINATION_RISK` and do not use that information to generate, mutate, rank, or kill candidates.

## 5. Foundation objective

Generate a diverse frozen set of **4 to 8 candidate native mechanisms** from the starting substrate and available construction language.

The objective is not to guess a specific engineering target. The objective is to discover small native mechanisms with internally strong structure and potentially broad emergent behavior.

Do not force one winner. Preserve serious competing branches and productive failures.

For each candidate freeze:

1. candidate ID and one-sentence native idea;
2. exact declared substrate and any added choices;
3. typed dependency graph;
4. state carrier;
5. exact local/update law;
6. collapse / quotient / support semantics if used;
7. scale/refinement semantics if used;
8. invariants or monotone quantities actually proved or exactly checked;
9. composition / recursion behavior;
10. internal degeneracies and minimal kill witnesses;
11. parameter count and which parameters are structural versus arbitrary;
12. what genuinely new object, theorem question, or representation the candidate exposes;
13. contamination statement certifying that no sealed calibration criterion was used.

## 6. Internal evaluation allowed before calibration

Candidates may be compared only on native-side criteria such as:

- semantic admissibility and dependency closure;
- exact update closure;
- composition safety;
- finite-information economy;
- choice independence / relabeling equivariance when relevant;
- nontrivial multiscale behavior;
- ability to generate rather than merely encode structure;
- robustness to obvious internal counterexamples;
- explanatory compression measured only against the candidate's own declared native phenomena, not external engineering targets.

Do not score candidates by resemblance to circle geometry, classical pi, periodic `2pi`, Gaussian/Fourier formulas, engineering protocols, or any withheld calibration member.

- Wrong turns are allowed.
- If genuinely stuck, a researcher may voluntarily request existing native-side tools/shoulders, but must not request the sealed R046 target.
- Preserve productive failures as `what the failure exposed`, not as future prohibitions.
