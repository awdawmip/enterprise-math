## Architecture

The existing task machine remains the sole authority. Current-state inventory and continuation packets are projections. New service sessions have real newly allocated execution identities; public registration records cannot authenticate possession of their private session capabilities. Driver DA activation is separate from researcher RA registration.

A successor preserves the existing immutable task, source boundary, completed work and frontier, then obtains a new authenticated CLAIM/ER under exact predecessor CAS. One accepted successor fences old execution writes. Recent accepted owner activity blocks stale takeover. A real CONTINUATION HANDOFF releases work for resume. Current-session Driver succession follows the same provenance-preserving principle; historical valid reviews remain valid at their original time.

Checkpoint, Result freeze and Driver review use the existing native writers and current role/ownership checks. Prospective Result/review receipts bind their payload, actual frozen taskbook and observed authenticated events. A new old-format record without a valid receipt cannot silently change operational state. The exact pre-cutover record list preserves original bytes and does not waive any original audit.

MCP reads pinned branch evidence independently of the current control commit. It publishes only bounded generated records and task/session artifact namespaces, verifies Source bytes, and then emits coordination events. Durable operation journals distinguish known unapplied conflicts from unknown remote effects. No arbitrary shell or uploaded research program is executed by the service.
