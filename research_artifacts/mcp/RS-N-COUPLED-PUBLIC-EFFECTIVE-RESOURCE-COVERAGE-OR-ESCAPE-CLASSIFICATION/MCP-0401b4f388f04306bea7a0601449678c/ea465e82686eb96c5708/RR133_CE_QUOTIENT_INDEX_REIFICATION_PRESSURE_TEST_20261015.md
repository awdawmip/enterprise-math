## 1. The completely specified mathematical family

Fix any public integer `N_0≥2` and the finite ring `R=Z/N_0Z`.
It may be a fixed permitted composite input; no primality assumption or
factorization of N_0 is required. Let `k` range over ordinary Turing-machine
indices on an empty input. Define a computably enumerable module relation
presentation with one generator u as follows:

1. Simulate machine k step by step.
2. If it halts, enumerate the single relation `u=0` once.
3. Otherwise enumerate no relation.

Write `E_k` for this enumerator and

`M_k = R u / span_R(relations enumerated by E_k)`.

The finite description of E_k is produced uniformly and effectively from
k. An ordinary program can immediately return that description or index.
Neither producing the index nor simulating a finite number of enumeration
steps requires a halting oracle. But the completed mathematical quotient is

`M_k = 0` if k halts, and `M_k = R` if k does not halt.              (P1)

Every individual M_k is finite, generated by one element and finitely
presented. In fact it is presented by the one-by-one matrix `[1]` or `[0]`.
At most one relation is ever enumerated. These facts do not identify which
finite presentation is correct for arbitrary k.

This is a conditional external algebraic interface, not a declaration of
new native X6 state or a reduction of native geometry. The enumeration step
is an ordinary typed process order. Assigning its code to an internal
register would not turn its unbounded quotient interpretation into a native
finite-time observable. No native physical mechanism is proposed.

## 2. Uniform support-reification impossibility

**Proposition.** There is no uniform partial computable compiler `B(N_0,k)`
that halts for every k in this family and outputs a finite explicit matrix
presentation `C_k` over R satisfying

`Supp_(N_0)(C_k) = Supp_(N_0)(M_k)` for every k.                              (P2)

The compiler need not return either displayed one-by-one matrix; arbitrary
finite dimensions and arbitrary finite explicit matrices are allowed.
It need not preserve the whole module: support alone already suffices for
the contradiction. It must preserve the completed quotient's support, not
merely that of an arbitrarily selected finite enumeration prefix.

*Proof.* Suppose B exists. Given k, compute C_k; this terminates by the
stated domain promise. Apply the inherited finite-presentation support
readout to C_k: compute `delta=gcd(N_0, all maximal minors)` with the exact
empty-matrix conventions fixed in the current application document.
This is a total effective calculation on the returned finite object and
does not require factoring N_0. By support preservation and (P1), delta
is 1 exactly when k halts, and is greater than 1 exactly when k does not
halt. For nonsquarefree N_0, preserving support does not require the
returned delta to equal N_0; only the `delta=1` versus `delta>1` distinction
is used. Thus the procedure decides the halting problem,
which is impossible. ∎

The undecidability invoked here concerns this explicitly defined classical
index family. It is **not** an undecidability theorem about the Enterprise
Math Objective, its actual admission policy, factoring, or the coverage
Task. It demonstrates why a generic implication "effective finite runtime
index ⇒ effective support-bearing finite presentation" is false without
additional premises.

The domain promise is essential. A partial procedure that waits until the
relation appears and returns `[1]` is correct when it halts, but is undefined
for nonhalting indices; it is not the required all-input compiler. Printing
`[0]` after any fixed waiting period fails for a later-halting machine.
Returning a changing finite approximation with an unknown final stage is
not returning one certified finite terminal presentation. Even the known
bound of one enumerated relation supplies no effective "no more relations"
signal.

This also supplies a concrete limitation of the typed bridge's Lemma 3.
Let R(k,C) mean that C is a correct finite support presentation for M_k.
Each fiber has a witness. If this full relation were uniformly c.e. on
finite codes, the lemma's search would produce a total-on-this-family

uniformly c.e. Merely having a c.e. enumeration of *module relations* is not
having a c.e. enumeration of *correct completed-presentation witnesses*.
