## Frozen primary mechanism and matched universe

Public input is an odd distinct semiprime N, with no p,q supplied to the deployed algorithm. Set D=4N, K(N)=ceil(N^(1/3)) by exact public integer arithmetic, and freeze B=4 buckets. The interface also accepts generic positive N,K,B for correctness checks; those cases are not the Task's decisive stratified experiment.

For1<=k<=K define
x_k=ceil(sqrt(4kN)),
e_k=x_k²−4kN,
score_k=e_k/(2x_k−1),
bucket_k=floor(B*e_k/(2x_k−1)).

Always0<=e_k<2x_k−1, so bucket is in0,...,B−1. Priority is (bucket,k), increasing. This is a coarse bucket version of the old normalized-score family, not fully sorted rational scores within a bucket. No old conditional-rank statistics are transferred to this schedule.

The original4kN point cannot be replaced by2*ceil_sqrt(kN): atN15,k2, true x11/e1/score1/21, while that replacement givesx12/e24/score24/23>1. Likewise unnormalized residual thresholds would change the selected subset and are not presented as this original priority.

Matched comparator: the same single upper-square point for every same multiplier, in ordinary increasing-k Hart order; multiplier-Fermat uses the same offset-zero point budget. Any stronger implementation no more costly than that correct comparator only strengthens the obstruction. This is not a performance claim against every Hart fixed multiplier or every expanded Lehman interval. Hart's original modulo-N presentation and its fixed-M practical version are distinct from the old4kN primitive; the comparison here explicitly matches the old primitive.

Both schedules use the same necessary zero-inclusive QR tables for moduli64,3,5,7, the same exact residual-square test, and the same proper-factor termination. After a square e, test gcd(x−sqrt(e),N), then the plus sign only if the minus gcd is trivial. Gcd1 orN is a paid failure, not a success. The deployed functions receive no hidden factors or productive-hit labels. Public cube-budget construction, sieve-table construction/storage, optional equal prechecks and every failed candidate are paid; shared preparation is added to both totals.

## Exact inverse generator

Let a0=ceil_sqrt(D), amax=ceil_sqrt(DK), A=amax−a0+1. For an integer a in this inclusive range, a is the original x_k exactly when
(a−1)²<Dk<=a².

Thus its full multiplier interval is
L_a=max(1,floor((a−1)²/D)+1),
U_a=min(K,floor(a²/D)).

Each k occurs exactly once in these ordered shell intervals. They may be empty or contain several k. No factor of N is used. Put q=2a−1 and s=a². The normalized bucket b has
bq<=B(s−Dk)<(b+1)q,
hence intersect [L_a,U_a] with
k>=floor((Bs−(b+1)q)/(BD))+1,
k<=floor((Bs−bq)/(BD)).

The lower floor-plus-one enforces the strict upper bucket boundary. Exact lower boundaries belong to their bucket. Within each bucket, scanning a and local k upward gives increasing k; exhausting b0,...,B−1 yields every original multiplier once, in the declared priority. At a successful candidate the consumer may stop and pays the actually inspected prefix.

The implemented recurrence keeps s,previous_s,q. Advancing a by1 uses s'=s+q+2, previous_s'=s, q'=q+2. Every such transport and every empty shell inspection is charged. Endpoint roots are computed twice, rather than K times. That saving is exchanged for many more inspected rows; it is not a free residual oracle.

The simpler single-floor decoder k=floor(a²/D), e=a² modD covers all original candidates only when e<D is ensured. ForD4N the sufficient whole-window condition2amax−2<D is exactlyK<=N. Our growing K satisfies that condition, but the implementation retains full intervals for all K. A finite outside-regime witness isN15,D60,K24,a38: bothk23/e64 andk24/e4 have that same upper square, and the simple floor retains only24. This boundary is checked explicitly rather than silently narrowing the interface.

## Paid count identity

The full B-pass generator has the following exact logical event counts, verified by the new checker:
square_index_row=B*A,
row_floor_divisions=4*B*A,
row_products=3*B*A,
square_index_transport=B*(A−1),
endpoint integer_sqrt=2,
candidate_emission=K.

Bucket state initialization, comparison, arithmetic, output-field writes, all residual tests/modular checks/gcds and consumer failures have additional event entries. The ledger counts named logical operations and cells, not Python bytecodes or elapsed seconds. Integer operations have different bit costs. Meter overhead is not an experimental performance claim; every visited row still has positive sequential work. Generator state is a bounded number of O(log(NK)+logB)-bit integers. Output materialization, if requested by a downstream consumer, costs its emitted cells; the checker lists are offline validation, not a free deployed cache.

If the first proper-factor hit occurs at k* in bucket b*, current square a*=ceil_sqrt(4Nk*), the generated row count is exactly
G_hit=b* A+P,
P=ceil_sqrt(4Nk*)−ceil_sqrt(4N)+1.
Already emitted/tested candidates in that shell add their own charges. With no hit all B passes cost B*A and exhaust the same K-point universe; this changes neither complete-window productive coverage nor its lack of a universal guarantee.

For a single complete pass,
A=2sqrt(N)(sqrt(K)−1)+O(1).
At K~N^(1/3), A~2N^(2/3) and A/K~2N^(1/3). Merely reducing the naive sqrt-call count from K to2 does not lower total generation work. Nor is this literal scan output-sensitive in the accepted-output size: for promised squarefreeN, zero-threshold e=0 has k=N*j², so K<N has no output although A can be large. That only obstructs this implementation; that very promise can certify the zero-threshold empty set cheaply by another algorithm.

## Pointwise first-hit obstruction

For real X>=Y, ceil(X)−ceil(Y)+1>X−Y. Therefore if k*>=2,
G_hit>=P>2sqrt(N)(sqrt(k*)−1)
>= (2−sqrt(2))*sqrt(Nk*),
and
G_hit/k*>=(2−sqrt(2))*sqrt(N/K).

At K=ceil(N^(1/3))<=2N^(1/3), this gives the finite bound
G_hit/k*>=(sqrt(2)−1)*N^(1/3).

The comparator encounters that same productive original point, with the same necessary sieve and proper-gcd predicate, at some j<=k*. It examines at most k* points. A necessary QR rejection rule cannot remove an actual square; trivial-gcd cases continue in both implementations.

To turn rows versus points into a bit-cost comparison, explicitly assume the declared sequential implementation performs positive work at every visited a row. Let L=O(log(NK)). Ordinary exact multiplication, division, integer square root, residual-square test and gcd have polynomial bit-cost implementations; elementary binary-search sqrt and grade-school arithmetic already suffice. With the fixed four QR moduli, per-point comparator work is bounded by C*L^d for some fixed C,d. Thus variable work for the comparator is at most C*k*L^d, whereas the literal inverse scan alone costs at least a positive constant times G_hit. Its variable-work disadvantage is N^(1/3−o(1)), conditional on these stated bit-model assumptions. It has no fixed polynomial cost gain in this growing window. This does not claim finite 32–96-bit wall-time disadvantage from the row inequality alone.

If k*=1 and b*=0, both orders reach the same first multiplier and the quantitative k*>=2 bound does not apply; there is no ordering advantage. If k*=1 after earlier buckets, their b* complete scans remain charged. If the entire window fails, B*A rows compare to at most K ordinary points under the same rule; failed coverage is preserved.

For common paid preparation Q(N), totals are Q+W_inverse and Q+W_Hart. If W_inverse>W_Hart, adding Q cannot reverse that inequality, but a huge Q can make the ratio tend to1. Therefore the N^(1/3−o(1)) ratio is a variable-work statement and is not asserted for totals without a bound on Q. Arbitrary expensive candidate filters are not hidden in Q; this proof uses the explicitly fixed/polynomial-cost per-point budget.

Scope: literal square-index row scans with the declared bucket passes. A generator that provably skips empty shells, computes cheaper exact transports, uses different compressed indexes or changes the matched candidate family is outside this obstruction and needs its own paid proof. No general factorization no-go follows.
