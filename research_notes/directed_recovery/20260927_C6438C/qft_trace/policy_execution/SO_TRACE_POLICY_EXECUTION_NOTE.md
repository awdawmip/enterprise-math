## Restore, negative controls and interruption

A serialized new cursor with pending work at `100` is deterministically replayed and continues with bit `0`; the resulting new cursor bytes agree. This rebuilds the mathematical prefix and pending decision. It does not serialize a query cache or random tape.

Seven cursor negative controls reject changed own source, changed trace-bank source, changed guard contract, selected word, charge, Boolean history and an old-version cursor. Six require actual fresh replay, whose evidence is retained; Boolean history rejects before native work. Two additional controls reject the old bank type at construction and at a public boundary, both before native calls. The already tested 40 public-entry mutation combinations were not redundantly rerun: the new implementation reuses the frozen boundary routine and explicitly tests its changed type boundary.

With query budget two, an attempted bit is interrupted without committing it; pending work remains. Raising the budget and retrying that same bit produces the same cursor and raw mass as a fresh one-bit execution. The failed attempt is saved separately from the subsequent cumulative retry. Every captured top-level guard has depth zero and no owner.

All intermediate evidence snapshots used by the checker are detached with `deepcopy`. The inherited evidence method itself still returns some live arrays; future callers must detach snapshots before continuing the object. The reused guard restores nesting state on `BaseException`; inherited ledger rollback remains the existing `Exception` transaction, not a new promise for `KeyboardInterrupt` rollback. Constructor failures do not universally carry replay evidence. The checker has an outer unique-file failure handler preserving available CALLS, sources and traceback; no unexpected failed-execution artifact occurred in this run.
