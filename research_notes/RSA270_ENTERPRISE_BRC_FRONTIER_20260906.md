## 1. Second-layer semiprime tree: meaningful structure, wrong scale

For a multiplier branch `k` and offset `j`, the second-layer square-difference observer is

`A_k = 4*k*N`,

`x0 = ceil(sqrt(A_k))`,

`d_(k,j) = (x0+j)^2 - A_k`.

An endpoint factors only when `d_(k,j)=y^2`, since

`(x-y)(x+y)=4*k*N`.

More generally, products of branch defects can be used as congruences of squares when their valuation parity recoalesces. This is the correct BRC extension of the shell tree, but it overlaps the classical Fermat/Lehman/QS congruence-of-squares framework.

Exact N-only searches established the following finite negative boundary:

- `j=0` scanned through `k=10,000,000`: no exact-square endpoint;
- selected low-shell / low-defect branches scanned deeply in `j`: no endpoint;
- priority path-resolved `(a,b,j)` directions were also scanned without a factor;
- the best low-defect points remained hundreds of bits away from an exact square;
- pairwise exact-square recoalescences among low-shell branches were explained by identical squarefree multiplier kernels and yielded only trivial gcds;
- after stripping primes through `10^6`, the best retained residual cofactors were still roughly `348–366` bits;
- synthetic 895-bit semiprime tests showed low-defect second-layer coordinates did not predict the hidden factor ratio better than simple controls.

Hence:

`SECOND_LAYER_NEAR_SQUARE_MINIMUM != FACTOR_RATIO_ORACLE`.

`LINEAR_EXTENSION_OF_SMALL_k_OR_j != RSA270_SCALE_ATTACK`.

The useful continuation is relation generation with genuinely smaller/smoother norms, not a larger raw endpoint window.

## 2. Factor-ratio provenance must retain `(a,b)`, not only `k=ab`

For `N=pq`, the factor-bearing identity is

`(a*p + b*q)^2 - 4*a*b*p*q = (a*p - b*q)^2`.

Therefore a branch labeled only by `k=ab` is not operation-safe once factor interpretation is required. Distinct rational directions `(a,b)` with the same product `k` encode different hidden factor-ratio directions.

Freeze:

`RSA270_BRANCH_IDENTITY = (a,b,j)`, not merely `(k,j)`.

This corrected an earlier temptation to overinterpret unusually low shells at a particular scalar multiplier.

## 3. Construction-family prior: useful constant entropy reduction, not a break

The original RSA Challenge construction documents approximately equal-length primes constrained to `2 mod 3`. A forensic pattern across solved Challenge factors also shows a binary prefix `11`; the newly disclosed RSA-260 factors independently continue those observed properties.

If the same prefix pattern is carried as a **conditional empirical prior** to RSA-270, then the likely allocation is `447-bit × 448-bit`, both prime factors `2 mod 3`, with a narrowed factor-ratio interval. Prefix-box propagation further forces the first three bits to `111 × 111`.

However survivor counts then grow essentially exponentially again as more paired bits are exposed. Thus the prior removes only a constant amount of entropy and does not make direct bit-branch enumeration tractable.

No theorem about the unknown RSA-270 factors is claimed from the prefix pattern.

## 4. Historical RNG / RSAREF provenance route remains conditional

Historical RSAREF code exactly reproduces several observed family features:

- generated primes are forced into an upper interval giving binary prefix `11`;
- candidate search advances by 2;
- with public exponent `e=3`, the filter implies prime factors `2 mod 3`;
- the preserved random generator uses a 128-bit state and emits MD5-based blocks while incrementing state.

This is a strong construction-family match, but there is no authenticated evidence that the RSA Challenge decimal-list primes were actually generated by the same RSAREF key-generation path or PRNG state stream.

Therefore:

`RSAREF_COMPATIBLE_PATTERN != PROVENANCE_PROOF`.

Without authenticated generator/seed/state evidence, output-only state recovery remains computationally prohibitive and the RNG route is not an active factoring break.

## 7. Exact positive Enterprise result I: four-square/X6 shell observer is factor-complete

For the four-axis squared shell define

`R4(N) = #{ z in Z^4 : z1^2+z2^2+z3^2+z4^2=N }`.

Jacobi's four-square formula gives, for odd `N`,

`R4(N)=8*sigma(N)`.

For a distinct odd semiprime `N=pq`,

`sigma(N)=1+p+q+N`,

so

`S=p+q = R4(N)/8 - N - 1`,

and the factors follow from

`x^2 - S*x + N = 0`.

For RSA-270, `N == 7 (mod 8)`, so the one-, two-, and three-square support strata vanish and the first nonempty support stratum has support size 4. In the full six-axis shell this contributes

`C(6,4)*R4(N)=15*R4(N)`.

Thus the minimal-support squared X6 shell stratum is a factor-complete composite-indexed observer.

This is an exact reduction, not a fast algorithm: exact evaluation of this observer is itself factoring-equivalent on the semiprime family.

## 8. Exact positive Enterprise result II: four native B2 layers collapse to `sigma(N)`

For the 2D native L1 ball,

`B2(r)=2r^2+2r+1 = 4*T_r+1`,

with `T_r=r(r+1)/2`.

Using the classical four-triangular-number identity,

`C_X(N) = #{(a,b,c,d)>=0 : B2(a)+B2(b)+B2(c)+B2(d)=2N+2}`

satisfies

`C_X(N)=sigma(N)`

for odd `N`.

Hence for a semiprime `N=pq`,

`C_X(N)=N+1+p+q`,

so the total exact four-layer branch mass determines the factor sum.

More strongly, the Lambert expansion gives the factor-pair recoalescence condition at `M=(N-1)/2`:

`2ab+a+b=M`

if and only if

`(2a+1)(2b+1)=N`.

Therefore the four-layer Enterprise branch population is known **exactly** to collapse onto weighted factor-pair branches.

The unsolved algorithmic question is no longer whether the factor information is present. It is whether this recoalescence can be executed without enumerating an `O(sqrt(N))`-scale layer population or already solving the factor equation.

## 9. Exact no-go: fixed local modular collapse erases the factor information

For an odd prime `ell` with `ell` not dividing `N`, the identity

`2*B2(r)-1=(2r+1)^2`

forces the pair-sum support modulo `ell` to fill the field. Direct finite-field counting further gives

`#{a,b,c,d mod ell : sum B2(ai)=2N+2 mod ell} = ell*(ell^2-1)`,

independent of `N`.

The nonsingular prime-power lift has the same essential independence when the target is a unit, and CRT extends the effect to odd moduli coprime to `N`.

Consequently:

`FOUR_LAYER_FACTOR_INFORMATION = GLOBAL_INTEGER_BOUNDARY / PROVENANCE INFORMATION`,

not fixed-local-modulus support or multiplicity data.

Repeated local modular collapse cannot reveal the factors unless the chosen modulus already shares a factor with `N`, in which case gcd has already solved the problem.

This is the strongest exact negative result on the four-layer route.

## 10. Bivariate provenance lift: the factor-bearing block becomes an exact plateau boundary

A later refinement preserves more branch provenance instead of collapsing the four-layer count to the scalar `sigma(N)`.

Define

`W_s(u) = (u^(s-2)-u^(-s))/(1-u^(-2))`

`       = sum_{j=0}^{s-2} u^(2-s+2j)`.

The Ramanujan/Kac-Cheung product manipulation gives the exact Laurent-series form

`F(Q,u)=sum_{m,n>=1} W_(m+n)(u) * Q^(2mn-m-n)`.

For odd target `N` and `M=(N-1)/2`, the coefficient condition

`2mn-m-n=M`

is exactly

`(2m-1)(2n-1)=N`.

Hence

`[Q^M]F(Q,u) = sum_(d|N) W_((d+N/d+2)/2)(u)`.

This is a provenance-preserving lift of `sigma(N)`: each divisor-pair branch retains a Laurent block.

For `N=pq`, `p<q`, let `S=p+q`. Then

`[Q^M]F(Q,u)`

is exactly the sum of two known outer blocks plus one factor-bearing central block (each appearing with the divisor-pair symmetry). After subtracting the known `N`-dependent outer block, the maximal Laurent exponent of the remaining plateau is

`e_max=(S-2)/2`.

Therefore

`S=2*e_max+2`,

and the factors again follow from the quadratic equation.

This sharpens the current target:

`FACTORING_RSA270 <=> EXTRACT_THE_FACTOR_PLATEAU_BOUNDARY_FROM_THE_BIVARIATE_PROFILE`.

The unknown is whether that marked boundary can be obtained from the product/source representation in sub-factorization cost.

## 11. Root-of-unity compression hits a cryptographic hardness boundary

Let `omega` be a primitive cube root of unity. Then `W_s(omega)` depends only on `s mod 3`.

For an RSA semiprime with `N == 1 (mod 6)`, the specialized coefficient distinguishes whether the two hidden primes are both `1 mod 3` or both `2 mod 3`.

This is equivalent to deciding whether `-3` is a genuine quadratic residue modulo the RSA modulus rather than merely having Jacobi symbol `+1`.

Thus the first nontrivial torsion compression does retain a hidden factor bit, but it lands exactly on the standard quadratic-residuosity hardness boundary.

Freeze:

`TORSION_SPECIALIZATION_CAN_RETAIN_FACTOR_INFORMATION`,

but

`LOW_ORDER_TORSION != CHEAP_FACTOR_OBSERVER`.

For RSA-270, cheap gcd probes using exponents derived from `(N-1)/2`, `(N-1)/3`, `(N-1)/6`, small divisors of `N+1`, and small discriminants/bases produced no nontrivial factor. Extending the `(N-1)/2` base scan through primes below 2000 was also negative.

Small C6/C12-aligned cyclic Frobenius masks were likewise negative, and a maximally symmetric six-point subgroup mask collapses exactly to ordinary scalar order information. Excessive X6 symmetry therefore destroys the required branch provenance.
