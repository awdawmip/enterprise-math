## 1. Executive result

A reusable Enterprise finite-certificate tool exists, but its source is **constraint factorization**, not an assumed native Euclidean convexity.

The discovered calculus is:

> Decompose a global realization into independent state blocks. Give each block a local admissible-set class with a bounded local infeasibility certificate number. Global block-rectangular constraints inherit a certificate number equal to the **maximum**, not the sum, of the local numbers. A global failure projects to one bad block and therefore has a bounded local witness.

The central structural law is

`INDEPENDENT_BLOCK_COMPOSITION -> GLOBAL_CERTIFICATE_NUMBER = MAX_LOCAL_CERTIFICATE_NUMBER`.

For the most useful Enterprise special case—integer interval coordinates or Boolean partial-assignment coordinates—the local number is `2`; therefore arbitrarily many independent coordinates still have global certificate number `2`.

The exact negative boundary is equally important:

> Bounded domain size, bounded constraint arity, and even a path/tree interaction graph do **not** imply a bounded certificate number once constraints can propagate relations across an unbounded chain of blocks.

There is an explicit Boolean path family with `n` variables and `n+1` constraints whose whole family is infeasible but every proper subfamily is feasible. Hence minimal obstruction size is unbounded.

This gives a reusable positive tool together with a falsifiable failure boundary.

## 2. Historical mechanism extracted, without importing classical geometry

The classical family of Helly/Radon/Carathéodory theorems contains three operationally different mechanisms.

### 2.1 Helly mechanism

Helly-type information is an **infeasibility compression** statement:

`GLOBAL EMPTY INTERSECTION -> SMALL EMPTY SUBFAMILY`.

Equivalently, if every subfamily up to the Helly number is feasible, the whole family is feasible.

The Enterprise tool keeps this operational meaning but does not assume Euclidean points, affine combinations, or convexity as native premises.

### 2.2 Carathéodory mechanism

Carathéodory-type information is a **generation compression** statement:

`POINT IN GLOBAL HULL -> POINT GENERATED BY SMALL SUBSET`.

This is logically different from bounded infeasibility certificates. In product systems its natural composition law is generally additive across blocks rather than max-like.

### 2.3 Radon mechanism

Radon-type information is a **forced partition collision** statement:

`ENOUGH GENERATORS -> SOME BIPARTITION HAS INTERSECTING HULLS`.

In abstract convexity a finite Radon number implies a Helly bound (`h < r`), so Radon can be a stronger route to finite Helly information. But it is not necessary for the Enterprise product theorem below: factorization yields the Helly certificate directly.

### 2.4 Why the three should not be identified

For the Boolean subcube/product-hull family in dimension `d`, this report proves:

- Helly certificate number `h = 2`;
- Carathéodory generator number `c = d`;

while a standard abstract-convexity face example has Radon number growing logarithmically with dimension while its Helly number remains `2`.

Thus a dimension-uniform `h=2` does not imply dimension-uniform Carathéodory or Radon numbers. The three mechanisms are related but not equivalent.

Conservative historical placement appears in Section 13.

## 3. Enterprise constraint language

### Definition 3.1 — block system

An **Enterprise block system** is a finite block index set `B` together with a nonempty state set `X_b` for every `b in B`.

The global realization space is

`X := product_{b in B} X_b`.

No geometry is assumed.

### Definition 3.2 — local admissible class

For every block `b`, choose a class

`A_b subseteq P(X_b)`

of admissible local subsets, containing the unconstrained set `X_b`.

A local family `F_b subseteq A_b` is feasible when

`intersection F_b != empty`.

### Definition 3.3 — local certificate number

The local failure-certificate number `h_b` is the least positive integer `h`, if it exists, such that every finite infeasible family `F_b subseteq A_b` contains an infeasible subfamily of size at most `h`.

Equivalently:

`ALL SUBFAMILIES OF SIZE <= h ARE FEASIBLE -> WHOLE LOCAL FAMILY IS FEASIBLE`.

If no finite bound exists, write `h_b = infinity`.

### Definition 3.4 — block-rectangular Enterprise constraint

A global constraint `C_i` is **block-rectangular** when

`C_i = product_{b in B} A_{i,b}`

with `A_{i,b} in A_b`.

An unconstrained block uses `A_{i,b}=X_b`.

A finite constraint family `F={C_i : i in I}` is globally feasible when

`intersection_{i in I} C_i != empty`.

Restriction to a subfamily is literal deletion of constraint indices.

### Definition 3.5 — failure certificate

A failure certificate is a pair

`(b, J)`

where `b in B`, `J subseteq I`, and

`intersection_{j in J} A_{j,b} = empty`.

Its size is `|J|`.

The certificate names both the failing block and the original constraints that already force the failure.

### Definition 3.6 — success witness

A success witness is one realization

`x=(x_b)_{b in B}`

such that

`x_b in intersection_{i in I} A_{i,b}`

for every block `b`.

### Definition 3.7 — symmetry

The interface is invariant under:

1. relabeling the constraints `I`;
2. permuting blocks `B`;
3. replacing each `X_b` by an isomorphic local state set under a bijection that transports the admissible class `A_b`.

Certificate size and feasibility are preserved under these relabelings.

## 4. Main theorem — max-law for finite certificates

### Theorem 4.1 — Enterprise Block Helly Transfer

Let `B` be finite. Assume every local admissible class `A_b` has finite certificate number `h_b` and let

`H := max_{b in B} h_b`.

Then every finite family of block-rectangular global constraints has the following property:

`GLOBAL FAILURE -> FAILURE CERTIFICATE OF SIZE <= H`.

Equivalently, the global block-rectangular class has Helly certificate number at most `H`.

### Proof

For a family `F={C_i : i in I}`,

`intersection_i C_i`

is exactly

`product_{b in B} (intersection_i A_{i,b})`.

Because `B` is finite and every block state set is ordinary set-valued, this product is nonempty exactly when every coordinate intersection is nonempty.

If the global family is infeasible, there exists a block `b*` such that

`intersection_i A_{i,b*} = empty`.

By the local certificate property of `A_{b*}`, there is a subset `J subseteq I` with

`|J| <= h_{b*} <= H`

and

`intersection_{j in J} A_{j,b*} = empty`.

Therefore the global subfamily `{C_j:j in J}` is already infeasible. The pair `(b*,J)` is the required witness. QED.

### Corollary 4.2 — independent composition law

If two already-certified interfaces are composed by independent Cartesian product, with certificate numbers `H_1` and `H_2`, then the combined interface has bound

`H_combined <= max(H_1,H_2)`.

If both local bounds are sharp and their sharp families can be lifted by leaving all other blocks unconstrained, then

`H_combined = max(H_1,H_2)`.

Thus independent dimensions do **not** accumulate certificate size.

### Theorem 4.3 — sharpness transfer

Suppose a block `b*` has exact local certificate number `h_{b*}=H`, witnessed by a minimally infeasible local family of size `H`.

Lift each local set in that family to a global rectangle by using the full set `X_b` on every `b != b*`.

The lifted global family is minimally infeasible of size `H`.

Hence the global certificate number is exactly `H`.

QED.

## 5. Minimal obstruction structure and extractor

### Proposition 5.1 — projection of minimal obstructions

Let `F={C_i:i in I}` be a globally minimally infeasible rectangular family: `F` is infeasible but every proper subfamily is feasible.

Then at least one block `b` has empty total local intersection, and for every such bad block the projected family

`{A_{i,b}:i in I}`

is itself minimally infeasible using all indices `I`.

### Proof

A bad block exists by product factorization. Fix one. If any constraint `i` could be removed while that block remained infeasible, then the corresponding global subfamily would remain infeasible, contradicting global minimality. QED.

### Witness extractor

Given represented constraints:

1. scan blocks for one whose local intersection is empty;
2. invoke that block's local witness extractor;
3. return `(block, original constraint indices)`.

The extractor never enumerates the global product state space.

For interval and Boolean-mask blocks below, extraction is explicit and linear-time in the represented constraints.

## 6. Exact h=2 Enterprise subclasses

### 6.1 Integer interval blocks

Let `X_b=N_0` or a finite integer chain. Let local admissible sets be integer intervals, including one-sided/full intervals when required.

A finite interval family is infeasible exactly when the largest lower bound exceeds the smallest upper bound. Choose one interval attaining each extremum. Those two intervals are disjoint.

Therefore

`h_interval = 2`.

The bound is sharp because two disjoint nonempty intervals form a two-constraint minimal obstruction.

### 6.2 Boolean support/literal blocks

Let `X_b={0,1}` and local admissible sets be

`{0}`, `{1}`, or `{0,1}`.

A finite family is infeasible exactly when it contains both a requirement for `0` and a requirement for `1`. Those two constraints are already infeasible.

Therefore

`h_boolean_literal = 2`,

and the bound is sharp.

### Corollary 6.3 — arbitrary-dimensional boxes and subcubes

Any finite Cartesian product of interval blocks, Boolean-literal blocks, or a mixture of them has exact global certificate number

`h = 2`

provided at least one nontrivial block admits a two-set conflict.

The dimension and number of constraints do not enter the certificate number.

This is the main high-leverage special case for Enterprise use.

## 7. Algorithmic consequence

Let there be `m` global constraints and `|B|` blocks.

### 7.1 Generic Helly-oracle use

If only a subfamily-feasibility oracle is available, a certificate number `H` reduces the validation target to subfamilies of size at most `H`, at most

`sum_{k=1..H} binom(m,k)`

checks.

For fixed `H` this is polynomial in `m`; for `H=2` it is quadratic instead of an unconstrained global state search.

### 7.2 Represented product use

When the block representation is available, the stronger algorithm is to aggregate local intersections directly.

- integer intervals: retain only the maximum lower bound and minimum upper bound per block;
- Boolean support masks: retain required literals per coordinate and detect the first opposite pair;
- generic certified block: call the block feasibility/witness procedure.

This avoids enumerating `product_b |X_b|` even when that state product is enormous.

The theorem's value is therefore not merely a brute-force finite bound: the certificate size is controlled by local structure and independent of total state count and number of independent blocks.

## 8. Exact negative boundary — relational propagation destroys uniform certificates

The max-law requires factorization after whatever bounded compilation the interface declares. Without a factorization or another separately proved structural theorem, bounded local arity is insufficient.

### Theorem 8.1 — unbounded minimal obstruction on a Boolean path

For every `n >= 2`, let the state be

`(x_1,...,x_n) in {0,1}^n`.

Use the `n+1` constraints

- `L : x_1=0`;
- `E_i : x_i=x_{i+1}` for `i=1,...,n-1`;
- `R : x_n=1`.

Then the full family is infeasible and is minimally infeasible. Consequently the unrestricted class containing these systems has no finite Helly certificate bound.

### Proof

All equalities force

`x_1=x_2=...=x_n`.

The endpoint constraints then require the common value to be both `0` and `1`, impossible.

Remove `L`: assign every variable `1`.

Remove `R`: assign every variable `0`.

Remove one equality `E_k`: assign

`x_1=...=x_k=0`

and

`x_{k+1}=...=x_n=1`.

Every remaining constraint is satisfied. Therefore deleting any one constraint restores feasibility, so the family is minimally infeasible of size `n+1`.

As `n` is arbitrary, no uniform finite bound exists. QED.

### Strength of the no-go

The counterexample uses only:

- Boolean domains;
- unary and binary constraints;
- a path interaction graph;
- no high-arity hidden local condition.

Thus none of the following alone restores a uniform certificate number:

`FINITE DOMAIN`, `BOUNDED ARITY`, `ACYCLIC INTERACTION`, or `TREEWIDTH 1`.

### Certified repair condition

A safe repair is:

> Compile every relationally coupled component into one declared superblock, and require a uniform local certificate bound for the resulting superblock class. Independent superblocks then compose by the max-law.

If coupled components can grow without a uniform local certificate theorem, the calculus intentionally returns `NO FINITE BOUND CERTIFIED`.

This is the exact boundary of the present tool interface. It does not claim that no other special relational class can possess its own Helly theorem; such a theorem would simply become a new certified local block class.

## 9. Carathéodory-like generator calculus on products

The failure-certificate theorem has a useful but different dual companion.

### Definition 9.1 — product hull

Suppose each block has a closure/hull operator `cl_b`. For `S subseteq X=product_b X_b`, define

`Hull(S) := product_b cl_b(pi_b(S))`.

### Theorem 9.2 — additive product generator bound

Assume block `b` has Carathéodory generator number `c_b`: whenever

`y_b in cl_b(T)`, 

there is `T' subseteq T` of size at most `c_b` with

`y_b in cl_b(T')`.

Then the product hull has generator number at most

`C <= sum_b c_b`.

### Proof

Let `y in Hull(S)`. For each block `b`, choose at most `c_b` source points from `S` whose `b`-coordinates generate `y_b`. Take the union of all chosen source points. Its size is at most `sum_b c_b`, and by monotonicity its projection generates every coordinate of `y`. QED.

### Proposition 9.3 — Boolean subcube Carathéodory number is exactly d

For `X={0,1}^d`, let `Hull(S)` be the smallest coordinatewise subcube containing `S`; equivalently, coordinate `j` may take exactly the values occurring in the `j`-projection of `S`.

Each coordinate block has `c_b=1`, so Theorem 9.2 gives `c<=d`.

For the lower bound, let

`x=0^d`

and for each `i=1,...,d` let `s_i` have `0` in coordinate `i` and `1` in every other coordinate.

Then `x in Hull({s_1,...,s_d})`, because every coordinate sees a zero somewhere. If `s_k` is removed, coordinate `k` is `1` in every remaining generator, so `x` leaves the hull.

Thus all `d` generators are necessary and

`c=d`.

This family simultaneously has Helly certificate number `h=2` for subcube constraints. Hence the Helly and Carathéodory numbers obey fundamentally different composition laws here:

`HELLY: max`,

`CARATHEODORY: sum (sharp in this example)`.

## 10. Radon-like relation

A Radon partition principle can imply Helly information in an abstract convexity structure, but it is not the engine of the Enterprise block calculus.

For the grid/face convexity consisting of intersections of axis-parallel affine subspaces, Pálvölgyi records a family with

`h=2`

while its Radon number grows with dimension (logarithmically in the cube/face parameterization).

Therefore:

1. a uniform Helly-2 certificate theorem does not require a uniform Radon bound;
2. Radon structure is a stronger optional invariant for this purpose;
3. a Radon-like theorem should not be postulated merely to justify product certificates already obtained by factorization.

Together with Proposition 9.3, the same product/subcube world exhibits three scales:

`h = 2`,

`r = dimension-dependent`,

`c = d`.

The operational conclusion is that Enterprise should keep three APIs distinct:

- failure certificate API (Helly-like);
- generator compression API (Carathéodory-like);
- partition collision API (Radon-like).

### Native source typing

The frozen native foundation defines the fixed sector

`S_12 = {(a,b,0): a,b in N_0}`

as one of the three glued two-axis positive charts.

This demonstration does **not** define cross-sector transition semantics and does not alter the current cross-sector metric/gluing open boundary.

### Constraint interface

A local chart/measurement/guard on a fixed `S_12` realization is admitted to this tool when it is separable as

`a in I_i`,

`b in J_i`,

where `I_i,J_i` are integer intervals and an omitted restriction means the whole coordinate chain.

The state space is `N_0 x N_0`; the two blocks are `a` and `b`.

By Section 6,

`h_chart = 2`.

Therefore pairwise compatibility of all such chart boxes is sufficient for a common fixed-sector native address.

### Positive example

Use

- `C1: a in [2,7], b in [1,6]`;
- `C2: a in [5,9], b in [0,4]`;
- `C3: a in [4,8], b in [3,9]`.

Their common coordinate ranges are

`a in [5,7]`,

`b in [3,4]`.

For example `(5,3,0)` is a common native address.

### Sharp failure example

Two guards

`a in [0,2]`

and

`a in [3,5]`

are already a two-constraint failure certificate, independent of all other coordinate guards.

### Scope boundary

A coupled condition such as a nonseparable relation between `a` and `b`, or a condition that switches among `S_12,S_23,S_31`, is not silently treated as two interval blocks. It must either:

1. receive an explicit local certificate theorem as a coupled block; or
2. remain outside this Helly-2 interface.

This prevents target leakage into unresolved chart-transition semantics.

## 12. Cross-domain demonstration B — typed Boolean-BRC support compatibility

### Native source typing

The current BRC bridge fixes canonical historical BRC as Boolean/result-support semantics on a component-typed transition skeleton, with richer path provenance/multiplicity living only in explicit enrichments.

This demonstration uses only a **declared compatibility layer over a Boolean support snapshot**. It does not attempt to invert Boolean BRC to recover discarded path multiplicity or provenance.

### State type

Let `U={u_1,...,u_d}` be a finite declared set of typed support atoms—for example typed terminal/relation events already distinguished by the component-labeled skeleton.

A candidate support profile is

`sigma: U -> {0,1}`.

Each support atom is one Boolean block.

A local compatibility requirement may independently say:

- `sigma(u)=1` (must be supported);
- `sigma(u)=0` (must be absent);
- no restriction on `u`.

Thus every requirement is a Boolean subcube.

### Certificate theorem

By Section 6,

`h_typed_support = 2`.

A global support-profile incompatibility always has a two-requirement witness: the same typed support atom is required both present and absent.

### Example

For three typed atoms `(u12,u23,u31)`, take

- `R1: u12=1, u31=0`;
- `R2: u23=1`;
- `R3: u12=1`.

A common support mask is

`(1,1,0)`.

Adding

`R4: u31=1`

creates a two-constraint obstruction `{R1,R4}`.

### Why this is genuinely a second domain

The first demonstration solves common realization in an integer native coordinate chart. This one solves consistency of typed Boolean result-support assertions. Their state sets, admissible local predicates, and witness meanings differ; the shared engine is only the block finite-certificate API.

The BRC typing rule remains essential: if semantically distinct events are erased into one unlabeled atom, the constraint language itself has already lost the distinction and no certificate theorem can recover it.

## 13. Historical comparison and conservative novelty statement

### Historical comparison

The report's mathematics is intentionally placed inside established Helly/Radon/Carathéodory and abstract-convexity traditions rather than presented as a new classical theorem.

Relevant prior mechanisms include:

- classical Helly/Radon/Carathéodory local-to-global and generation theorems;
- abstract convexity spaces and the relation `finite Radon -> h<r`;
- discrete/lattice convexity work studying exact Carathéodory, Helly, and Radon invariants;
- the well-known strong Helly behavior of axis-parallel/product-like families;

The Enterprise-specific contribution of this task is the following integrated tool package:

1. a geometry-free Enterprise constraint interface;

## 15. TOOL API

### Tool name

`ENTERPRISE_BLOCK_FINITE_CERTIFICATE_CALCULUS`

### Constraint input

A declaration

`(B, X_b, A_b, constraints C_i)`

where:

- `B` is a finite block set;
- `X_b` is each block's nonempty state space;
- `A_b` is its certified local admissible-set class;
- each global constraint is rectangular: `C_i=product_b A_{i,b}`;
- every local class exposes a finite certificate bound `h_b` and, when possible, a witness extractor.

### Global feasibility

`FEASIBLE(F) iff intersection_{C in F} C != empty`.

### Certificate output

On failure:

`(bad_block b, original_constraint_indices J)`

such that

`|J| <= h_b`

and those constraints already conflict in block `b`.

### Bound

`H = max_b h_b`.

For interval/Boolean-literal blocks:

`H=2`.

### Witness extractor

`find bad block -> run local extractor -> lift local indices unchanged`.

### Composition behavior

Independent product composition:

`H(product of interfaces) = max(local H)`

when the local sharpness witnesses are available; always `<= max(local H)` under the hypotheses.

Relational coupling:

`COUPLED BLOCKS -> COMPILE AS SUPERBLOCK OR REQUIRE NEW LOCAL THEOREM`.

### Success construction

Choose one state from each nonempty local total intersection and assemble the product realization.

### Failure modes

The tool returns no uniform bound when any of the following occurs without a separate theorem:

1. a local block class has `h_b=infinity` or unknown `h_b`;
2. a global constraint is not rectangular in the declared decomposition;
3. relational coupling propagates across unboundedly many blocks and is not compiled/certified;
4. semantic typing has already erased distinctions required by the problem;
5. problem size is hidden inside one alleged “local” constraint without a uniform local certificate theorem.

### Diagnostic boundary witness

For suspected unbounded coupling, test whether the class can encode the Boolean endpoint/equality path family of Section 8. If yes for arbitrary path length, a uniform Helly bound is impossible.
