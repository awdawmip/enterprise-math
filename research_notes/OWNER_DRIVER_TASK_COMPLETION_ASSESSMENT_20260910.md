## Interface

An ACCEPTED Driver can explicitly assess completion in one typed JSON comment
inside the review report. The report is already bound by the immutable DR's
path, Git blob, SHA-256 and derived identity. The new predicate verifies these
pins, the unchanged raw Result digest and exact task/publication/Driver fields.
It does not infer satisfaction from the Result's prose. No Result, taskbook,
global compatibility alias or replacement record is changed.

The first-review command now supplies its genuine validated review candidate
to follow-up preflight before creating any DR. The previous placeholder could
not carry real report/Result pins; the first local prototype exposed that
boundary and was corrected before publication. Later materialization and
packet replay use the same report check. Existing packet bindings suffice;
there is no new registry or substitute review authority.

Current publication, ACCEPTED review, PASS/SUCCESS Result, TASK terminal scope,
all six follow-up gates, active Driver authority, exact-set review semantics,
byte-checked transactions and the open parent boundary remain required.
Explicit partial/incomplete/negative target values cannot be converted by an
assessment. Synthetic reviews cannot use this added report route. Duplicate
blocks or JSON keys, stale identities/digests and changed report bytes refuse
closure. Existing literal-SATISFIED and named-success compatibility behavior
remain available under their own checks.
