**原始源状态 → 整数行列式 T → 商与余数 z → 最远圆弧距离 D(z) 和唯一胜出标签。**

## 新成果二：完整观察链的 CPU 测量

平台：CPython 3.13.5 / Linux 6.18.57 x86_64。每种实现进行5轮顺序计时，方法顺序逐轮轮转，在定时区间关闭垃圾回收。全部基于已经准备好的相同冻结原始状态；定时区间包含逐状态的行列式、商/余数、最远距离及标签计算。原始输入列表准备、弧生成、事件包络预处理及额外索引表示构造单独计时。

| 实现 | 余数路线 | 距离路线 | 65,536 状态中位数 |
| --- | --- | --- | ---: |
| direct64 | 原状态元组、T % P | 逐点检查64弧 | **910.081 ms** |
| div_env | 原状态元组、T % P | 事件包络 | **145.069 ms** |
| table_env | 六位商表及T阈值 | 事件包络 | **187.583 ms** |
| shift_T_env | R284DZ七位移位及T阈值 | 事件包络 | **207.864 ms** |
| shift_bits_env | 七位移位及R284EA九位阈值 | 事件包络 | **211.193 ms** |
| div_packed_env | 同时准备原始位序整数，T % P | 事件包络 | **140.222 ms** |
| table_packed_T_env | 位掩码取六位商表及T阈值 | 事件包络 | **149.104 ms** |

一次性准备阶段样本：原状态元组创建95.838 ms，64弧创建0.240 ms，R284DS包络创建0.681 ms，额外位序整数索引构造49.026 ms。它们未混入上表主循环中位数，且只是单次样本。其他环境、批次长度、内存布局、指令实现和冷/热缓存状态尚未核验。

## 数学与工程解释

1. R284EC 证明的最优期望查询次数 33623/16384，目标函数是读取原始源比特的次数，每次读取等成本，且算术和分支免费。这不是处理器总时间。实际原始位可以已装入整数或元组；本轮看到不同成本模型确实给出不同优化选择。
2. R284DZ 的七位公式和其受限电路类别内最优性依旧精确成立。此处测得它并未击败 CPython 内建大整数模运算。该结果是**受控实现比较**，不是对七位公式的数学反例，也不是对其它硬件实现的不可能性断言。
3. R284DS 的193区间带标签观察器在全部冻结状态上完全等于直接64弧，且真实运行存在显著成本下降。对本次全域批次而言，0.681 ms 预处理远小于省下的逐状态多弧代价。
4. 当前数据为独立算术执行与观测链的公平对照，并不涵盖全部四读联合观察、轨道键生成、逆恢复、索引存储与多次翻转更新，因此尚不能宣称全应用端到端最优。
