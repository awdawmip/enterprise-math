## 实现的三种策略

| 策略 | 空缺判断 | 请求变化后的处理 |
|---|---|---|
| `fresh` | 每次源允许创建时重新取得父通用集合 | 下次重新读请求 |
| `holes` | 保留 H，实际命中当前目标就使用 | 绑定后去掉新键余数，目标未命中时重采 |
| `prefixes` | 同样保留 H，同时保留已观察低位前缀 | 重采时直接复用缓存，只有未知位发起原8步读取 |

`prefixes` 为初始每槽建立一个未知标签。复制将目的槽指向源标签；父复制原程序已读完整键时，顺便补齐此标签的低位信息。绑定使用父程序实际返回的键建立已知低位标签；删除将槽置为已知空0。失去所有槽引用的标签可回收，始终最多 r 个活跃标签。

动态 H 的安全性排除**非空**请求。采集算法仍将空槽0保守计入 r 个阻挡者，以直接复用父配额树。`drop` 引入空0不影响已有 H 的业务安全性。

设低位宽 b。每次新增缺席查询都令某个初始未知标签的前缀长度增长1；已知绑定、复制、删除不制造新的未知标签。因此一个稳定持有区间内，包含初次采集的新增缺席查询总数至多 r·b。当前实现继续原样支付复制、绑定、valid、execute 等业务程序自带的键读取，JSON 将它们单列为 `business_key_bit_reads`，所有原命令均计入 `commands`。

控制器长期保留 r 个槽标签指针、最多 r 个低位前缀及 H；所需数据量为 O(r(b+log r)) 位。父搜索的临时分组继续按槽计数。输出中的原命令列表、逐步日志及测试准备是验证材料，不是保留全部旧身份的运行决策表。

## 实际保护接线

`protected` 模式使用父 `BatchRing` 的实际进入、相位读出、结果发布及双端口交接。新增 `mixed` 控制状态将整个混合操作序列放在同一真实持有区间内，返回时丢弃证据。

两个门相位均实际执行13个混合动作：核心461条，保护包裹31条，共492条。每个相位的全部462个原命令边界，分别插入一次完整对手 bind 进入尝试；对手均得到 busy，核心关系保持不变。实际交接后，对手的73条 bind 操作成功。全终态核对源、请求、两类身份键、门状态、私有答案及临时关系清理。

这覆盖逐边界完整进入尝试及真实交接。上轮全原语交错图保留其原覆盖；本轮没有把这些边界探测计作新的全交错穷举。

## 返回值接线与实际反例

搜索命中的缓存位不会写物理答案寄存器，所以创建后的答案修正根据最后一次**实际**布尔读出。

已执行反例：初始请求键 `(0,18,9,20,10,8)`，源为空；两轮 `reserve A / bind槽0 / release A` 后再次创建 A。最后实际读取为0，之后消费的最后缓存位为1。正确36条程序创建键3并返回 true；故意省去4条答案修正，32条程序创建同一键却返回 false。该反例及全缓存命中情况均保存在 `regressions.json`。

首次验证中有一条测试断言把 H 安全性扩大为“连空0也必须排除”，因此在 drop 准备失败。该断言已按非空请求定义修正；生产更新规则没有用这一错误断言选择编号。
