## 类轨道最小值剪枝为什么保解

`front_orbit_min.cpp` 仅修改前驱已验证 `front_orbits.cpp` 的根部规范化。设 G 保持当前已占据点的并集，选定剩余类数最少的类型。在任意可行覆盖里，对这个类型的每个选中类取它的 G 轨道最小掩码，再取这些最小掩码的最小者 m。将实现 m 的类用某个 G 元素移至 m。

变换后，其他同类型选中类仍有轨道最小值至少 m；又因类互不相同，其实际掩码严格大于 m。因此只保留

`actual_mask > m && orbit_minimum >= m`

必保留每个可行覆盖轨道的至少一个代表。第二个不等式必须是“大于等于”：不同不交类可以处于同一类轨道。

`orbit_min.diff` 固定实际三处变更。`validate_orbit_min.cpp` 在 19 个合法二核心帧上检查 1,547 组不交类选择，特别保留了 13 个同轨道不交对；17 个帧有非平凡稳定子，另一个非平凡帧的指定类型候选池为空。`orbit_min_control_replayed.json` 为另一工作分支重新执行该控制程序所得相同结果。控制例支持实现检查；一般保解依据上一段证明，不依赖抽样。这里没有宣称正式独立 Review。

`front_orbit_frames.cpp` 在带见证出口的同一整数引擎上，仅增加固定余集编号和逐帧终局记录。证明未使用实验性位集引擎，也未使用浮点 LP 不可行状态。

## 复算入口

需要 Python 3 标准库及支持 C++20、128 位无符号整数和 POPCNT 的编译器。证明验证不需要优化器。

快速检查完整谱覆盖、所有回执和 9 帧的仿射传送（不宣称重新执行覆盖搜索）：

```text
python3 replay_bundle.py --previous ../previous --mode audit
```

重新生成原菜单类库并实际重跑整个 9,861 层：

```text
python3 replay_bundle.py --previous ../previous --mode full --jobs 2
```

完整搜索的候选顺序和所选引擎会影响节点数；应核对完整谱覆盖及所有终局无解，而非强制重跑节点数等于保存值。

单独重跑最后一个分型的 5 个余集代表：

```text
python3 replay.py --previous ../previous --work work --first 9861 --last 9870 --cores 0,1,2 --engine orbit-min --prepare-only
c++ -std=c++20 -O3 -mpopcnt front_orbit_frames.cpp -o work/front_orbit_frames
python3 run_mixed_frames.py --frames 0,1,3,5,8 --receipts fresh_frame_receipts
python3 audit_mixed_frames.py --receipts fresh_frame_receipts
```

`fresh_frame_receipts` 须为新的空目录；该逐帧入口只复用显式指定目录中已有的终局。完整入口 `--mode full` 默认使用新建工作目录，不复用保存回执。
