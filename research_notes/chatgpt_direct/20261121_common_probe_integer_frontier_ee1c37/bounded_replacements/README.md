# 9,996 次构造的全类联动替换与精确费用势

2026-11-21；沿用原共同晚选变换、125 个历史及全体至多一次原端点补读。`initial.txt` 是已完整验证的十二标签表，费用 9,996，类大小为两个 13、一个 9、九个 10。

## 四段替换范围的完整排除

给每个新类与一个同大小旧类建立一一对应，记

\[
r_i=|C_i^{\mathrm{old}}\setminus C_i^{\mathrm{new}}|
    =|C_i^{\mathrm{new}}\setminus C_i^{\mathrm{old}}|.
\]

允许十二个类同时改变。在所有对应类均满足 \(r_i\le4\) 的范围内，没有费用小于 9,996 的合法整表。对应可遍历所有同大小类的匹配；标签名称不参与费用或结论。

检查器按每个旧类删除的点集、从其外部加入的等量点集完整枚举。加入过程用原 250 个菜单导出的 47,000 个禁三元组判定合法，终端按原二点观测位集计费。新类的安全价格上限来自

\[
c(C_i)\le9995-\sum_{j\ne i}m_{|C_j|},
\]

其中单类最小费用 \(m_s\) 沿用完整原生目录。原大小组成的这些最小费用合计为 9,845。每个保留下来的候选携带旧类下标；覆盖搜索同时要求每个下标选一次、每个历史覆盖一次。它没有把候选间重叠当作可行分区。

| 每类最多替换的历史数 | 价格筛选前合法候选数 | 完成搜索节点 | 严格改善整表 |
|---:|---:|---:|---:|
| 2 | 657 | 90 | 0 |
| 3 | 6,722 | 2,933 | 0 |
| 4 | 67,177 | 285,939 | 0 |

`verify.py` 从原菜单独立重建观察文件，重新编译并完整重跑四段替换范围。它还运行费用势变体，得到相同排除；预算恢复到 9,996 后找回原表，全部十二类再由直接菜单分组计费检查。

此前全部六类区域重分割的结论允许新类改变大小：严格改善至少使七个旧类完整点集消失。本页四段结论保持对应大小，约束的是每个对应类的成员变化数。这两种限制各有明确量词。

## 固定原两个十三点类时的全类型费用势

固定原表两个十三点类，剩余 99 个历史由一个九点类与九个十点类覆盖。`point_dual.json` 给每个剩余历史整数权重 \(w_x\in\{187,190,193,196\}\)，并给每个自由类权重 \(b=-1180\)。对任意合法九点或十点类 \(C\) 都有

\[
c(C)\ge\sum_{x\in C}w_x+b.
\]

为验证其全域性，只需检查九点类费用不高于 \(9\times196-1180=584\)、十点类费用不高于 \(10\times196-1180=780\) 的完整目录；更贵类由最大点权界自动满足。完整 1,495,322 行原生种子确认所需费用类型，完整银行中与固定核心不交的 **20,134** 个相关类全部直接原生核查，整数松弛均非负。

把十个类的不等式相加，点权各出现一次，得到

\[
c(T)\ge2592+\sum_{x\in U}w_x+10b
       =\boxed{9872}.
\]

这个精确证书覆盖上述固定核心及大小组成的全部合法类，已经越过发现阶段的 624/788 列费用上限。更普遍的母类对边际证明见本轮 `marginal_bound/`。

以此势函数把每个候选价格替换为非负整数

\[
\bar c(C)=c(C)-\sum_{x\in C}w_x-b
\]

后，原 9,995 预算等价于剩余预算 123。四段范围由 285,939 个搜索节点降为 151,680；候选生成与原菜单费用计算相同。这是该输入上的搜索节点比较，未将前处理或证书发现成本隐藏在通用加速保证中。

## 五段范围的补充整数证书

五段范围的完整候选生成得到 522,700 个价格筛选前合法候选。两个十三点类均只有原类可选；去掉与它们相交的候选后，剩余 **74,582** 个带对应下标的九点／十点候选。

`color_dual.json` 是分母 100 的整数点权和对应类权证书。对每个候选 \(C\) 及其旧类下标 \(i\)，精确核对

\[
100c(C)\ge\sum_{x\in C}a_x+b_i.
\]

实际逐列最小整数松弛为 3；十个自由类权及全部 99 个点权相加，再加两个固定核心，给出的全表下界分子为 989,537。因此五段范围内的整数费用至少为 **9,896**。费用超过生成预算 9,995 的表自动满足此下界。这个证书用于进一步加速五段范围的整数覆盖搜索；完整五段排除仅在相应终局实际完成后另行报告。

## 可移植复验

先通过相邻 `lower/replay.py --prepare-only` 按它的说明重建原银行和种子。然后从总包根目录运行：

```sh
python3 -B bounded_replacements/verify.py \
  --previous previous --bank /tmp/lower-work/bank \
  --seeds /tmp/lower-work/seeds --work /tmp/replacement-check --radius 4

python3 -B bounded_replacements/verify_color.py \
  --work /tmp/replacement-color-check
```

前一个命令检查原菜单、全类型整数势、完整四段覆盖排除及可行正控制。后一个命令重新生成五段的全部带对应下标候选，并以 Python 整数逐项核对分母 100 的证书，不需要 LP 求解器。发现阶段使用的浮点目标值不承担最终真假判定。

程序需要 Python 3 标准库及支持 C++20、POPCNT 和 128 位无符号整数的编译器。完成回执与源码指纹在 `verification_r4/result.json`、`verification_color/result.json`。本页保留实际完成范围；正式独立 Review 状态为 `NOT_REVIEWED`。
