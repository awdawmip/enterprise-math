# 十二标签下一段整数成本排除

本目录接续第七轮完整复验包 `previous`。模型与该包相同：125 段旧历史、125 个菜单、两种共同晚选变换，总计 31,250 个等权输入。核心指成本 1,104 的中心删点十二点类或成本 1,296 的完整十三点类；成本 1,116 的十二点类不计作核心。

## 已完成的全域成本层

`certified_result.json` 与 `certificates/complete_costs.jsonl` 固定已完整结束的成本层，不把部分完成的后续层算入全域下界。截至该回执，9,855、9,856、9,857、9,858 的零、一、二核心谱分别有 59、72、70、90 个，共291个，全部排除。此前的三、四核心证明覆盖到 9,860，至少五核心证明覆盖到 9,995，因此这些新排除合起来给出 **R12 >= 9,859**。这291个谱共访问18,784,325个几何节点及1,415,456,601个精确覆盖节点。

候选类与类型谱均从原菜单重建。单类大小与成本上限先由其余类的最低成本得到；原完整枚举的各大小成本上限覆盖当前范围。十三点合法类的完整分类已知仅有成本 1,296 的母类。含至少七个低成本大类（核心或成本 1,116 的十二点类）的十二标签表此前已证至少读 10,147，故在本目录预算内可以排除。

每个成本谱记录所有消息类的大小、成本和个数，大小和为125、标签数为12。先按已证仿射轨道列举互不相交的核心，再选择哪些中心填回。中心逐个检查，只允许尚在余集中的中心填回；同一个中心不能填回两次。单删十二类可以固定一个或两个锚点。余下精确覆盖按最少候选的类型或未覆盖历史分支，并以各坐标五个取值纤维的人数作精确必要条件。这里的坐标仅编码有限历史状态。`front.cpp`、两个人数头文件和 `genprof.cpp` 延用前轮已验证的算法。

完整重跑已结束的全域层：

```text
python3 -B replay.py --previous /path/to/ROUND7 --first 9855 --last 9858 --cores 0,1,2 --jobs 2
```

可加 `--cost 9855` 等参数只重跑指定层。默认使用新建临时目录并实际重新计算所有请求的谱；只有显式给 `--work /path/to/checkpoint` 时才会保留生成的候选库并复用已完成谱。

## 四核心分层继续到9870

`four_result.json` 与 `certificates/four_complete.jsonl` 另固定恰四核心的 9,861 至 9,870 层。十层谱数依次为350、379、431、447、508、525、594、649、682、753，合计5,318个。2,087,761个几何节点、5,533,016个精确覆盖节点全部无解。因此，结合前轮9,860以内的结果，**恰四核心的十二标签表至少读9,871次**。

```text
python3 -B replay.py --previous /path/to/ROUND7 --first 9861 --last 9870 --cores 4 --jobs 1
```

这个分层结论本身不会把一般十二标签下界升为9,871，因为零、一、二核心仍须单独处理。

## 稳定群归一化的可选实现

`front_orbits.cpp` 在无额外单删锚的固定一、二核心余集中，还使用保持余集不变的全部菜单成本仿射对称。选取一个剩余类型，在其类族全部群像中取最小掩码作为锚，并要求同类型其余掩码更大。任一覆盖都能被群元素移到这种形式，所以该归一化不丢掉解。其余部分仍用同一精确覆盖。

`orbit_example.json` 保存已结束谱的一次对照：9点557成本三类、10点744成本三类、11点936成本四类、12点1104成本两类。普通覆盖排除需要96,837,613节点，归一化覆盖需要41,931,304节点，均检查同六个核心余集并返回无解。这个比较仅是该实例的搜索节点数，不是通用复杂度或端到端耗时结论。可用 `--engine orbits` 选择该实现。

## 接续范围

持久工作目录中的 `completed.jsonl` 是逐谱运行回执，`running*.json` 是未完成计算的定位资料。它们不把正在运行的分支记为排除。`work` 覆盖零至二核心的9,855至9,860共482个谱。后续成本尚未全结束时，应以 `certified_result.json` 的完整成本层及各分层独立回执为准。

零、一核心分层已经另外全部完成：`zero_one_result.json` 与 `certificates/zero_one_complete.jsonl` 固定9,855至9,860的93个谱，逐层为11、13、12、19、12、26个。23,333,080个几何节点、210,216,733个精确覆盖节点均无解。结合此前至少三核心的9,860以内排除，**任何总读数至多9,860的十二标签候选现在必须恰含两个核心**。这仍未证明二核心候选存在。

```text
python3 -B replay.py --previous /path/to/ROUND7 --first 9855 --last 9860 --cores 0,1 --jobs 1
```

生成的45MB候选种子、二进制候选库与本机可执行文件只作计算缓存，无须随复验包发布；上述命令能从前轮原始依赖重建。`experiments` 内斜向投影尝试未形成已证新结果，不支撑这里的下界。

## 一个已精确核对的线性松弛障碍

费用谱 `9-557-2_10-744-5_11-936-2_11-944-1_12-1104-2` 的总成本为9,858。固定两个中心删点核心后，有六个互不等价的101点余集。`type_integer_result.json` 记录全部六个余集的纯整数精确覆盖无解，共14,838,470节点。

其中五个余集仍存在严格的有理分数覆盖：各104个合法类取正有理权重，余集的每个点权重和恰为1，各类类型的总权重恰为其要求的整数个数。连同两个固定核心，总类权重为12、总成本恰为9,858。`fractional_covers.json` 给出全部有理分子和分母；有的分母较大，故不以小数近似替代它们。`verify_fractional.py` 从原菜单重建合法性与费用，逐一检查508个不同合法类，再用分数算术核对所有点与类型等式，完全不需要优化器。

因此，在这五个具体分支中，仅靠点覆盖等式、类型个数等式和非负性所得的线性规划松弛不能排除该费用谱；整数分割约束确实提供额外信息。这不是对所有线性割或其他松弛方式的不可能性结论。

```text
python3 -B verify_fractional.py --previous /path/to/ROUND7
python3 -B replay.py --previous /path/to/ROUND7 --first 9858 --last 9858 --cores 2 --profile 9-557-2_10-744-5_11-936-2_11-944-1_12-1104-2 --jobs 1
```

`type_separator.py` 与 `fractional_witness.py` 是发现这些权重的辅助程序，使用SciPy和SymPy；浮点优化只提出候选，保存的结论均经整数或有理数复核。发现程序的浮点状态本身不构成排除证据。
