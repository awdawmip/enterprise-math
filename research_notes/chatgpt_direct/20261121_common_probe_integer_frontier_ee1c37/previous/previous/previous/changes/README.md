# 两档最优表之间至少要换多少个完整旧类

从 m 个标签变为 m+1 个标签，允许对所有标签重新编号。按实际历史点集计算保留下来的完整旧类，原有 m 类扣除这项重合数就是更换数。我们在两边都达到其全域最低读数的表对中，寻找最小更换数。这里可独立选取每一对相邻预算的代表。

已知每个 m≥21 都能达到单类最低成本给出的整数分配下界。复验器枚举能在取等分配中出现的类大小，唯一可能的类大小分布为均衡分配。令 A_s、B_s 分别是两档最优表的 s 点类数。任意表对至少需要更换 Σ_s max(A_s−B_s,0) 个旧类。对 21 至 24 的四个起点，原有构造每次正好用六个五点类替换五个六点类。对 25 至 62，每档在 replacements.json 中列出选用旧证书的哪一张表、要移除的类编号和新类上的全部历史。对 63 至 124，从已知最优表挑一个二点类拆成两个单点。程序逐对核验两张表恰盖 125 点、合法性、两个读数均取到全域最优，以及实际更换数等于整数下界。

| 原标签数 m | 最少更换的完整旧类 |
|---|---:|
| 21–24 | 5 |
| 25–30 | 4 |
| 31 | 2 |
| 32–40 | 3 |
| 41–61 | 2 |
| 62–124 | 1 |

此外，从任意一张合适的 62 标签最优表出发，可以沿同一条嵌套链一直到 125 标签。该表由 61 个最省二点类和一个最省三点类组成。附带的 62 档拆分保持最优，得到的 63 标签表恰含一个单点和 62 个最低成本二点类。此后只须依次拆分剩余二点类。
