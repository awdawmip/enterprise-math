# 十二标签补读数的全域下界

在前一版下界 9,847 之上，逐层排除 result.json 列出的整数读数。一个成本谱记录十二个消息类各自的大小和补读数，其大小之和必须等于 125。由本轮 twelve_cores 的三核心分层与前版的七大类结论，9,860 以内只需检查零、一、二或四个核心且至多六个低成本大类的成本谱。核心为成本 1,104 的中心删点十二类或成本 1,296 的完整十三点类；低成本大类还包括成本 1,116 的其余单删十二类。

复验器从 125 个菜单和两种共同变换重建二点歧义和禁三元组，枚举每个大小在单类预算内的全部候选。程序先选择互不相交的核心位置，再放回需要的中心。可固定单删十二类时，在相应的仿射稳定群下固定一个或两个代表，再列尽其余单删类；零核心且零单删时可以先固定某类的仿射轨道代表。对剩余点集做精确覆盖，按稀少的类型或点分支。

每个坐标的五个平行平面上，余集的五个人数必须等于剩余各类平面人数逐项加和。front.cpp 同时核对三个方向：枚举每类所允许的方向排列，并用整数动态规划判断五个平面的有序计数能否相加得到目标。将五个人数同时减去同一个整数不改变差值，且余集总点数已由谱固定，所以可以用排序后与最小值的四个差来编码。支撑结论只需每个谱均检查完且无解，搜索分支顺序不影响证明。

从本目录运行 `python3 -B replay.py --previous /path/to/ROUND6 --jobs 3`。另加 --four-cores 会单独核对 9,847 至 9,860 范围内恰含四核心的全部成本谱，计数见 four_core_result.json。结合恰三核心、至少五核心两份整数权证，任何含至少三个核心的十二标签表都至少需要 9,861 次补读。需要 Python 3 与支持 C++20 的编译器。各层谱数、全部谱的 SHA-256 及通用下界收录在 result.json 内。
