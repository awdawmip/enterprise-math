# 四纤维联合奇偶割与新的精确分数覆盖

2026-11-21。本增量沿用原共同晚选变换、125段旧历史、31,250个等权输入及原合法类定义。三坐标是原生菜单程序的有限历史读出编码，心跳世界 X6 的原有桥接与观察范围保持不变。正式独立 Review：`NOT_REVIEWED`。

## 一条55点奇数集割不被前一联合系统蕴含

固定前驱费用谱

\[
(9,557)^2(10,744)^5(11,936)^2(11,944)(12,1104)^2,
\]

及前驱第2框架的两个十二点核心。自由历史集为 F，共101点。令

\[
V=F\cap\bigl([x_0\ne4]\mathbin{\mathrm{XOR}}[x_1=4]
                  \mathbin{\mathrm{XOR}}[x_2\in\{1,4\}]\bigr).
\]

直接计数得 \(|V|=55\)。任何整数分区都满足

\[
\boxed{\sum_C (|C\cap V|\bmod2)x_C\ge1.}
\]

证明：整数分区在 V 内的占用数之和为奇数55，至少一个被选类占用奇数点。

前驱最终312支持点 `integer_cuts/all_joint_exact/cover_2.json` 已满足完整星团相容、全部单线性形式模2/3/4/5、双坐标加法模3和至多三个仿射纤维/单点XOR。它在此割的精确左端却为

\[
\frac{112938537080637033207601500431880235243}
     {146892661307821883249929206807463679241}
=0.768850779\ldots<1.
\]

因此这些已声明的联合约束并不蕴含这条55点奇数集割。

等价的规范化形式取四纤维
\(U=F\cap([x_0=4]\oplus[x_1=4]\oplus[x_2=1]\oplus[x_2=4])\)，
\(|U|=46\)，类型位按四个自由类型取 `(1,0,1,1)`。它们恰为类大小的奇偶，所以系数等于 \(|C\cap(F\setminus U)|\bmod2\)，即上述 V 割。

## 完整三坐标Boolean函数族

分别任取三个函数 \(f_i:\mathbf F_5\to\mathbf F_2\)，令
\(\lambda(x)=f_0(x_0)+f_1(x_1)+f_2(x_2)\)，并任取四个类型位 \(a_t\)。只保留

\[
r=\sum_{x\in F}\lambda(x)+\sum_ta_tn_t=1\pmod2,
\quad(n_0,n_1,n_2,n_3)=(2,5,2,1).
\]

对应割为
\(\sum_C[\sum_{x\in C}\lambda(x)+a_{t(C)}]_2x_C\ge1\)。
这就是每个原坐标任取取值子集后作XOR，再允许类型奇偶位。

可把每个 \(f_i(0)\) 归零：减去常数仅给每个类增加其大小乘该常数，可由类型位吸收。于是共有 \(2^{12}\) 个规范化点函数和每点函数8组右端奇数的类型位，即 **32,768个索引割**。这不是不同几何割的去重计数。

`separate_coordinate_parity.py` 用精确公共分母枚举完整家族。前驱588支持第1框架全部通过；前驱312支持第2框架恰有一个规范化索引割违反，即上面的四纤维割。

## 加入以后，全候选松弛仍有精确解

在第2框架的全部 **8,538个候选类** 上加入新割的完整框架稳定子轨道，再复用旧模数、星团和XOR分离，得到新的304支持有理点。`cover_2.json` 给出完整权重，公共分母为129位。

精确验证得到：

- 306个正权原生合法类，包括两个单位权重核心；
- 全部逐点覆盖等式、四类精确重数、总标签权重12、总费用9858；
- 27,676条内部星团不等式；零权锚类与固定核心情况自动满足；
- 12,413,656个原模数/双坐标索引成员；
- 22,371,336个至多三特征XOR索引成员；
- 新的32,768个三坐标Boolean函数/类型索引割。

上述55点割在新点恰好取等。新点的全部检查均以整数或有理数完成。LP只用于发现候选权重；最终存在性由完整显式权重及直接校验给出。这个结果把“分离旧点”和“排除完整松弛”准确区分：前者成立，加入新家族后的该框架仍有分数覆盖。

## 文件与复验

`cover_2.json` 是新304支持正例。`checks/` 是原实际整数验证回执。`discovery/` 保存完整候选LP的约束清单、两轮历史、原浮点顶点与精确恢复顶点，保留发现过程而不把浮点状态作为定理依据。

在组合包根目录运行：

```bash
python joint4/replay.py --integer-cuts integer_cuts --previous previous --work /tmp/joint4-audit --mode audit
python joint4/replay.py --integer-cuts integer_cuts --previous previous --work /tmp/joint4-full --mode full
```

`audit` 核对固定文件与前驱依赖、重算短55点分离，并消费已保存的完整验证回执。`full` 还重算新点的原生菜单、覆盖/类型、完整星团、全部原模数族、三特征XOR和新增32,768族。输出仅写入指定 `--work`。依赖为Python、NumPy及C++20编译器；证书验证不调用优化器。

本包的构造与分离属于作者研究及同团队交叉检查，正式独立 Review 保持 `NOT_REVIEWED`。十二标签的整数最优值由其他整表证明继续推进，本分数点不承担整数编码表的角色。
