# 旧消息经过一次真实的原核改写后是否仍有效？

## 写者改变的是物理请求表

沿用十五槽五环程序：世界 h∈{0,1,2,3,4}，五个顶点槽分别表示 h 等于哪一个顶点，五个边槽表示 h 落在哪两条边上。先用真实删除所回传的三个原守卫位准备表，并把 h 对应的摘要留给后来者。其间一个写者不知道当初的测试器准备；由五次非改写的原槽位读取得顶点指标，独立确定旧世界。它按外部选定的公开映射 F 把表改成 F(h) 的五环表：

1. 原位读五个顶点，共 **40** 条；
2. 原删除十个标记并独立检查全部槽已空，共 **150** 条；
3. 对 j=1…10 逐项查源、创建新 A 实例并绑定完整键 j；若新世界需此标记，绑定到它的专用槽，否则绑定到废料槽。每项释放源并删除废料槽，共 **1,032** 条。每一项均核验实际键与新鲜性，普通绑定选择没有额外探查。十个不同身份各用一次，旧请求已清空、此前保存的新标记也不会与 j 冲突。

因此每次改写恒为 **1,222** 条；与原来相同的准备 2,346 条合计 **3,568**。原程序每步实际检查源/请求、共享身份、私有答复与临时清理；改写后的完整物理请求表逐槽等于 F(h) 的规定编码。读写费用在总命令中足额纳入；“后续补读”为后续服务者因旧消息不足而额外支付的查询，不包含写者的五次收费。F 会向后续服务者公开，写者看到的五份原答复、日志、路由地址与中间状态不传给它。

边菜单 e=(u,v) 随后公布。服务者按既有程序强制复制边标记并清除工作槽，决定第一项；监听原绑定返回的完整键。若首项返回 11，真实后继要求区分当前为 u 或 v，使用旧摘要检查两者的逆像颜色；若仍同色，只补读新表中顶点 u 的区分位，然后交付 11 或 u+1。若首项返回边键，真实后继是固定 12，无补读。整个菜单任务实际创建两次。

## 保持与破坏的正反操作

固定旧颜色 c=(0,1,0,1,2)。当 F 是恒等、平移 +1、反射 x↦−x（模5）时，新边的两个端点逆像仍为旧环一条边，必异色。故三种实际改写下各自 5 个旧历史、5 个菜单全部免补读；同一颜色继续支撑服务，尽管原物理请求已清空并重建。后端使用 c(F⁻¹(x))，允许标签变化而不修改或扩增原消息。

若允许 F=x 或 2x（模5），而须在选择 F 之前写入摘要，则全体可能的冲突对是新边在两种映射下的全部逆像：恒等给出五条边，倍乘的逆像给出五条对角线。这十对恰为五顶点完全图。任何两个旧历史若共享消息，将有一项能选的 F 和一条边使它们首项交付相同而次项不同；即便到服务时 F 已经公开也不能免补读。零补读精确需要五个消息。若编码时就知道选定哪个 F，可改存 c(F(h))，三消息足够；此对照由可逆性和原环三染色推出。

具体见证：原历史 0 与 2 留下同一条旧摘要 0；经倍乘产生新世界 0 与 4。对已公布的边 (4,0)，强制复制两次都读到相同边键，实际首项都是 11；新表的顶点4槽分别为 0 和 5，一次原位读取答 0 与 1，随后真正交付的次项分别是 **5 与 11**。含全部写者、一次补读与两个业务字的总费用分别为 **3,861、3,859**。旧摘要失效是因为它不能再分开该对当下任务需要区分的世界。

## 需要多少补读：50 个同等计数的场景

对两种 F、五条边、五个旧历史共 50 项，以下以各项补读次数的**和**为目标。假设旧消息类大小为 n₁,…,nₘ，每同色顶点对只在唯一一个“F、边菜单”组合上冲突，两个旧世界各需至少一次补读；同一新边的端点至多两个，查一个实际顶点即可达到。精确总数为 Σᵢ nᵢ(nᵢ−1)。对一定位数平分五个顶点最优：

|汇合预存位数|0|1|2|3|
|---|---:|---:|---:|---:|
|实际使用的消息数|1|2|4|5|
|50 项合计最少补读|20|8|2|0|
|各场景的最坏补读|1|1|1|0|

这里没有给两种操作设定真实世界发生概率；若在这 50 项上取均匀概率，数值可再除以 50。程序独立检查了满足每个消息预算的全部顶点分割，并验证表中逐场景达到的结果。
