## 生产结构

设请求槽r、每目标颜色数M=r+1、低位宽b=ceil(log2 M)、B=2^b。固定分配2B−1个前缀节点，每节点有子树标签计数与桶首尾指针。每个活跃观察来源标签只挂在其已知低位的最深前缀桶中；复制共享同一标签，初始相等但未经辨认的请求仍可分成不同标签。

每个槽通过侵入式循环链接到自己的标签，标签保存引用数与代表槽；每个前缀桶通过侵入式双链保存标签。删除代表槽时直接切换到链上的下一槽，不遍历全部请求。所有当前标签数、已知位数和峰值都增量维护。

`count(v)` 只计本节点及后代桶中的标签，不包含尚挂祖先桶的标签。因此不能把任意节点的 `count=0` 单独当成安全证据。查询从根开始，每次先清空本节点的未知桶再下降；沿这条路径，祖先已完成分流，节点计数才足以约束所有潜在阻挡者。

初始每个请求槽产生一个根未知标签。一次真实位读取把标签从深度ell的桶移到对应子桶，只有新子节点的计数加1；既有祖先计数不变。绑定/删除退休旧标签并插入低位已知的新标签；业务完整读出沿新增深度补齐标签。创建与释放源保持请求树。

## 当前目标的候选容量

目标首键的低b位为s。节点低位前缀为p、深度ell，合法颜色从0到M−1。令

`first = (p-s) mod 2^ell`。

如果first≥M，该节点无合法颜色；否则候选数为

`m = 1 + floor((M-1-first)/2^ell)`。

生产代码在搜索入口先计算s=`C.key(target,0) % B`，后续容量计算只处理低b位范围内的整数，实际创建仍使用原完整身份键。无需枚举M个颜色或构造B位大掩码。

查询保持`m>n`，其中n是当前节点的活跃标签数。清空本节点桶后，两个子节点的候选容量与标签数分别相加得到父值，故至少一个子节点仍有缺额。固定选择满足缺额条件的最小`(n,bit)`子节点；n=0时直接用first取得一个合法颜色。

控制器另保留一个已经证明安全的余数作为见证。每次成功冲突检查后，先用一次模B差值判断该见证是否落在当前目标合法范围；命中则直接使用。绑定新键余数与见证相同才删除见证。当前目标未命中才调用树搜索，不补回一个全目标配额集合。

所有新读取均执行原八步读取块，并消费其完整布尔输出；原绑定、复制、valid、execute返回的实际键可补齐观察。生产控制器不调用测试器的完整请求解码。创建使用最后一次实际布尔输出；无新增读取时保留前面的可用性真值，缓存与树信息不会冒充物理答案寄存器。

## 计量与复杂度口径

一般累计新增缺席位读取继续满足Q≤rb。首次完全未知的目标查找精确最坏值为`F(r)=2r−popcount(r)`，与父单目标算法的界一致；本轮进一步保留实际形成的分组，使以后不再重放旧缓存位。

新增决策控制状态需要O(r log(r+1))位：2B−1个节点、至多r个活跃标签和r个槽链指针，以及一个低b位见证。累计测量计数器另需O(log N)位，原命令列表、日志与验证材料另计。原Compiler的静态成员、候选关系和编译表沿父模型核算。

除原BRC命令发射和测量输出外，一次查询细化只执行常数次桶/计数更新；一次受控身份操作更新常数条长度至多b+1的路径；一次真正搜索至多访问b+1个节点。N个业务操作中的新增决策控制工作可按O(r+Q+Nb)计量。该口径使用能够装下节点索引、请求计数及低位值的字操作；它不是把任意长Python整数或输出日志视为常数。

结果中的类型化事件含义如下：

| 字段 | 精确记录的事件 |
|---|---|
| `vacancy_bit_reads` | 实际新增缺席查询，单次使用原8步读取块 |
| `business_key_bit_reads` | 原业务程序的身份位读取；不含存在性等其他布尔读，但全部原命令已计入commands |
| 旧策略 `request_bit_inputs_to_search` | 旧配额树实际消费的真实位与缓存位之和 |
| `query_label_moves` | 新树依实际读出把一个标签推进一层，恰等于新增缺席读数 |
| `query_count_updates` | 该推进新增的子节点计数更新，也恰等于新增缺席读数 |
| `query_node_visits` | 新树实际查询路径中的节点数，含终止节点 |
| `candidate_count_queries` | 两个子节点的候选容量计算数，每次分支2次 |
| `business_path_touches` | 业务补齐、退休和新标签插入实际触碰的计数节点数 |
| `witness_checks` / `witness_hits` | 单见证的目标范围检查／命中数 |
| `slot_detaches` / `slot_attaches` | 槽链的移除／连接事件 |

这些是不同类型事件，不将448次旧位输入和128次新节点访问直接解释为CPU加速倍数。每个原命令、标签细化、节点访问及业务更新分别报告。
