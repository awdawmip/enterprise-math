## 1. 本轮对象与成果

父结果将动态引用实现为创建身份元数据，匹配变化走原三元内核。本轮选取一个逻辑目标 h、r 个登记引用槽的完整顺序接口，把当前实例、引用身份、同源比较、有效性、复制、删除、有限编号选择以及条件执行，全部编译成固定的 reserve/release 命令。生产执行过程中不查询 Python 名字表，不按当前输入选择命令路径，不由测试程序选择空编号或写回答案。

六槽实例使用七个编号，全部状态存于84个声明成员、435条候选三元关系的有限匹配中。每个 API 动作返回一个完整六成员布尔寄存器，并清理私有临时关系。编译器支持任意有限 r>=1，M=r+1。

这里实现的是一个逻辑对象的带标识存储接口。物理当前行 C_c 表示该逻辑对象存在并属于编号 c；不是在原三元组 h 外面免费加一个身份字段。观察者在完整 API 边界读取当前存在、请求空/目标、有效性和同源关系，不观察中间存储事件的创建代次、编号数值或任意物理成员。底层事件可能在同一逻辑对象操作内部重新装配。由真实晶胞实现这些候选及观察界面的对应，作为后续原生桥接义务保留。

## 3. 存储表示

对每个持久行 v（当前行0，以及r个引用行）设置私有成员 a_v,b_v,p_(v,0),...,p_(v,M-1)。颜色 c 用唯一三元事件

    C(v,c) = {a_v,b_v,p_(v,c)}

保存；空行没有事件。各行成员互不相交，同行所有候选共享 a_v,b_v，所以同时至多形成一个。不同引用可各自保存相同列 c，表示同源，且不会因为共享物理成员而互相阻挡。

另有一行相同格式的临时备份、两个编号阻挡成员、一个三成员比较标记、一个公共工作成员、一个六成员完整输出寄存器。总库存为

    (r+2)(M+2)+12 = (r+2)(r+3)+12.

r=6 时，七个持久行用63成员，备份行9成员，其他辅助12成员，共84。

实际六槽布局：当前行 {1,2,p},p=3..9；六个引用行依次使用10..63；备份64..72；阻挡成员73、74；比较标记75、76、77；工作78；完整输出79..84。源码中的颜色为0..6。PROGRAMS.json保存完整静态布局和全部原命令。

## 4. 条件写入与复制、比较

沿用已证明的 WriteAll(P;h;z)：对每个 p∈P 尝试 {p,h_min,z}，然后尝试 h，最后释放 z，共 |P|+2 步。源与目标/工作区分离。所有 p 被占用时探测均受阻，空目标 h 可以形成；至少一个 p 空闲时临时探测阻挡 h，最后清除。目标已存在时保持。每块结束源恢复、工作清空。

复制 v 到 w：先释放 a_w 清目标；对全部 M 列执行 WriteAll({p_(v,c)};C(w,c);z)。唯一占用的源列产生相同目标列；空源使目标保持空。调用既有六步 reader 保存目标存在性。自复制在编译期由相同槽参数识别，仅读取存在性；不依赖运行中状态。

同源比较：对所有列执行 WriteAll({p_(v,c),p_(w,c)};D;z)，D是私有三元标记。存在某列同时占用，恰好两非空行保存同色；通过六步 reader 写完整结果，再清除 D。空行比较为假，自比较等于非空性。valid(i) 比较引用i与当前行；same(i,j) 比较两引用，包括两者都已失效的情形。

因此身份同源不再只存在于 Python 元数据。当前与引用的记录及比较结果都由实际匹配承载。

## 5. 有限编号选择的实际实现

create 先用反向六步 reader 保存当前是否为空，作为返回结果。然后按固定顺序扫描全部 M 列。

对于颜色 c，临时阻挡事件

    B_c={p_(0,c),u,v}

使用两个私有辅助成员 u,v。对每个引用行 i 运行 WriteAll({p_(i,c)};B_c;z)。只要有一个登记引用仍保存 c，B_c就形成，阻挡当前行 C(0,c)。随后尝试 C(0,c)，再释放 u 清阻挡；继续下一列。

当前为空时，r个引用最多占r种颜色，M=r+1保证至少一空色。第一个未被引用的颜色形成当前事件；此后的当前提案被同行公共成员挡住。当前原来存在时，同行公共成员使它保持，不生成新实例，返回假。失效引用仍参与颜色占用，因而其同源信息在最后一个引用退出前继续受保护。

这是固定扫描，不使用运行时 min/free-color Python 分支。固定顺序和候选库是静态程序信息。

## 6. 条件执行与实际逻辑恢复

execute(i) 先实际比较当前与引用，得到完整真假结果。打开结果头，负尾端口只在结果为假时占用。对每个颜色，用当前列与负尾两项条件把当前记录复制到临时备份。随后释放当前行，逐列把备份转回当前，清备份，补齐结果头。

若请求有效，负尾不存在，备份为空，当前行被删除；引用记录仍保存原身份，故今后失效。若请求无效，当前颜色被转存并恢复，逻辑当前状态保持。目标与各引用都空时也得到假并保持空。

这一实现会暂时打开当前存储行，所以正确性在完整 API 边界上成立。实际单槽反例中，一个无效 execute 的第27..31步可观察到当前行暂时为空；末态则精确恢复且返回假。若给物理存储事件另附不可复用创建名，同一测试中其名字由1变11，逻辑颜色不变。故本轮实现的逻辑身份与原生物理创建连续性需要分别定型，未将此解释为父严格物理身份恢复边界的反例。

## 7. 精确模拟定理与成本

将理想执行器仍可访问的创建身份，与当前物理表中的颜色建立一一对应：当前存在性相同，各引用空/目标相同，同一身份恰对应同色。允许的接口为 create,destroy,bind,copy,drop,present,valid,same,execute；只有一个固定逻辑目标h，所以 target等价于present并返回h或空。

逐动作证明：

1. create 有空色时扩展对应；当前已存在则保持。所有未来可访问引用占用的颜色均被排除，保证新身份不与旧引用混同。
2. destroy删除当前节点，保留引用；copy/bind/drop分别保持或删除相应节点的身份归属。
3. same与valid恰检查颜色相等及非空，给出理想结果。
4. execute在真分支删除当前节点，假分支按原色恢复，其余节点不变。
5. 每段清理临时状态并产生完整响应；没有节点的颜色可在下一创建时重新使用，对应已退出的理想名字。

归纳得到任意有限完整 API 串的响应与同源分组精确对应；依赖已取得响应选择后继的客户端也由同一归纳覆盖。比较的是这个边界观察语言，而非中间物理匹配的逐步同态。固定一一重命名不影响同源结果。原CWM汇合继续保留历史重数。

## 9. 明确遗漏范围与失败证书

固定顺序、环境稳定时，每个原语均幂等。每个原位置连续安排f+1次、全程至多f次完全遗漏，至少一调用执行，组末等于原一步；逐组归纳保护完整词。此结论不允许在重复之间插入外部变化。

实际保护单槽77步完整链：create→bind→destroy→create→valid。f=1时154命令，保留无遗漏及154种单遗漏；f=2时231命令，保留无遗漏、231种单遗漏、26565种双遗漏。原CWM精确汇合后，全部完整末态与无故障目标一致。这是固定生命周期链的执行覆盖，没有六槽全并发/全故障联合穷尽主张。

未保护create遗漏一个真实已用色阻挡事件的加入，会把旧请求仍保存的色重新分配，旧引用实际复活。表外旧引用被隐藏、登记表drop后编号复用，再把旧引用引回，同样可误认新对象。两条轨迹均保留。

如果让两条引用物理记录共用同一个颜色成员，第一条形成后第二条被原匹配规则阻挡，无法保存两个别名。因此本构造采用每行私有颜色端口，通过实际比较联系列号；没有把“同源”误建模为“同时占用同一成员”。
