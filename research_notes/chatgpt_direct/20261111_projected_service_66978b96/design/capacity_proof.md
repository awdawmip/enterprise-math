# 可设计的辅助标记数：同一首选服务的精确容量

使用 N≥1 种不同的业务交付，0 为所有首选均可用，其他 N−1 种各占一个首选。世界由此交付唯一确定。名单内测试只能问某一指定标签是否出现；另外事先可以任意设计 h 个二值标记，每个标记在世界上是一列固定函数，汇合后一次实际读取其中一列。h 是**可用的不同观测列数**；不等于每走一步就能临时设计新测试。此节只优化读取深度，前缀制造标记的成本另计。

深度 d 可承载的最大不同交付数为

    C(d,h)=2^j(d−j+1),  j=min(d,h).

上界允许连标签 0 也能被单独点名，这只增强测试者。根问一个单点，肯定端立即确定，否定端最多 C(d−1,h)，合计至多 1+C(d−1,h)。根问一个辅助列，两端各有至多 h−1 个剩余辅助列，故至多 2C(d−1,h−1)。基例 C(0,h)=1、C(d,0)=d+1。所给闭式满足递推，在 h≥1、d≥1 时第二项达到最大（可能并列）。上界无需假设每个后续节点真能自由改变辅助库存。

构造达到：j 位固定辅助列编码至多 2^j 个等大的桶，每桶至多 d−j+1 种标签。先读桶号，再逐个问桶内非零标签，最后一个由排除法确定；含 0 的桶把 0 留到最后，绝不需要询问 0。实际合法测试即可达到。于是给定 h 的最优最坏读数是满足 N≤C(d,h) 的最小 d。若任务事先已知，汇合另准传递 s 位任意摘要，可容纳量再乘 2^s：每个摘要类有同样的上界，而按总标签分成消息×桶，辅助列在各类分别定义即可达到。同一组辅助列/摘要必须为未预告的多种名单通用时，适用本轮另外的时序定理，不作此设计假设。

|交付种数 N|0 个辅助标记|1 个|2 个|3 个|4 个|
|---:|---:|---:|---:|---:|---:|
|5|4|3|3|3|3|
|8|7|4|3|3|3|
|16|15|8|5|4|4|
|32|31|16|9|6|5|

特别地，N=2^b、b≥1，要达到 b 次读的叶数极限，只要 b−1 个可选辅助标记，少于 b−1 个达不到（设 j=b−k，若 k≥2 则 k+1<2^k）。最后一位区别可由桶内一个首选测试补足。

校验：helper_capacity.py 在 N=2..8，h=0,1,2 中枚举固定列集合；仅剔除恒定、重复及互补测试，含可独立检测 0 的辅助列。共 9,581 个（带参数重复计数的）设计；通过全询问树动态规划求出最优值。另验 420 个闭式递推格点。机器值见 capacity_results.json。
