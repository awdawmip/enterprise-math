# 最大消息类能覆盖多少段历史

三个服务共用一个晚选变换时，单个合法消息类最多有 13 段历史，达到容量的类共有 250 个，彼此为仿射像。本节研究先从这 250 个母类中选若干个，再将交点分配给其中一个母类的编码。原模型中，一个母类的任意非空子集也是合法消息类。因而在此附加条件下，最少标签数就等于覆盖 125 点所需的最少母类数。

在完整点集上，给定允许选择的母类数 $k$ 和允许遗漏的点数 $h$，固定第一个母类。对未分配的点，先计算每个母类能新增多少个点。若剩余名额内最大的新增数之和仍不足，则排除。当某个候选的新增数就算配合最好的其他名额也无法达到覆盖要求，它便不能再选。没有可选母类包含的点只能实际漏掉，计入 $h$。

接着选尚待覆盖且选项最少的一点。对可覆盖此点的母类编号，将第一个入选者固定，其前面的全部排除，以此规范化继续搜索。余量允许时再枚举漏掉这个点的情形。遍历只使用精确的整数上界。每个分支都选定一个以前未选的母类，或者消耗一个新漏点。见证以母类编号给出，检验程序从实际菜单重新生成母类，直接检查并集以及依序截去前面已分配点的消息分区。完整枚举给出的禁止门槛及结点数见 result.json。

十一个最大母类无法覆盖全部历史，十二个也无法全盖。十三个母类的覆盖见 witnesses.json。因此，若每个标签类都必须嵌入某个十三点合法类，则完成全域一读恰需十三个标签。十个母类最多覆盖 112 段历史。十一、十二个母类最多分别覆盖 **119 和 121** 个历史。为证明十二母类最多只能盖121点，对所选任意两母类，利用仿射自同构和两者交换取最小编号代表，250个母类的二元组恰有12种位置。任一候选完整族中，固定其位置编号最小的那一对，将其归一化成母类0及相应代表j。因此其余每个母类与0所成的二元组位置序不能低于j。将它们放入相同整数搜索，容许最多3个遗漏，12种位置均无解。对无此限制的十一标签或十二标签表，至少有一个合法消息类不嵌入任何十三点类。

运行 python3 -B replay.py --older /path/to/round2/delivery。该依赖目录应含 bounds/。

对于所给十三个母类，89 个点仅属于其中一个，余下 36 个点需选择归属。使累计读数最低的分配恰为 **9,346**。assignment.json 列出取等表、36 个共享点的权和十三个类的常数项。逐一检查每个类必取的私有点与所选共享点，对全部 1,152 个合法局部选项核对：常数项与所选共享点权之和至多为该类读数的 10,000 倍。整表求和恰得 93,460,000，证书表达到 9,346。这个最小值对应所给的一组十三个母类，尚未对其他十三母类覆盖取最小。
