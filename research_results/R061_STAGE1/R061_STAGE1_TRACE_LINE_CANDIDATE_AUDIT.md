## 1. Native line identity

Fix a sector `S_ij`.

Define the trace identity

`T_{a,b}^{(ij)}=[X_i^a X_j^b]`

under the equivalence relation generated by

`X_i X_j ~ X_j X_i`.

This trace stores:

- the native sector label `(ij)`;
- `a` copies of the native positive-axis component generator `X_i`;
- `b` copies of `X_j`.

It is therefore stronger than a common carrier center endpoint. A carrier relation involving the third direction cannot rewrite this native component identity.

Its linearizations are exactly the Stage 0 validated shuffle:

`Lin(T_{a,b}^{(ij)})=Sh_{a,b}(X_i,X_j)`.

Cardinality:

`|Lin(T_{a,b}^{(ij)})|=binom(a+b,a)`.

## 2. Native realization map

Define

`Realize_E(T_{a,b}^{(ij)})`

as the set of all paths

`Sigma_O^(ij) ; w`,  `w in Lin(T_{a,b}^{(ij)})`,

with cell state after a prefix `p` equal to

`C_ij(#X_i(p),#X_j(p))`.

Every prefix count is nonnegative, so every state remains in the fixed sector affine center chart.

Every letter translates by one nearest-center direction `t_i` or `t_j`, so every transition is between overlapping nearest-neighbor circle cells.

## 3. Local commutation diamond

Starting from any `C_ij(p,q)`, compare

`X_i X_j`:

`C(p,q) -> C(p+1,q) -> C(p+1,q+1)`

and

`X_j X_i`:

`C(p,q) -> C(p,q+1) -> C(p+1,q+1)`.

Both paths:

- have one cell at every state;
- use only nearest-center transitions;
- remain in the sector;
- terminate at exactly the same typed terminal cell;
- accumulate exactly one `i` component and one `j` component.

The two distinct intermediate cells form the two sides of a local carrier diamond/elementary rhombus (with a carrier third-direction chord). Thus the adjacent commutation has a real native cell-incidence realization; it is not merely a symbolic endpoint-count identity.

## 4. Why the third-direction chord does not collapse the trace

At the carrier level the same diamond has a direct reverse-third-family chord because

`-t_k=t_i+t_j`.

The current foundation explicitly freezes this as a **carrier presentation relation only** and forbids treating it as a native Enterprise vector identity.

Therefore the allowed native line-trace relation is

`X_i X_j ~ X_j X_i`,

not

`X_i X_j ~ -X_k`.

The first relation preserves native component labels; the second would erase them by promoting a carrier relation to a native vector relation.

## 5. Composition

Trace identities compose by component addition:

`T_{a,b}^{(ij)} * T_{c,d}^{(ij)} = T_{a+c,b+d}^{(ij)}`.

Concatenating one representative of the first trace with one representative of the second gives a valid representative of the larger trace.

The set of direct concatenations is generally a proper subset of all linearizations of the larger trace, because letters can interleave across the concatenation boundary.

Closure under the same adjacent component-preserving commutations gives exactly

`Realize_E(T_{a+c,b+d}^{(ij)})`.

Thus identity composition is exact and path composition is compatible after trace closure.

## 6. Scaling

For `k in N_0`:

`(T_{a,b}^{(ij)})^k = T_{ka,kb}^{(ij)}`.

Hence scaling preserves the line-identity class and the realization rule.

No claim equates the number of letters `k(a+b)` with the native length. The scaled native length remains the frozen algebraic norm of the scaled component pair.

## 7. Reversal

A realized cell trajectory may be traversed backward by inverse carrier transition morphisms.

This is a path-groupoid inverse:

`(C -> C+t_i)^(-1) = (C+t_i -> C)`.

It does **not** create a native negative number axis and does not introduce a negative native coordinate generator. Reversal changes path orientation, not the native positive-axis ontology.
