# Coordinate migration Driver evidence review: seven upstream obligations and integration readiness

Status: `BLOCKED / GOVERNANCE / EVIDENCE-GATED`

## Mother question

Do the seven upstream coordinate-migration tasks collectively provide exact, source-bound evidence for their own frozen obligations, and which specific gaps remain before the integration-acceptance task may be treated as evidence-ready?

## Frozen inputs and scope

Review exactly the seven upstream publications recorded in the coordinate triage manifest: full-X6 atlas, chart/BRC transport, layer/shell semantics, runtime refinement, caller/data migration, research-bridge audit, and CFD operator transport. A publication record is not a Result. A local pass is not automatically a reviewed theorem. Negative and partial outcomes remain valid evidence when their scope is explicit.

Preserve P000, native signed operations, native cell population, ordered path provenance, and the distinction between display/address/readout and internal mathematics. Review representation deltas only; do not reopen unrelated research.

## Hard target and required outputs

For every upstream task, bind the exact publication generation, source/result bytes, formal or executable checks actually run, unresolved assumptions, negative witnesses, and the smallest required correction if any. Issue a disposition that is precise enough to distinguish accepted task-local evidence, nonterminal revision, scoped no-go, or unresolved dependency.

Produce one integration-readiness ledger showing which claims may be transported without reproof, which interfaces require migration only, and which mathematical statements genuinely need recomputation or new proof. The ledger must not mark `RS-COORD-INTEGRATION-ACCEPTANCE-20260916` evidence-ready unless every dependency named there is satisfied by the required artifact strength.

## Research value to preserve

This review keeps the coordinate project evidence-driven. It protects already-valid mathematics from unnecessary reopening while preventing a representation-level success from erasing unproved full-X6, observer, refinement, engineering or migration obligations.

## Success, kill, and return criteria

Success is a reproducible source-bound Driver disposition for each of the seven upstream tasks plus an exact integration-readiness state; success does not require every research hypothesis to be positive.

Reject any review that substitutes task publication for a Result, treats a finite test as an infinite theorem, ignores a declared negative witness, or weakens information-preservation requirements to obtain a pass. If one obligation fails, return the smallest repair while retaining every unaffected accepted component.
