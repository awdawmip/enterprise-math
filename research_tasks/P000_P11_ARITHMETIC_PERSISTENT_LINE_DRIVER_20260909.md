# P000 P11 arithmetic persistent line Driver and complete handoff

## Mother question

How should the P11 arithmetic-collision line remain continuously owned, reviewable and recoverable from the current diagonal elliptic-fiber result through the diagonal/off-diagonal continuations, independent verification, final integration and eventual route closure or park decision?

## Frozen inputs and scope

Read `research_notes/P000_P11_ARITHMETIC_COMPLETE_RELEASE_AND_DRIVER_HANDOFF_20260909.md` first.

This is a GOVERNANCE task for an explicitly activated Research Driver. Publication of this task does not create a future Driver identity, execution owner or continuously running background process. Persistent responsibility means that one line Driver is the default reviewer/router while active and that a replacement can recover the same responsibility from the durable dossier.

The line is `OBJ-P000-SIX-AXIS-ARITHMETIC-TROPICAL-INTEGRATION` restricted to the P11 arithmetic-collision branch. It includes the accepted historical chain, the reviewed diagonal fixed-locus Result `RR-764F6E463528167708E9`, the two current mathematical continuations, the independent audit and final integration task.

Current P000 V5 and the joint-relation observer preservation contract are mandatory boundaries. This governance task cannot grant theorem truth, Working Truth, Foundation status, native-geometry interpretation or broader project priority by itself.

## Hard target and required outputs

1. accept an explicit line-Driver delegation under the current Driver role and persist the actual resolved Driver identity and authority source;
2. maintain one current line dossier binding task/publication IDs, exact Result/review revisions, active owners, unresolved obligations, P000 version, observer-safety constraints and the next executable action;
3. treat finished researchers as one-shot contributors: all later-needed proof, code, certificates, source exposure and unresolved issues must be recoverable from durable artifacts rather than assumed future contact;
4. route `RS-P000-P11-DIAGONAL-ELLIPTIC-FIBER-PRIMITIVE-ARITHMETIC` and `RS-P000-P11-OFF-DIAGONAL-EQUAL-AREA-FIBER-PRODUCT` as the two current mathematical branches, preserving any existing valid owner before issuing a new one;
5. review each returned immutable Result against its exact current bytes, reuse already-reviewed unchanged obligations, and maintain an incremental issue/decision ledger rather than restarting full review;
6. if a Result requires revision, publish the proper same-Task-ID superseding generation for a fresh bounded researcher when no valid revision task already exists;
7. release the independent audit only after both mathematical branches have Driver-accepted exact Results and an actually independent verifier can be identified;
8. release final integration only after the branch Results and independent audit satisfy its declared evidence conditions;
9. apply the current BRC/observer discipline at line bottlenecks: preserve joint/composite relation directions, labels, signs, multiplicity and reconstruction provenance unless an exact scoped safety certificate permits quotienting;
10. keep all derived Pythagorean, elliptic and higher-arithmetic results typed as facades under current P000 V5; escalate only a genuine cross-line/native-semantics question to Owner;
11. choose evidence-based revision, continuation, split, park or closure after each terminal task; do not manufacture tasks merely to keep the line active;
12. before the Driver context ends, update the dossier with the exact next action, blockers, accepted/rejected artifacts and replacement instructions.

## Research value to preserve

The line has become too deep for repeated Owner-level reconstruction: its useful state is distributed across carrier decomposition, tropical alignment, conditional selectors, simultaneous pairability, Diophantine normal forms and elliptic fibers.

A persistent line Driver keeps that evidence chain coherent while short-lived researchers solve bounded mathematical units. The Owner can then concentrate on cross-line synthesis, world-model direction and shared interfaces rather than rereading every local proof.

## Success, kill, and return criteria

This governance task succeeds only when the P11 arithmetic line reaches a reviewed final integration/closure/park decision with a reusable evidence package, or when responsibility is explicitly transferred with a complete replacement dossier.

Do not mark it complete merely because one researcher returns a proof or because the two mathematical tasks are published. Do not fabricate an active owner, independent review, theorem acceptance or automatic execution.

A recoverable nonterminal handoff must state the current line Driver, exact task/publication/result/review identifiers, active owners, blocked gates, current P000 and observer constraints, and the smallest next executable action.
