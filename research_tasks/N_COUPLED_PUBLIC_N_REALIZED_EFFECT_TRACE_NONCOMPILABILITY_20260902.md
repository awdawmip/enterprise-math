# N-coupled public-N realized-effect trace noncompilability

## Mother question

After both complete runtime reflection and public presentation-transparent constructor traces have been proved to scalarize one-sided finite-module support before readout, can a fully specified public-`N` effectful capability contain a **realized runtime transition** whose support-bearing output is genuinely not reconstructible from the public trace, yet still yields a non-oracular delayed support asymmetry?

## Frozen inputs and scope

Use the accepted boundaries unchanged:

- an explicit finite presentation with one-sided hidden rank/support exposes a proper determinantal gcd;
- complete finite extensional reflection exposes cardinality and/or reconstructs a presentation;
- `G_trace-lin` removes runtime reflection but remains scalarizable because `NEW_FREE`, relation attachment, direct sum, and tensor product are presentation-transparent from the public syntax tree;
- the accepted mechanism audit excludes hidden-factor inputs, group-order/smoothness routes, collision/cycle routes, congruence-of-squares/relation routes, named-prime p-adic lifting, and direct nonunit endpoints as relabeled novelty.

This task must freeze one exact capability calculus `G_effect`. It may retain deterministic presentation-transparent constructors, but it must contain at least one load-bearing consuming transition

`REALIZE_EFFECT(spec, H_1,...,H_k) -> H'`

or an exactly equivalent effectful primitive whose **realized outcome** is not included in the pre-readout public transcript.

The public specification `spec`, its input/output types, allowed composition laws, and any probability/nondeterminism semantics must be completely explicit. Treating the effect implementation as secret is not admissible.

## Hard target and required outputs

Hard target:

`PUBLIC_N_ONLY_REALIZED_EFFECT_TRACE_NONCOMPILABILITY_CONSTRUCTED_OR_EXACTLY_OBSTRUCTED`.

A positive result must prove all of the following for the frozen calculus:

1. runtime handles remain extensionally nonreflective before readout;
2. at least one reachable realized state has genuine one-sided hidden support or an exactly equivalent typed asymmetry;
3. the exact realized output presentation/support is not effectively compilable from the public transcript and input presentations before readout;
4. every permitted pre-readout scalar remains gcd-clean;
5. the terminal readout is implemented from the frozen public capability vocabulary and is not specified as a factor/nonunit/CRT-side oracle.

If the effect uses hidden randomness or nondeterminism, the task must explicitly determine whether the public semantics can be pushed forward to an effectively sampleable/enumerable distribution or family of explicit presentations. If so, and successful readout is exactly a proper gcd/nonunit event of the realized presentation, classify the mechanism against direct randomized nonunit search rather than treating hidden realization alone as a new capability.

A valid negative result may prove that all realizations are presentation-compilable from public effect data, that the effect is equivalent to explicit randomized presentation sampling/nonunit hunting, or that it encodes a reviewed classical/hidden-factor mechanism.

Freeze the exact effect contract, symbolic theorem or construction, deterministic checks for finite claims, execution provenance, and a NEW Result-ID with complete Git-blob SHA-1 plus SHA-256 bindings.

## Research value to preserve

The N-coupled line has now separated three notions that must not be conflated: changing hidden support, hiding an explicit support-bearing representation, and limiting reflection of runtime values. The current frontier adds a fourth: whether **realized effect information** can be unavailable from both runtime reflection and public source compilation while still being mathematically non-oracular.

A positive survivor would be the first mechanism in this line not already killed by ring-term erasure, unimodular invariance, explicit-presentation scalarization, complete-reflection scalarization, or public-trace compilation. A negative theorem would further clarify which effect resources merely disguise randomized nonunit search.

## Success, kill, and return criteria

Success requires a fully specified effectful calculus, a theorem-level trace-noncompilability/nonreflection argument, a genuine one-sided support construction, and a non-oracular final readout.

A valid negative return is an exact reduction to public presentation compilation, explicit randomized presentation/nonunit search, or another reviewed mechanism, or an exact no-go for the frozen effect class.

Kill and reject:

- hidden factors or factor-correlated secret inputs;
- a primitive whose contract already reveals a factor, nonunit, CRT side, or selector;
- undocumented implementation secrecy;
- complete runtime enumeration/equality or presentation-transparent source syntax masquerading as nonreflection;
- random scalar or matrix sampling followed directly by a proper-gcd/nonunit test without an independently new typed mechanism;
- order/smoothness, collision/cycle, square-relation, or named-prime p-adic mechanisms under new terminology;
- finite hit rates as proof of the semantic claim.

No positive construction should be interpreted beyond its exact frozen capability class until the existing mechanism audit has been applied to its full input/state/stopping/readout semantics.
