# R014 — Exact-Law Representation Resource Calculus

Status: `READY / P1 / HIGH / CROSS-ROUTE RESOURCE PRESSURE TEST / NOT CANONICAL`

## 0. Mother question

This task starts **after semantic precision has already been fixed**.

Do not compare two representations as resource alternatives unless they implement the same declared semantic contract: the same required observation, legality/DOMAIN behavior, future operations, relation/witness channels and continuation interface.

The mother question is:

> When the exact semantic law is fixed, do exact implementations form a project-native resource calculus with reusable composition/lower-bound structure, or are the observed tradeoffs merely ordinary time-space/circuit/compiler/Pareto phenomena expressed in Enterprise Math language?

R014 is independent from R013:

- R013 asks when a precision-indexed theorem family is mathematically closed.
- R014 asks how one already-fixed exact semantic law may be represented/executed with different operational resources.

Do not merge the two tasks.

Deep Research: **ON only for prior-art attack and de-duplication**.

---

# 1. Freeze semantics before resources

For every case study define a semantic contract `S` first.

At minimum record:

- accepted input/state type;
- declared future/action language;
- current and future observations;
- whether output is terminal readout or recursively executable state;
- DOMAIN/legality requirements;
- relation/witness/multiplicity/provenance requirements;
- exactness criterion.

Only implementations in the same operational fibre

`Impl(S) = { implementations realizing S exactly }`

may be compared on resource coordinates.

If two candidates differ in semantic capability, route the comparison back to A2/P023/R013 precision semantics rather than calling one implementation cheaper or more expensive.

---

# 2. Candidate resource vector

Start with a typed vector, not a universal scalar:

`R(I) = (state_storage, law_storage, coefficient_width, channel_count, preprocessing_work, online_work, serial_depth, parallel_depth, decoder_or_normalizer_cost, reconstruction_cost)`.

Coordinates may be `N_0`, rational bounds, asymptotic functions, or `N/A` depending on the representation class.

Rules:

1. decoder/normalizer/reconstruction cost is never free;
2. a terminal answer table and an executable-state presentation are different semantic contracts unless continuation equivalence is proved;
3. representation-class-specific lower bounds must say which technology is allowed;
4. do not scalarize the vector unless a workload/cost functional is explicitly declared;
5. retain the nondominated Pareto set when no canonical scalar cost exists.

The researcher may alter this vector only by explaining why a coordinate is semantic rather than operational, redundant under the declared class, or missing from a sharp counterexample.

---

# 3. Mandatory cross-route pressure tests

Use at least these five families.

## 3.1 Stage131 implication/closure presentation

Compare, under identical closure semantics:

- adjacent/Hasse basis;
- transitive/one-round table;
- sparse TC-spanners / source-specific shortcuts;
- Horn/hyperedge macros;
- selective rooted-circuit materialization under workload/fan-in budgets.

Extract which resource laws survive the transition from unary graph paths to multi-premise AND/OR proof geometry.

## 3.2 Future-word compiler

Compare:

- generators only;
- literal word cache;
- finite transformation-monoid/right-generator automaton;
- Cayley-table parallel normalization;
- formulaic/circuit normal form.

The key pressure test is that semantic effect count does not determine presentation complexity.

## 3.3 CRT / modular sensor factorization

Fix one exact modular reflection law and compare fused versus factorized coprime channels.

Track peak width, total rounded width, channel count and conditional reconstruction depth. Separate arithmetic semantic equivalence from implementation packaging.

## 3.4 R004 storage / innovation timing

Consume the frozen #449 resource schedule only as a test family.

Ask whether moving exact transcript capacity from ex-ante storage to runtime innovation is represented by the same resource algebra as precomputation depth, or whether causality/timing requires a distinct typed coordinate.

Do not reopen R004 causal ontology.

## 3.5 R005-A horizon / segment execution

Use the exact finite-horizon and segment-depth law as a second execution-depth family.

Ask whether segment materialization and Stage131/word-cache materialization factor through one common block-composition resource theorem or merely share a superficial ceiling formula.

# 4. Prior-art kill gate

Before claiming any new generic resource theorem, attack at least:

- time-space and time-memory tradeoffs;
- circuit size/depth/work tradeoffs and addition chains;
- automata/transformation monoids/Cayley representations;
- succinct data structures / preprocessing-query tradeoffs;
- partial evaluation, memoization and compilation;
- transitive-closure spanners / shortcutting;
- multiobjective/Pareto optimization;
- communication/channel-width tradeoffs where relevant.

Classify each surviving statement as:

- `ROOTING_SUCCESS / PRIOR_ART`
- `ENTERPRISE_SPECIALIZATION`
- `R014_SPECIFIC_RESIDUE`
- `TOOLING_ONLY`
- `REJECT`

A result that only says “more storage can reduce runtime” is automatically prior art.

---

# 5. Exact-law compiler object

Pressure-test the proposal that the natural resource-bearing object is not a table, quotient or scalar but an exact compiler/executor package

`I = (encode/decode, normalize, execute, observe)`.

The researcher must determine whether there is a mathematically useful equivalence relation `I ~_S J` meaning both realize the same semantic contract `S`, and whether resource comparison on an equivalence class has any invariant structure beyond ordinary program implementation complexity.

Do not call this a new primitive unless an exact theorem requires it.

---

# 6. Composition question — main theorem candidate

Suppose exact semantic subsystems `S1,S2` compose into `S1 ⊗ S2` and implementations `I1,I2` compose into `I1 ⊗ I2`.

Seek the weakest valid resource composition law, for example typed inequalities of the form

`R(I1 ⊗ I2) <= F(R(I1),R(I2), interface_cost)`.

Investigate when coordinates:

- add;
- multiply;
- take max;
- compose by depth;
- require synchronization/reconstruction overhead;
- cannot be predicted from component resources alone.

A sharp non-compositional counterexample is as valuable as a positive theorem.

If no generic law survives representation changes, return that as the negative boundary rather than inventing a universal calculus.

---

# 7. Lower-bound question

Separate three levels:

1. information/semantic lower bound — forced by number of exact semantic states/effects;
2. representation-class lower bound — forced inside a declared table/automaton/circuit/channel model;
3. implementation lower bound — dependent on machine/cost model.

Use existing sharp examples to show these can diverge.

Target at least one theorem/counterexample establishing that semantic cardinality alone does **not** determine exact presentation storage, depth or work.

---

# 8. Relationship to R013

R014 may provide resource defects consumed by R013 C4, but it does not define research closure.

R013 may say a theorem family is coherent and closed even though its exact implementations have a large Pareto frontier.

Conversely, an efficient representation does not establish theorem coherence or intrinsic residual collapse.

Return an explicit interface packet between the two tasks rather than merging them.
