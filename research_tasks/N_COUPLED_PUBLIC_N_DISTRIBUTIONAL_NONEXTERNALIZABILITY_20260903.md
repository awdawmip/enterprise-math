# N-coupled public-N distributional nonexternalizability

## Mother question

After exact seed externalization has shown that hidden realized branches with public exact seed laws are distributionally equivalent to explicit randomized presentation search, can any fully specified public-`N` effect remain executable and non-oracular while its support-bearing output law is **not** effectively externalizable?

## Frozen boundary

Use unchanged:

- explicit finite presentations scalarize one-sided support through determinantal/Fitting gcds;
- complete extensional reflection scalarizes finite opaque modules;
- public presentation-transparent constructor traces compile exact presentations;
- `G_effect-seed` may hide the actual realized branch but its public exact seed laws and deterministic branch compilers externalize the exact presentation law;
- ordinary random scalar/matrix presentation sampling followed by a proper-gcd/nonunit event is not a new mechanism.

Freeze the distinction:

`ACTUAL_BRANCH_NONCOMPILABILITY != DISTRIBUTIONAL_NONEXTERNALIZABILITY`.

## Hard target

`PUBLIC_N_ONLY_EFFECT_DISTRIBUTIONAL_NONEXTERNALIZABILITY_CONSTRUCTED_OR_EFFECTIVE_PUBLIC_EFFECTS_EXACTLY_EXTERNALIZED`.

The task must freeze one exact semantic class `G_effect-dist`.

A negative theorem may prove that every finite or otherwise explicitly delimited public effective generative semantics in the class has an external simulator/enumerator for the same presentation/output law. Such a theorem must state its computability and exactness hypotheses precisely.

A positive construction must satisfy all of:

1. public `N` only;
2. no hidden factor/CRT selector or factor-correlated environment input;
3. runtime handles remain extensionally nonreflective;
4. the actual realized branch is not recoverable pre-readout;
5. the public semantics itself does not yield an effective external sampler/enumerator of the same support-bearing explicit presentation law;
6. the effect remains operationally executable from its public specification, without appealing to secret implementation or a noncomputable/physical oracle;
7. terminal readout is built from the frozen public vocabulary and is not specified to return a factor/nonunit/CRT side.

The central burden is the tension between items 5 and 6. If nonexternalizability can only be achieved by adding an oracle or secret source, freeze that as a negative boundary rather than calling it a survivor.

## Mechanism firewall

Explicitly compare every candidate against:

- direct randomized scalar/matrix nonunit search;
- Pollard p-1 / Williams p+1 / ECM order/smoothness;
- rho/collision/cycle;
- Fermat/Lehman/Hart/CFRAC/Dixon/QS/NFS square-relation mechanisms;
- named-prime p-adic/Hensel mechanisms;
- hidden factors, CRT selectors, factor-correlated seeds/environment state.

Finite hit rates are never proof of semantic nonexternalizability.

## Required evidence

Freeze:

- exact effect contract and computability/externalization definitions;
- symbolic theorem or positive construction;
- deterministic exact checks for finite claims;
- adversarial oracle/secrecy/classical-mechanism audit;
- execution provenance;
- NEW Result-ID with complete Git blob SHA-1 + SHA-256 manifest.

Do not infer a factoring or complexity lower bound from a task-local externalization theorem.
