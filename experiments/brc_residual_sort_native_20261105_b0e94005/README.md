# BRC 残差分类转数值升序：C++ 实现与完整成本实验

日期：2026-11-05。范围：自然数 `0 <= x <= 1,000,000`。任务：将残差分类作为中间步骤，最终输出从小到大的数值顺序。

## 本轮结果

已经实现四个 BRC 版本，和四个基线在同一 C++ 程序中测试。最终矩阵包含 5 种输入分布、4 个规模、8 个算法，共 160 行计时结果。

- 对 100 个均匀随机数，BRC 合并版为 **3.178 µs**，`std::sort` 为 **0.606 µs**，当前 BRC 实现较慢。
- 对 100,000 个近平方数，逐项开根 BRC 为 **2739.482 µs**，共享锚点版为 **743.306 µs**，合并版为 **731.647 µs**。共享锚点把完整根求值从 100,000 次降到 1 次，提供了明确的结构收益。
- 同一近平方条件下，`std::sort` 为 **3094.217 µs**，两遍 10-bit 基数排序为 **346.551 µs**，普通区间计数为 **241.046 µs**。合并版相对 `std::sort` 的中位数速度比为 **4.23**；两种整数基线仍更快。
- 锚点版与合并版的中位数只差 **1.57%**，P10–P90 明显重叠；7 个对应轮次中合并版只快 3 轮。额外的倒数取商与合并计数尚未表现出稳定提速。
- 近平方 1,000、10,000、100,000 个元素的合并版用时分别为 **6.900、72.050、731.647 µs**。这与该输入族的线性工作量相符；复杂度结论依据下方算法分析。

## 算法

每个输入记录为 `Record { uint32_t value, id; }`，共 8 字节。`id` 是输入原始位置，用来检查重复值的稳定性。所有算法处理同样的记录；本报告的耗时对应带位置的记录排序。

| 名称 | 实现 |
|---|---|
| `std_sort` | 标准比较排序，允许重复键改变相对顺序 |
| `std_stable_sort` | 标准稳定比较排序 |
| `radix20` | 低 10 位、高 10 位依次做稳定计数，每遍 1024 桶 |
| `range_count` | 扫描最小值和最大值，按 `x-min(x)` 做一次稳定计数 |
| `brc_square` | 每个数整数开根，先按残差、再按根做稳定计数 |
| `brc_anchor` | 最小值的根作为公共锚点，商预测并精确验证，失败时整数开根 |
| `brc_adaptive` | 锚点版加同盆地证书和固定的 16 次预测试探 |
| `brc_fused` | 自适应版加精确倒数取商，以及有条件的一遍根—残差网格计数 |

### 1. BRC 状态与数值顺序

写成

\[
x=k^2+r,\qquad k=\lfloor\sqrt{x}\rfloor,\qquad 0\le r\le2k.
\]

不同根对应互不交叠、顺序递增的平方盆地；同根内残差越大，数值越大。因此 `(k,r)` 字典序等于数值升序。两遍实现先稳定按 `r` 排，再稳定按 `k` 排。

当前范围内 `k <= 1000`、`r <= 1998`，用 `(k << 11) | r` 暂存在原 `value` 字段，保留 `id`；末尾按 `k*k+r` 恢复原数。这是可逆的状态编码，最大需要 21 bit。

原语采用当前输入域的整数二分开根，搜索上界为 1001，每次最多 10 轮。它是上轮 BRC 根—残差语义的有限域 C++ 移植；本轮没有变动项目中的既有算术实现。

### 2. 共享锚点

令 `K=floor_sqrt(min(input))`，对 `K>0` 预测

\[
\widehat{k}=K+\left\lfloor\frac{x-K^2}{2K}\right\rfloor.
\]

逐项检查

\[
\widehat{k}^2\le x<(\widehat{k}+1)^2.
\]

证书成立才采用预测根；否则调用完整整数根。候选平方使用 64-bit 中间值，例如输入 `[1,1000000]` 会产生远大于 32-bit 平方安全范围的候选根。`K=0` 走完整根路径，避免零除。

对输入族

\[
x=(K+j)^2+e,\quad0\le j<B,\quad0\le e<D,
\]

若

\[
(B-1)^2+D-1<2K,
\]

则 `j=floor((x-K*K)/(2*K))`，预测全部成功。本实验近平方族的 `K=900, B=20, D=8` 满足 `368<1800`。锚点由输入自行确定；生成器的参数不传给排序器。

自适应版先检查整个样本是否位于同一平方盆地，成立时直接复用 `K`。否则前 16 次实际预测中至少 12 次成功才继续预测，未达阈值则余下输入直接开根。16/12 在首轮计时前固定。通过试探后每项仍进行精确证书检查，后续可能发生更多回退。

### 3. 精确倒数取商与一遍分类

令 `d=2K>=2`、`M=floor(2^32/d)`。对 32-bit 非负 `t`：

\[
q_0=\left\lfloor\frac{tM}{2^{32}}\right\rfloor,
\qquad q=q_0+[t-q_0d\ge d].
\]

近似商只可能是真商或真商减一，因此一次修正得到精确商。乘法用 64-bit，初始化 `M` 的一次除法计入耗时。

得到所有状态后，记实际坐标跨度

\[
B=k_{max}-k_{min}+1,\qquad D=r_{max}-r_{min}+1.
\]

当 `B*D<=n` 时，使用网格键

\[
g=(k-k_{min})D+(r-r_{min})
\]

做一次稳定计数；这个编号保持 `(k,r)` 字典序，且计数表最多 `n` 个槽。其余情况继续用残差、根两遍分类。网格只用作计数下标，记录内部保留可逆的根—残差编码。

### 4. 总工作量

两遍分类的工作量为 `O(n+B+D)`，融合被选中时为 `O(n+BD)`，且 `BD<=n`。还需计入状态提取。

锚点路径设完整根回退次数为 `f`，总成本可写为

\[
T_{root}+O(n)+fT_{root}+T_{classification},
\]

其中单字整数算术按常数成本计。充分条件成立、`f=0`，并且分类表规模为 `O(n)` 时，总成本是 `O(T_root+n)`。对于当前近平方输入族，`B=20,D=8`，仅开根一次，分类阶段为线性。

这份实现把值域固定为百万以内，各次整数根的循环上界也固定。扩展到任意位长自然数需要重新计入根求值及多字算术成本。本轮所验证的是此有限域实现和上述结构条件；比较排序、基数排序和计数排序的实际基线均在本程序中。

### 输入与控制

1. **均匀随机**：在 `[0,1000000]` 独立均匀抽取。`n=100` 的第一个 bank 是前序研究的固定 100 数样本；其余按固定种子产生。
2. **近平方**：独立抽取标签 `label in [0,159]`，映射到 `(900+label/8)^2+label%8`，共 160 个可能值。
3. **匹配重复的散布数**：使用与近平方组逐位置完全相同的标签；映射到一个有序、互异、散布于百万范围的 160 数支持集。因此重复次数、相等关系和秩序模式都匹配。
4. **单平方盆地**：均匀取 `[810000,811800]`，所有根为 900，用于验证单盆地捷径，并与普通窄区间计数对照。
5. **逆序均匀样本**：将对应均匀组的同一多重集合降序排列，然后赋原始位置。

每种条件 8 个输入 bank。生成过程使用 `mt19937_64` 和明确的无偏拒绝采样；源代码保存种子、固定样本和生成规则，数据生成在计时区间外。

在 `n=100000`，近平方合并版只有 1 次完整根求值、1 次倒数初始化、平均 99369.125 次乘法取商，所有实际预测命中。匹配散布组平均需要 99370.125 次完整根求值，试探 16 次后关闭预测，耗时 3478.226 µs。这说明相同重复与秩结构下，该锚点捷径的可用性会显著改变成本。

这两个组的数值跨度也不同，故这一对照同时改变了区间跨度与平方残差结构。普通 `range_count` 在近平方十万数上的 241.046 µs，以及单盆地上的 203.407 µs，是解释这种结构收益的重要整数基线。

## 计时与验证方法

- CPU：AMD EPYC 9V74，x86-64；单个进程绑定逻辑 CPU 0。环境的可用 CPU 为 0–8。
- 编译器：GCC 13.3.0；所有计时算法同一个可执行文件，参数 `-O3 -march=native -std=c++20`。
- 输入是上述 8 字节记录。BRC、radix、区间计数及 `std::stable_sort` 保持重复值顺序；`std::sort` 单独验证升序、记录身份和多重集合完整性。
- 一次计时调用包含输入副本分配/复制、所有键与锚点计算、工作数组分配和清零、排序、数值重建、临时内存释放。每次调用自行生成全部状态。
- 8 个输入 bank 轮换，每轮约 20 ms；共 7 轮，算法执行顺序按固定种子打乱。计时器为 `std::chrono::steady_clock`。
- 这是稳态轮换输入测试。P10/P90 是 **7 个批次的每调用均值分位数**，不是单次调用延迟或置信区间。
- 诊断计数在独立调用中收集。计时代码实例不增加逐项诊断统计；自适应路由所需试探计数仍在计时内。
- 输出通过内存逃逸屏障和可观测的输出依赖校验和被消费；完整排序正确性验证在计时外执行。

优化构建和 AddressSanitizer/UndefinedBehaviorSanitizer 构建均通过：

- `[0,1000000]` 的 **1,000,001** 个值逐一检查根、残差及编码重建；根的对照采用顺序跨平方边界的独立整数 oracle。
- **6,007,006 次**倒数商检查：6 个代表分母遍历全输入域，以及所有 1000 个合法偶分母的边界检查，含 `UINT32_MAX`。该次数包含重复测试点。
- **5,599 组数组**，每组检查全部 8 算法的带统计和无统计两种路径。包含长度 0–6 的四符号穷举、空数组、重复值、平方边界、零锚点、大候选平方、随机样本和五组十万数。
- 基准运行另验证 **160 个输入 bank** 的全部算法输出。

沙箱中的 LeakSanitizer 无法读取进程任务目录，故使用 `ASAN_OPTIONS=detect_leaks=0`；地址越界与未定义行为检测正常执行。原始通过回执、编译参数及文件 SHA-256 见 [validation_and_environment.json](validation_and_environment.json)。

`divisions` 表示排序实现中记录的动态除数除法次数；合并版的预测次数另在 `reciprocal_quotients` 列。统一命中率为 `hits/(hits+misses)`。根/跨度/路由统计均为每条件 8 个 bank 的平均值。

## 编译与复现

```bash
g++ -O3 -march=native -std=c++20 -Wall -Wextra -Wpedantic brc_sort_bench.cpp -o brc_sort_bench
./brc_sort_bench --verify
taskset -c 0 ./brc_sort_bench --bench results_reproduced.csv 100000
```

未提供 `taskset` 或 CPU 0 不在允许集合时，用可用的 CPU 编号，或直接运行可执行文件。计时会随硬件与负载变化。`--bench` 的最大规模参数可改为 `1000000`；本报告的已执行矩阵到 `100000`。

可选地址与未定义行为检测：

```bash
g++ -O1 -g -std=c++20 -fsanitize=address,undefined -fno-omit-frame-pointer brc_sort_bench.cpp -o brc_sort_bench_sanitize
ASAN_OPTIONS=detect_leaks=0 ./brc_sort_bench_sanitize --verify
```

排序入口包括 `brc<0>`、`brc<1>`、`brc<2>`、`brc<3>`。传入 `std::vector<Record>&` 和空统计指针，例如 `brc<3>(a,nullptr)`；输入应满足声明的值域，`id` 作为随记录移动的载荷保留。
