## 3. 组织成什么：证据、判断、联系和工作上下文

### 3.1 原始证据与成果视图

一个逻辑成果视图包含以下信息。它们是适配和查询输出的设计，不是要求每位研究者手填的新表单：

- `claim_id`：稳定语义标识，保留原条目 ID 的命名空间；来源修订与逻辑身份分开。
- `source_refs`：仓库、固定提交、路径、现有 blob 身份及可定位部分。
- `object_and_domain`：对象、类型与参数域。
- `observations` / `operations`：需要保留的观察与允许的后续操作。
- `assumptions` / `quantifiers`：承重前提和量词。
- `precision_error_cost`：分辨率、误差模型、资源/成本含义。
- `statement` / `limits`：准确命题和来源明确的边界。
- `evidence_status`：作者证明、有限计算、独立核对、正式接纳等各自真实状态。
- `tool_refs` / `proof_refs`：可复用实现、证明和证书。

字段从已有记录映射，缺失时明确未知。未填齐字段的研究仍可保存；查询时指出影响适用判断的缺口。程序验证字段和版本，数学语义由真实论证与必要审查决定。

### 3.2 跨线关系

关系记录保存 `from`、`to`、`relation_kind`、`mapping`、`matched_conditions`、`open_conditions`、`evidence_refs`、`status` 和依赖版本。

已有 `CONSUMES` 和 `REUSE_IDENTIFIED` 保持原含义。新增的候选类比、反例相关和条件冲突可以先作为实验关系类型，不自动修改主干图的规范。

一条关系应说明：哪边的什么结果可在另一边的哪一步使用；对象怎样对应；哪些条件已核；还有什么需要证明。候选类比不参与自动数学蕴涵闭包。`A` 与 `B` 相似且 `B` 与 `C` 相似，不生成 `A` 定理可用于 `C` 的结论。

原文、解释、候选关系和正式科学状态分别保存。自然语言摘要不得把有限实验改成一般证明，或把未审分支改成已接纳主干。

### 3.3 共同结构视图

多条路线出现相近结构时，可以从上述关系生成一个共同结构条目，说明它们共同试图解决什么问题、对象如何对应、共享哪些条件以及哪里仍不同。例如“保留指定观察和后续操作的状态压缩”可以是一个待检验的抽象入口；这句话本身不证明任何具体路线等价。

共同结构条目引用各条路线的精确成果，不合并原始作者和科学状态。必要的语义判断放在 `overlays/`；列表和可视化从它与关系记录生成。已有抽象无法容纳的新路线继续保留自己的表示。这样能按共同问题组织跨线材料，减少逐条配对和重复背景，又避免另造一套必须人工填满的全库分类表。

### 3.4 主模型的工作上下文

常驻内容由当前模式所需的基础、问题、已核前提及未解决位置组成；完整证明与历史材料按需展开。一个恢复记录应足以知道当前问题和证据位置，不必复制全部历史。

查询返回适用候选及理由，而不只返回相似度：共同对象是什么、关键差异是什么、哪里需要展开。返回数量与展开深度由具体任务和实际资源约束决定，不能把本试验配置写成所有研究的统一阅读配额。

## 4. 最小接口与增量维护

下面是逻辑接口，不是已部署 MCP 名称：

| 接口 | 输入 | 输出 |
|---|---|---|
| `search_results` | 当前问题、已知对象/条件、来源快照、允许视图 | 成果 ID、命中依据、来源、需要核对的条件 |
| `get_result` | 成果 ID、要求的版本/范围 | 完整命题、假设、状态、证明/工具链接 |
| `related_results` | 已选成果、关系类型、当前问题 | 已确认复用与候选关系分别呈现，包含待核条件 |
| `read_evidence` | 精确来源引用与范围 | 原始证据；尽量复用现有 GitHub 或 scientific-read 接口 |
| `refresh_changed_sources` | 新旧来源前沿及实际变更集合 | 受影响摘录、索引、关系和待复核项；不改变数学接纳状态 |

查询结果标明所用来源快照与索引覆盖状态。索引尚未吸收的新成果，可沿精确原文路径读取，不能把未检索到解释为不存在。

建议的数据流：成果先按现行路径保存；后续按 Git 变更提取候选条目；复用已有语义字段；只重检受影响关系；更新派生索引；研究时按需读取。文件未变则复用已有核验。来源内容改变使相应解释进入待复核，不把这种状态写成数学结论被推翻。

连接工作从有意义的新材料展开到相关候选，避免每次做全部成果两两比较。候选生成、语义核对和索引维护的成本计入试验。记录失败的匹配，保留直接来源检索作为可用路径。

中控台不可用时，CLI 对同一来源快照仍应能够查询和回源。查询、索引更新和语义补充不应被绑定到正式 CLAIM/Result 接纳过程。

## 5. 模式比较：拆开表示、导航与学习

不同模式使用同一批允许来源、相同主模型版本及相同科学输入。受控比较先固定成果内容和证据，再替换导航机制；整系统比较再计入提炼、放置、关联、维护与训练成本。

| 模式 | 定义 | 回答的问题 |
|---|---|---|
| M0 当前入口 | 当前合规基础、现有 toolbox 与精确来源读取 | 当前系统的真实基线 |
| M1 有界长上下文 | 事先声明、与答案无关选择的允许材料直接进入上下文 | 直接读取在该资料规模和预算下的质量/成本 |
| M2 平面成果卡 | 同一成果视图，按关键词/符号/明确字段查找 | 仅改变粒度和可寻址性有多少价值 |
| M3 向量或混合检索 | 同一视图，向量召回及声明的词法结合 | 不同术语表达下的召回是否改善 |
| M4 有类型的关系导航 | 同一视图，利用明确条件与来源的关系 | 跨线、多步依赖能否正确发现和使用 |
| M5 Nollm 原生 | 同一内容由宿主形成/放置，模型观察 Surface 后选择原生入口 | 几何共同现场和原生展开能否改善关联与维护 |
| M6 训练辅助模型 | 在固定检索材料上加入前提选择/重排/条件识别助手 | 学习稳定使用习惯能否产生额外收益 |

M3 中向量单独与混合可分别作为消融；M5 中调用外部词法路由救援属于单列 hybrid 结果；M6 至少与相同检索器的未训练版本比较。不要直接将未训练大模型与后训练小模型的总答案分数解释为“记忆方式优劣”。

另设 `M2_FREE_A_VIEW` 阶段投影变体，与 M0 在 FREE A 中比较：构建与查询都只使用相同允许基础和问题触发的必要精确定义、条件及工具材料，不利用额外成果集布局或排序。这样可以测量导航是否降低自由研究的查找负担，而不会因使用了词法后端就被排除。其他后端若将来用于该轨道，也需要声明自己的合规语料视图；全成果模式的成绩不能代替这种比较。

有界长上下文超出模型实际窗口时，记录该规模不可运行或按预先声明的选取规则形成子问题；不得事后把正确证据挑出来伪装成全量上下文基线。可以设置只用于诊断的 oracle 条件，但应独立标记、不参与主排名。

### 5.1 分开测试的四个因素

1. 表示：原文段落、现有成果卡、补充结构化视图。
2. 导航：词法、向量、关系、原生几何、直接长上下文。
3. 模型：主推理模型固定；辅助模型训练与否单独变化。
4. 使用过程：固定可比任务下的一次读取和自主多轮查询分别报告。

所有相同版本的来源、模型输出、提炼/放置决定、工具结果与运行设置在对应试验范围内保留。基础源、可见视图、任务曝光不同的结果不能混为同一对照。

共同输入不仅使用一个相同的快照名称，还要核对实际允许来源清单与版本、曝光条件及所比较因素之外的辅助模型配置。检索机制试验固定助手；训练助手试验则明确把助手训练作为改变的因素。

关系图若额外拥有已经归纳好的跨线事实，就同时改变了信息内容和导航。纯导航比较应冻结同一语义事实集合：平面和向量模式也能读取等价关系文本，图模式使用显式邻接。新增关系整理本身的价值可以另做对照，完整系统比较则计入建图和核对成本。同理，原文 M0 与整理后卡片 M2 的直接比较不是纯导航消融。

## 6. 研究模式与测试资料的隔离

### TASK / 知情综合探索

允许在实际范围内读取成果和候选联系。测试应包含不同术语下的可复用结果、条件近似但不能套用的结果、新进入资料库的结果、过期版本和缺证据任务。

### FREE A

沿 [现行问题先行精确查询规则](https://github.com/awdawmip/enterprise-math/blob/51a81b442e95717ec941e9acd2382c37d2c07cdb/docs/FOUNDATION_STARTUP_READING.en.md)：继承规定基础；自主形成相关问题后，冻结前也可读取所需精确定义、条件和工具；完整目录比较与去重在 Phase B。

FREE A 的返回、标题、关联预览、错误输出和缓存均使用相应视图。训练过目标成果集的小模型/adapter不作为“未接触该成果集”的选题助手；这里的额外暴露集合不包含现行明确要求继承的基础。已有成果暴露按真实状态保留，换工具或换角色不抹去暴露。

自由探索评测使用独立新会话及相同允许基础。问题形成后冻结候选，再由另一评价过程检查新颖性、结构差异、可研究性与重复。评价不是要求一个固定目标答案；应允许与原路线不同的有效问题。后台可以维护成果之间的联系，但 FREE A 选题者在相应阶段只能接收允许的视图；候选冻结后再接入成果比较与复用匹配。

### 开放开发集与真正 withheld 评测

公开合成样例只测试协议和机械行为。真实题目、参考条件、后续答案、调参记录以及题目依赖族分组在评价侧隔离；求解器只能读取允许的冻结资料。

同一 owner 的另一个会话并不自动构成权限隔离。真实验证需限制求解器的挂载、凭据、工具范围和网络入口，或在可审计的受控运行器中提供冻结来源。仅把答案放进不同目录、另一个分支或私库而仍让求解器持有访问权限，不足以构成盲测。

历史回放如果答案已公开在后续 Git 历史，也必须限制求解器到允许快照；无法做到时标为开放诊断，不报告为严格盲测。已经用于调布局、选关键词或训练的数据留在开发集。

## 7. 验收分层

### A. 机械与来源验收

这一层验证软件行为，不评价数学创造性：

- 同一来源视图经 CLI 与服务入口返回同一命题、条件和来源身份。
- 原文更新、改名、撤回或审核状态变化后，依赖记录准确进入更新/复核路径；未受影响记录不全库重算。
- 删掉可重建缓存后恢复相同逻辑资料；已接受语义放置和绑定从持久状态恢复。
- 不把作者证明、有限计算、独立审核和正式接纳合并成一个“有效”字段。
- 允许视图在索引、召回和返回阶段保持一致；FREE A 的合法精确查询可用。
- 未知来源、缺失证据、资源耗尽与没有匹配分别返回真实状态。
- 中控台断开时本地核心查询可运行。
- 原文修改不会静默覆盖语义补充；失败或未知写入使用既有对账方式。

对于固定验收样例，来源错绑、答案泄漏、状态擅自升级与跨快照混用应逐项修复后再通过该项。有限样例通过不证明永远零错误。

### B. 知识查找与正确使用验收

衡量必要证据是否找到、是否读到、是否正确使用。承重假设遗漏和错误迁移单列，不能被平均答案分抵销。参考依据可以是多个有效前提集合，而非只承认一条原证明路线。

比较采用同题配对和研究族分层，报告差值及不确定性。效果试验在观察答案之前冻结主要指标、统计方法和判断条件；未设非劣界时，不从“差异不显著”推出等效。

### C. 跨线复用验收

有效输出须给出实际可用的上游材料、对象对应与条件核对，并帮助完成一个真实步骤或准确指出桥接缺口。仅有“相关”标签、漂亮图形或更多候选，不计为有效复用。

记录：已确认可用、需要补条件、因具体原因不适用、来源不足。候选关系只能凭后续证据改变状态。开放问题上的未解决状态继续保留。

### D. 自由探索验收

比较问题的结构差异、重复率、可研究性、对现有热点的集中和来源暴露。文本距离不是创造性；评价允许多种研究目标。条件合规与选题质量分别记录，避免把更强的成果提示误当作盲探索能力提高。

主动复用旧结论推进新步骤、独立复现和无价值的重复推导分别标注。多条路线因数学证据汇合到同一结构可以是重要成果，不能仅因题目更集中而扣分。记录相对于允许知识的独立形成与相对于全库的实际新颖性，由冻结后的评价过程分别判断。

### E. 成本、维护与采用决策

成本包括提炼、布局、关系核对、向量/训练构建、查询、所有模型输入输出、工具展开、更新、缓存和失败重试。分别报告冷启动、暖启动以及追加新成果/修改旧成果后的恢复成本。

按任务类别比较质量—成本前沿。一个模式可以只适合跨线综合；无需在精确符号定位、所有规模和所有研究模式上同时胜出。采用条件是它在实际用途上提供可验证的净收益，并保持必要正确性；没有预先承诺固定节省比例。

将总成本写成 `C_total(Q,U)=C_build+C_train+Σ C_query+Σ C_update`。若两种模式维护条件相同，可依据实际测量计算摊销查询量；维护频率不同时保留 U，不用单一 break-even 数字隐藏更新成本。

## 8. Nollm 需要额外核验的具体点

1. 将 Surface 观察、选择和 recall 绑定到同一场状态。现有 CLI 重放选择历史，recall 另收坐标；真实维护过程中需要检测观察后的场变化。
2. 复用已有导航状态序列化、返回父层和请求更粗 Surface 接口，避免重写导航器。
3. 原生入口由模型观察场后选择。词法 key/path/prose 路由和外部图选入口单列 hybrid。
4. 分别记录内容物理可达、进入返回列表、实际进入模型上下文、最终正确使用。beam/top-k 截断可能导致可达内容未返回。
5. 同层邻接、上下 Coverage 和有限 Bridge 的作用分别消融；已知两步 Coverage 旧试验不能代表所有核组合。
6. 形成和布局只看训练/构建资料，不能看 withheld 问题答案。可使用训练期问题优化布局，但要保留未见研究族测试。
7. 数学条件解释留在 EM 语义记录中；Nollm Core 保持语义盲。几何得分不是数学真实性或语义相关概率。

既有试验数值及其原范围见 [CURRENT_EVIDENCE.md](CURRENT_EVIDENCE.md)。

## 9. 可直接开工的工作包

这些是可独立验证的工程目标，不规定研究者的思考步骤。

| 工作包 | 最小交付 | 验收证据 |
|---|---|---|
| 条目查询 | 适配已有分卷卡、精确 get、来源展开 | 正确返回条目而非整卷；条件/状态完整；本地真实查询 |
| 版本和更新 | 差量扫描、依赖复核、覆盖状态、缓存恢复 | 来源变化与缓存删除的回归记录 |
| 条件化联系 | 候选映射、适用差异、已有关系兼容 | 新任务中可核对的有效复用或准确不适用说明 |
| 模式比较 | 共同运行记录、隔离数据、冷/热/更新测量 | 独立任务的逐项结果及成本，不混报机制 |
| Nollm 适配 | 版本绑定的观场/选择/召回链、原生与hybrid分列 | 对应失败场景修复及未见任务对照 |
| 辅助训练 | 从真实选择/套用错误形成数据，固定检索器对照 | 时间和依赖族隔离下的增量收益；训练/维护成本 |
| 接入采用 | 通过实际用途验证的模式接入现有工具入口 | 有适用范围、可恢复配置、继续可用的直接读取路径 |

下一执行者可以先从已有条目级查询开始。Nollm 和训练辅助模型的完成不是这一能力交付的前置条件；也不要求先把全库连接整理成完美图谱。

## 10. 本包怎样使用

- `evaluation/evaluation_plan.json`：机器可读的试验模式、隔离条件、指标与采用原则。
- `evaluation/validate_evaluation.py`：检查运行记录中声明的合同与过程一致性；不执行模型、检索引擎或权限隔离。
- `evaluation/test_validation.py`：合成开发场景的检查器回归。
- `CURRENT_EVIDENCE.md`：已有公开实验与本轮实际检查范围。
- `VALIDATION_RESULT.json`：本轮实际运行的命令、输出和明确范围。

按照 evaluation 目录说明执行检查。真实运行完成后，应单独保存 source/model/adapter 版本、曝光视图、工具过程、成本和评价结果；未运行模式保留 `NOT_RUN`。

## 11. 方法参考及范围

- [LeanDojo / ReProver](https://arxiv.org/abs/2306.15626)：前提选择和未见前提划分的参考；不要求本项目先全部形式化。
- [HippoRAG 2](https://proceedings.mlr.press/v267/gutierrez25a.html)：关联记忆与基础事实检索要分别测试的参考；其问答成绩不代表本项目数学迁移能力。
- [LongMemEval](https://arxiv.org/abs/2410.10813)：信息提取、跨会话、时间、知识更新和拒绝无依据作答的分维度评价参考；会话基准不替代数学任务。
- [Nollm 项目缩影设计](https://github.com/awdawmip/Nollm/blob/cf10ab849c2b32132de01328061d172377729161/lab/nollm-lab/repository_memory/PROJECT_MINIATURE_DESIGN.md)：原生组织、已有缺口和历史对照来源。

本提案不主张这些方法具有新的学术优先权，也不把资料索引或机械测试晋升为数学结果。
