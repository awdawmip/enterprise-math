## 1. 目标和当前定位

此前把 Nollm 放入“可替换记忆后端”比较，是 Enterprise Math 的外部集成假设，不能据此定义 Nollm 内部架构。该假设在理解恢复后继续评估。既有成果级查询等独立工作可照常推进。

## 2. 怎样避免自举循环

使用比待理解系统简单的外部证据底座：普通文件、Git 固定版本、全文检索、标题与显式引用。这个底座先保证资料可找到、解释可回源，不要求先会正确解释整个 Nollm。

初始资料清点可以记录路径、版本、标题、文档声明的状态、显式继承/替代关系和未读范围。概念分类保持暂定；未分类材料仍可查找。现有模块名、当前实现中的概念和某个检索器的相关性排序，不独占收集范围。原设计中被实施遗漏的能力，仍有机会从设计文档和变更理由被发现。

理解以候选解释的形式形成。资料不足时可并列保留竞争解释，并说明什么证据能区分它们。每轮校准可以修改解释、补充来源或重新划分概念，而不是只扩充一份越来越长的摘要。

这套研究用导航不接入 Nollm 产品的原生关系发现路径。以后让 Nollm 参与理解任务时，保留这份独立参照，比较是否丢失概念、关系或证据。自举依赖的初始依据仍是可核查的项目来源与实际观察，不宣称实现了无外部依据的自我证明。

## 4. 收集产物怎样组织

优先复用既有缩影报告、架构书中的“继续有效／替换／吸收”说明，以及已带 Git blob 的工程判断。可在现有材料上形成以下视图，无须再建立一套百科或新的数据库。

### 设计依据与选择理由

记录关键目标、概念、机制和明确修订，并保留它们解决的问题、取舍、被放弃的替代方案及来源。原始指令、规范性陈述、阶段政策、目标设计、实验观察分别标注。来源没有提供理由时，推测应明示为解释假设。

### 实际实现与测量

记录当前代码路径、输入输出、状态变化、测试观察和能力缺口。代码说明“实际怎样做”，原测试说明“检验了哪些性质”。测试与被测实现共享同一计算时，不能据此增加独立数学证据。

### 设计—实施对照

把不同证据连接成具体事项：符合；有明确依据的调整；可能偏离；尚未实现；来源不足。每项保留决定该分类的依据。实现与文档不一致时，不默认修改文档以迁就实现，也不默认恢复旧版设计。

收集者、解释者与挑战者可以由不同工作上下文承担，但不规定固定数量。最有用的独立性来自不同证据路径：意图侧不以代码摘要作为唯一基准，实施侧不因某份设计提到能力就假定已存在，挑战侧可读原文并寻找能区分解释的案例。多个模型赞成同一摘要不能替代原始证据。

## 5. 怎样精炼而不丢掉设计含义

对影响变更的关键判断，短条目应能回答：

- 这个概念或机制要解决什么问题？
- 当前有根据的解释是什么，适用范围是什么？
- 哪些原文支持它，哪些部分是推断？
- 哪个看起来相似的替代解释会改变设计？
- 它在实现中对应哪里，哪些部分尚未知？

完整原文继续保留。短条目主要帮助决定接下来需要展开什么；引用只说明可追溯，不保证解释正确。相同字节的原文也可能被一直误读，因此“source blob 未变”不能替代概念校准。

从原文直接生成或修订理解，保留来源与变化理由。避免让后续摘要仅依赖上一代摘要，形成无法回到原意的压缩链。需要更换组织方法时可重建派生视图，已核语义判断及其出处仍保留。

### 本轮已发现的校准样例

缩影报告中“模型与几何各自承担明确职责”一节使用“LLM 判断一条内容是否值得记忆”。现行内容中立决定明确区分内容资格与新命题／复用／修订／零变化。

因此该摘要需要消歧：LLM 判断当前语义变化和如何形成、复用或放置；不能把主观重要性变成 canonical memory 的资格过滤。

这是已核文本之间的解释风险。尚未据此证明当前实现存在内容过滤。对短期内容或工具来源内容的假设案例，应同时辨别：有资格进入流程、当前没有新命题，以及技术上需要续接，是不同判断。

## 6. 用理解挑战检验迁移能力

验收关注解释和预测新情况，而不只看术语复述。以下是公开开发样例；公开后不得作为新的未见题性能证据。

| 挑战 | 需要辨认的区别 | 依据入口 |
|---|---|---|
| 把一条事实的多覆盖改成唯一父节点 | 真实旋转尺度覆盖与树状归属的差异；原始证据与几何关系的区别 | 第一性原理、缩影报告的共同现场与 Coverage 说明 |
| 提高 Aggregation Order 时自动创建一条高层摘要 | 观察尺度、物理存储层、语义粒度是不同变量 | 当前 README 的 Project understanding 与缩影报告“三种不同的层次” |
| 所有语句只写在第 0 层，就断言没有使用跨层几何 | 实际存储位置与经过空物理格的传播能力分开 | 缩影报告“空层也能承担真实传播”及其源证据 |
| 先按对象检索命中后再交坐标，声称是原生发现 | 辅助基线、对象精确回源与原生关系发现的区别 | 第一性原理 §2.3、§3；实验入口代码 |
| 删除一个被称为 cache 的表后无法找到正确入口 | 名称与实际正确性依赖分开 | 第一性原理 §3.1 |
| 生产核遗漏极小面积边，就要求恢复逐次高精度 polygon | 独立 Oracle 真值与生产有界近似合同分开 | 第一性原理 §9、§10 |
| 一个刺激既包含问题又更正旧事实 | 共享 Encounter 的导航与最终读／复用／修订等效果分开 | V3.12 §0–2 |
| 因某段内容短期、普通或来自工具而永久跳过 | 内容资格、当前变化量与技术续接分开 | 内容中立决定 §1、§2、§3、§7 |
| 两份文档对检索和几何的分工相反 | 原文状态、继承/替代关系及当前活动入口；允许来源链不完整 | 早期 V4、第一性原理、ACTIVE_PROJECT |

表中的缩影报告是查源入口和出题线索，不独自担任其自身理解测验的答案依据。规范题展开到活动设计原文，行为题展开到原始实现或运行证据，数学性质沿独立 Oracle；例如“第 0 层写入仍可跨层传播”应追到报告引用的原生机制与原始实验，而非再次引用同一句摘要。暂缺原始判别依据的题标为待校准，不计入理解正确率。

真正评价迁移能力时，选择未参与写稿、布局和调参的新案例，包含合法变动与看似合理的错误变动。执行者可以查允许的原始依据；评价答案或事后实现结果不提前交给它。若原始材料不足，能指出具体缺口优于编造一套闭合解释；一概拒答也不能被当作理解充分。

对于有运行后果的预测，事前保存所预测的行为和依据，再与可重现的实现观察比较。当前解释预测失败时，定位是解释错误、实现偏离、资料不全还是原测试能力不足。

几何数学的实际复算仍沿项目现行 Oracle 和误差合同。本理解任务不以文本检查替代那些校准。

## 7. 怎样比较理解材料和记忆机制

可以沿用前一份比较框架，但先回答更基础的问题：这份理解材料是否保留了关键区别。

| 对照条件 | 主要观察 |
|---|---|
| 原始文件与普通精确检索 | 不依赖候选摘要时，正确理解所需的实际阅读和时间 |
| 现有缩影报告与相同原始来源 | 当前整理帮助了什么，误导或遗漏了什么 |
| 有证据、理由、竞争解释的修订理解材料与相同来源 | 内容精炼本身对判断和变更预测的增量 |
| 相同修订材料经 Nollm 原生组织和导航 | 固定语义内容后，记忆机制是否帮助找到和组合材料 |

前三类主要比较资料表示及整理效果，最后一类再隔离导航贡献。保持主模型、问题、允许来源及真实曝光范围可比；计算理解材料形成、放置、读取、回源、修改和维护的成本。

主要观察正确的架构判断、关键区别丢失、无依据的权威升级、未见变更的影响预测、精确回源以及具体未知的识别。实际人工纠错次数和总上下文成本也有意义。原文覆盖率、摘要压缩率、图节点数和模型投票只能作辅助观察。

不同读者应从不同资料入口检验关键分歧，避免所有人先接受同一摘要。若评价称为未见或盲测，资料权限与先前暴露应按真实情况建立；同一 owner 的新会话并不自动构成隔离。

## 8. 什么叫对下一项变动已经理解充分

充分程度相对于拟变动的范围判断。执行者应能解释相关目标、关键概念、层间职责、设计取舍、来源和重要失败方式；能识别改变目标的替代方案；能给出有依据的影响预测，并说明仍缺什么。

不能用一份流畅总结、若干通过的合同测试，或“所有文件已读”作为单独结论。也不要求先完全理解项目所有历史，才允许继续收集资料或进行不触及未决设计的工作。

对仍有竞争解释的关键点，先寻找能区分它们的源证据或可逆试验。现有依据足够时由执行者解决；只有确实需要选择新目标、且资料无法决定的取舍，才带着具体选项交给项目所有者决定。

下一轮适合围绕一个有代表性的完整场相遇形成可核查解释：从刺激和原文保存，到语义形成、Surface、单物理入口、局部事实或空位、效果和证据回源。执行者可据资料选择切口和扩展范围，目的在于验证跨层理解能否支撑真实变更判断，而非只整理名词。
