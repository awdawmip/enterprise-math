## Frontier consumed

R11 established that exact metadata-only support certification is unsound on the pinned raw-array host unless every relevant write is mediated. R12 then proved that, **under an explicitly complete mediation boundary**, an exact outside-support nonzero counter `q` permits support re-entry after every escaped coefficient is exactly cleared.

R13 addresses the next missing condition: `q == 0` certifies current support, but it does **not** by itself certify that sparse-derived caches are synchronized with the current state after a dense interval.

## New theorem: support re-entry is not cache re-entry

Let `x` denote every authoritative input on which the sparse evaluator's derived state depends (at minimum the relevant state and, when applicable, Source). Let `C` be the carrier, and let `q(x)` be an exact mediated outside-carrier nonzero count as in R12.

Suppose a sparse implementation has a derived cache `K(x)` (for example a support map, restricted index table, precomputed coefficient view, or any value reused across route boundaries). Then

`q(x) = 0`

is necessary for carrier support eligibility, but is not sufficient for safe reuse of a previously built `K`.

A counterexample is immediate. Start with `x` carrier-supported and cache `K(x0)`. Enter dense mode by creating one outside-carrier coefficient; mutate an inside-carrier coefficient; then clear the outside coefficient exactly. The outside counter returns to zero, yet the old cache still equals `K(x0)` while the authoritative state is `x1 != x0`. A support-only router can therefore falsely re-enter sparse mode with stale derived state.

## Sufficient exact re-entry contract

A versioned contract is sufficient if all of the following hold:

1. **Complete mediation** — every semantic mutation of every input relevant to the sparse cache passes through the trusted boundary. Raw aliases or foreign in-place writes are forbidden or revoke the certificate.
2. **Exact support counters** — outside-carrier counts for independently mutable inputs are maintained by exact old/new deltas, with strict `!= 0` semantics.
3. **Semantic epoch** — a monotone epoch increments on every relevant semantic mutation.
4. **Cache invalidation/update** — a relevant mutation either updates the cache exactly and advances its stamp, or marks it invalid.
5. **Exact rebuild stamp** — a full rebuild computes the sparse-derived cache from the current authoritative inputs and stamps it with the current epoch.
6. **Atomic check/use boundary** — sparse execution begins only when all exact outside counters are zero, the cache is valid, and `cache_epoch == current_epoch`, with no mutation between this check and the use; equivalently, the epoch is rechecked immediately before use under a synchronization rule that forbids an intervening mutation.

Under these conditions, induction on mediated writes preserves the outside-support counters, while the epoch/stamp invariant prevents a stale cache from being accepted. At a route boundary, rebuilding at the current epoch establishes both carrier support and cache consistency. Thus sparse re-entry is exact.

This contract can be optimized: an implementation may incrementally update a cache rather than rebuilding it, provided the update is exact for the mutation and advances the cache stamp to the same epoch. The theorem is about the invariant, not about requiring a particular rebuild algorithm.

## Necessity boundaries

Three independent failure modes were retained deliberately:

- **Support-only stale-cache failure:** `outside: 0 -> nonzero -> 0` can restore `q=0` while an inside-carrier mutation makes the pre-dense cache stale.
- **Raw-alias failure:** an unmediated outside write leaves both `q` and the epoch unchanged, reproducing R11/R12's hard mediation boundary and enabling false sparse acceptance.
- **Check/use race:** even fully mediated writes are unsafe if a route decision is cached and a mutation can occur after the check but before sparse use without an atomic boundary or epoch recheck.

Therefore the R12 counter is an exact **support certificate**, not by itself a complete **execution-state certificate**.

## Consequence for the pinned host

R13 does not make the mediated R11/R12 variants valid on the unmodified pinned spectralDNS host. R11 already found no established complete write barrier there. R13 adds another host-side obligation: every sparse-derived cache that can survive across a dense interval must either be invalidated/rebuilt or be exact-versioned against all relevant mutations before sparse re-entry.

Accordingly, the original-host R8 exact-scan baseline remains the conservative route until a native mediated variant proves both write completeness **and** cache-epoch completeness.
