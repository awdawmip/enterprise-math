## New theorem: exact outside-nonzero counter

For a fixed carrier `C`, define

`q(x) = #{ i notin C : x_i != 0 }`.

Initialize `q` by an exact scan. For every mediated write `x_i: old -> new`, update

`q <- q + 1[new != 0] - 1[old != 0]`

when `i notin C`, and leave `q` unchanged for `i in C`.

By induction over the write sequence, `q` remains exactly equal to the number of nonzero coefficients outside `C`. Therefore

`q == 0  <=>  support(x) subset C`.

For independently mutable state `u` and Source `F`, the exact support-routing predicate is therefore

`q(u) == 0 and q(F) == 0`.

This improves on R11's permanent escape latch in one precise respect: if every escaped outside-carrier coefficient is later set **exactly** back to zero through the trusted barrier, the counter returns to zero and support-based sparse eligibility may be restored at the next canonical synchronization boundary. Re-entry is not authorized if stale derived state/cache from an earlier dense interval can be reused; such state must be invalidated or recomputed.

## Why a dirty bit/generation is not enough

A generation number or “was dirty” flag records that a write happened, not the current cardinality of outside support. The sequence `0 -> nonzero -> 0` and the sequence `0 -> nonzero` can both be “dirty” while only the first is sparse-eligible again. Exact re-entry therefore needs either recertification or enough mediated old/new information to maintain current support state.

## Local guard-cost witness

A warm Numba microbenchmark used a task-like flat complex array with `405,504` coefficients and a carrier of `384`. Each batch sets and then clears `W/2` outside coordinates so the route decision occurs at a sparse-eligible boundary.

The counter path includes the writes, exact counter maintenance, and O(1) eligibility. The comparison path performs identical plain writes followed by a full exact outside scan. Compilation is excluded.

In this local layout the observed crossover lies between 65,536 and 131,072 writes. This is a **guard microbenchmark only**, not a spectralDNS trajectory speedup.
