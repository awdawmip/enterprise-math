## New exact finite result

Consider a declared trajectory horizon with `N` nonlinear calls. Suppose a conservative implementation is allowed to enter a **one-way permanent-dense latch** at an exact synchronization boundary. Let:

- `L` be the number of calls that pay the route-support guard before the latch (`0 <= L <= N`);
- `m` be the number of those calls that actually execute sparse arithmetic (`0 <= m <= L`);
- `D` be homogeneous dense-counterfactual cost per call;
- `S` be homogeneous sparse cost per sparse call;
- `G` be homogeneous route-support guard cost on guarded calls;
- `A` be the hybrid-only fixed setup delta.

Post-latch calls execute the unchanged dense reference route and therefore cancel against the dense counterfactual. The exact finite identity becomes

`DenseTotal - HybridTotal = m(D-S) - L G - A`.

Hence positive end-to-end gain is equivalent to

`m(D-S) > L G + A`.

For `m>0`, the average saving required from each actual sparse call is therefore

`D-S > (L G + A)/m`.

This makes the economic role of early densification explicit: **fallback/post-latch calls cannot finance routing overhead; only calls that actually execute sparse arithmetic can do so.** A permanent-dense latch can reduce future route-detection overhead, but it cannot create sparse savings.

### Route-opportunity cap / early kill certificate

The identity yields a useful bounded decision gate for a provisioned native run. If one has sound finite bounds

- actual sparse opportunities `m <= M`;
- each sparse-call saving `d_j-s_j <= U`;
- charged hybrid-exclusive overhead is at least `H_lower >= 0`;

then

`DenseTotal - HybridTotal <= M U - H_lower`.

Therefore

`M U <= H_lower`

is a sufficient **kill certificate**: positive end-to-end gain is impossible on that declared horizon, even before estimating a mean fallback probability. This is deterministic finite accounting, not an IID model or a Navier–Stokes theorem.

## R10 instantiation: why a conservative latch materially changes the guard burden

R10 has `N=20` nonlinear calls (five RK4 steps × four RHS evaluations). Exact retained support is full by the end of step 1 in all three surrogate trajectories. A conservative permanent-dense policy can therefore stop paying the **route-support** guard after the first completed step, so `L=4` instead of `L=20`. This does not require claiming that support can never shrink later: after the latch, dense is used unconditionally, so later support shrinkage only means a possible lost sparse opportunity, not a correctness failure.

For the observed sparse counts:

| seed | sparse calls `m` | always-guard required avg sparse saving | latch-after-step-1 required avg sparse saving | reduction in guard burden per sparse call |
|---:|---:|---:|---:|---:|
| 91001 | 2 | `10G + A/2` | `2G + A/2` | `8G` |
| 91003 | 2 | `10G + A/2` | `2G + A/2` | `8G` |
| 91007 | 1 | `20G + A` | `4G + A` | `16G` |

Thus the route-support guard is paid on 4 rather than 20 calls: an 80% reduction in guarded-call count for this conservative policy. With `A=0`, the guard component of the required per-sparse saving is reduced by a factor of five. This **does not** prove the hybrid beats dense, because the actual native `D-S`, `G`, setup cost, route counts, and saturation boundary remain unmeasured on the pinned host.

The latch removes only route-eligibility support checking. It does not remove verifier-owned physical diagnostics such as Source transversality/divergence, Hermitian symmetry, energy/work diagnostics, timestep refinement, or dense-reference numerical comparisons.
