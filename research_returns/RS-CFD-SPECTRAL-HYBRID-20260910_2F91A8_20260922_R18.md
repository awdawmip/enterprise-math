## New result: route counts do not identify weighted sparse work

Let a trajectory have `n` nonlinear calls, of which `k` are sparse-eligible. Let every paired dense-reference call cost `D_i > 0`. Suppose only that dense-call heterogeneity is bounded by

`rho = max_i D_i / min_i D_i >= 1`.

Then the weighted sparse share

`w_sparse = (sum_{i in E} D_i) / (sum_i D_i)`

obeys the sharp envelope

`k / (k + (n-k) rho) <= w_sparse <= k rho / (k rho + n-k)`.

The proof is extremal: the lower bound assigns the minimum allowed dense cost to all sparse-eligible calls and the maximum allowed cost to all fallback calls; the upper bound reverses those assignments. Both extrema are attainable, so the bounds are sharp under exactly this information model.

A key consequence is that **route count alone gives no nontrivial upper bound on `w_sparse` when `rho` is unbounded**. Even one sparse-eligible call can carry arbitrarily close to all dense nonlinear work if that call is arbitrarily more expensive than the others. Therefore route saturation counts are useful diagnostics, but they cannot by themselves certify a small total-speedup ceiling. The paired dense per-call measurements requested by R16 are mathematically necessary unless an independently justified finite heterogeneity bound is available.

This sharpens, rather than contradicts, R16: its general weighted formula remains valid; only the equal-call-cost numerical specialization is non-robust to cost heterogeneity.

## Quantitative implications for the frozen R10 routes

For the two `k=2, n=20` trajectories, if dense-call cost ratio is at most `rho=2`, then

`1/19 <= w_sparse <= 2/11`.

Using the same illustrative `alpha=0.7` as R16, the ideal full-trajectory ceiling therefore ranges from `190/183 ≈ 1.03825x` to `55/48 ≈ 1.14583x`, depending only on how dense cost is distributed across the route positions.

For the `k=1, n=20` trajectory at `rho=2`,

`1/39 <= w_sparse <= 2/21`,

and the corresponding ideal full-trajectory ceiling ranges from `390/383 ≈ 1.01828x` to `15/14 ≈ 1.07143x`.

The inverse calculation is more operational. To make an *ideal* `1.10x` full-trajectory speedup even possible at `alpha=0.7`, the `k=2` route needs dense-call heterogeneity of at least

`rho >= 90/67 ≈ 1.34328`,

whereas the `k=1` route needs

`rho >= 190/67 ≈ 2.83582`.

Thus the native A/B/C experiment should not treat the sparse-call fraction `k/n` as a proxy for weighted work. It should record paired dense-reference cost on each nonlinear call and compute the actual `w_sparse`; if those measurements are unavailable, it must at least report a defensible `rho` bound and propagate the interval above.
