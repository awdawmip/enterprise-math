## New exact result 1: support fullness is not a monotonic invariant

A permanent-dense latch is always correctness-safe if it routes all later calls through the unchanged dense evaluator. But a stronger interpretation — “once exact retained support is full, it can never become sparse again” — is false in the task's allowed fixed-RK4 viscosity/Source semantics.

Consider the finite retained Fourier set consisting only of the conjugate pair `+k,-k`, with `k=(1,0,0)`. Give both active velocity coefficients the transverse vector `U=(0,1,0)`. For every interaction of the two active wavevectors, the convective coefficient contains a factor `U·(+k)` or `U·(-k)`, hence the nonlinear term is exactly zero. The state and Source are divergence-free.

Choose the viscous rate `nu |k|^2 = 1`, one classical RK4 step of size `h=1`, and a constant Source coefficient `S=-(3/5)U`. Each active scalar transverse coefficient therefore obeys

`y' = -y - 3/5`, with `y(0)=1`.

For classical RK4 at `z=-1`, the homogeneous multiplier is

`R(-1) = 1-1+1/2-1/6+1/24 = 3/8`,

while the constant-forcing gain is

`Psi(-1) = 1-1/2+1/6-1/24 = 5/8`.

Thus the next coefficient is exactly

`y_1 = (3/8)*1 + (5/8)*(-3/5) = 0`.

Both retained coefficients vanish simultaneously. The retained support is full at the start of the step and empty at the end. This is an exact finite spectral counterexample, using rational arithmetic and fixed RK4, to any universal support-monotonicity rule.

Scope boundary: this counterexample does not assert that the pinned production trajectory, the Source=0 surrogate runs, or a particular native spectralDNS run will re-sparsify. It proves only that a full-support snapshot by itself is insufficient to certify that future sparse opportunities are zero.

## New exact result 2: future-only latch regret identity

At a candidate latch boundary, compare two policies over the remaining `K` calls:

- **dynamic**: continue paying the exact route guard `G_i` and use sparse cost `S_i` on the future sparse-eligible set `J`, dense cost `D_i` otherwise;
- **latch**: stop route-eligibility checking and use dense `D_i` unconditionally, with future switching overhead `L_switch`.

Then all future dense calls outside `J` cancel exactly and

`C_latch - C_dynamic = L_switch + sum_{j in J}(D_j-S_j) - sum_i G_i`.

This is a *future-only* decision identity. Setup already paid before the boundary is sunk and does not belong in the switch decision.

If one has separately certified finite bounds

- `|J| <= M` future sparse opportunities;
- `D_j-S_j <= U` for every such opportunity;
- `sum_i G_i >= H_guard` future guard cost;
- `L_switch <= L_upper`,

then

`C_latch - C_dynamic <= M U + L_upper - H_guard`.

Therefore

`M U + L_upper <= H_guard`

is a sufficient certificate that latching now is no more expensive than continuing the guard on the declared future horizon.

The key semantic restriction is new: **a current full-support observation cannot itself be used to set `M=0`.** Any nontrivial future-opportunity cap must come from a separate invariant, a valid host-specific certificate, or a predeclared empirical bound. Without that, the permanent-dense latch remains correctness-safe but its performance dominance is unproved.
