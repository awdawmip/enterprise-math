## New result 1: static support is not static coefficient content

The correct static contract is a declared Source **support envelope** `Ssrc`, not frozen Source values. If every stage satisfies `support(Source_stage) subseteq Ssrc`, then the existing closure may be seeded with

`support(U_hat(t0)) union Ssrc`.

Source amplitudes and phases may vary arbitrarily inside that envelope. This distinction matters for real forcing functions that are time-dependent but spectrally confined.

For exact-equivalence certification, support means exact zero/nonzero. A tolerance-based detector is an approximation parameter and cannot silently stand in for exact support. The reference implementation therefore separates `exact_support()` from explicit `approximate_support()` and marks the latter non-exact.

## New result 2: atomic dynamic fallback contract

For a general Source-compatible route, the Source support must be inspected before the current RK stage RHS is committed. Let `C` be the certified carrier and let

`escape = support(Source_stage) - C`.

If `escape` is empty, the certified sparse route may proceed. If `escape` is nonempty, the current sparse stage result is not committed: it is discarded/rejected, the exact same stage input is replayed through the unchanged dense RHS, escaped Source coefficients are preserved without projection or thresholding, Source is added exactly once, and dense mode becomes sticky for subsequent stages unless a separately validated reclosure/restart protocol exists.

This is deliberately stronger than waiting for the next nonlinear call. A Source escape can enter the RK stage state immediately; detection after commit is therefore too late.

## RK4 validation

A standalone finite-mode witness harness validates stage atomicity. The witness keeps the previously proved escape mechanism: once modes `p=(1,0,0)` and `q=(0,1,0)` coexist, the dense nonlinear path can emit `r=(1,1,0)`. In the stage-2 test, Source first injects `q` at `k2`. The guarded route is exactly

`SPARSE, DENSE, DENSE, DENSE`

and the complete guarded RK4 step equals the all-dense reference step. The current stage is therefore replayed before commit rather than allowing a sparse result to leak into the RK state.

Local dependency-light validation:

`6 passed in 0.05s`

Covered cases are zero Source, changing coefficients within declared support, static support escape, dynamic escape/preservation, RK4 stage-2 pre-commit fallback with all-dense equality, and arbitrarily small exact nonzero support.

## Integration consequence

The existing adapter controls only the nonlinear callback and does not receive Source. Therefore the general dynamic guard cannot be correctly completed solely inside its current `__call__(rhs, u_hat, work, Tp, VTp, K, u_dealias)` signature. The guard must be integrated at a layer that can see both the current stage Source and the pre-commit stage state, or the host wrapper must explicitly supply an equivalent Source inspector/handle.

This is a sharper integration boundary than the previous three-option repair sketch. It rules out a superficially convenient but incomplete patch that merely checks the sparse nonlinear input after Source has already changed RK state.
